통합 아이템 제작 가이드

무기·액티브 유물·패시브 유물·소모품은 모두 ARItemDefinition 데이터 에셋 하나로 정의합니다. 유형은 Item Type Tag로 지정하고, 실제 동작은 유형에 맞는 런타임 블루프린트가 담당합니다.

먼저 알아둘 구조

공통 데이터 에셋

ARItemDefinition은 표시 정보, ID, 기본 스탯, 스킬 설정, 런타임 클래스를 보관합니다. 같은 부모 클래스로 네 종류를 만듭니다.

런타임 객체

획득할 때 클래스가 인스턴스화됩니다. 무기·유물은 ARLoadoutItemInstance, 소모품은 ARConsumableInstance 자식 BP를 지정합니다. 플레이어 BP에 그래프가 복사되는 것은 아닙니다.

식별과 계열

(Item Type Tag, Item Id)가 고유 검색 키입니다. Additional Tags는 여러 아이템이 공유할 수 있는 문자열 계열명입니다.

새 아이템마다 Gameplay Tag를 등록할 필요가 없습니다. 네 개의 Item.Type.* 태그만 유형 선택에 사용합니다. 전투·입력·상태이상용 Gameplay Tag는 그대로 유지됩니다.

데이터 에셋 필드

카테고리를 누르면 에디터 Details의 항목별 역할을 볼 수 있습니다. 네 종류 모두 같은 항목이 보이지만, 일부는 특정 유형에서만 사용합니다.

Identity — 유형, 고유 ID, 계열 문자열
필드입력역할
Item Type Tag무기 Item.Type.Weapon, 액티브 Item.Type.ActiveRelic, 패시브 Item.Type.PassiveRelic, 소모품 Item.Type.Consumable 중 선택획득 시 어느 시스템·슬롯으로 갈지 결정합니다. 프로젝트에 이미 등록된 네 태그를 선택하세요.
Item Id제작자가 직접 적는 양의 정수. 0은 미지정이므로 사용할 수 없습니다.같은 유형 안에서 중복되면 안 됩니다. Find Item By Key(Type, Id)가 카탈로그에서 찾습니다. 중복 검색은 오류 로그 후 실패합니다.
Additional Tags여러 문자열. 예: Fire, Lake같은 계열의 아이템을 여럿 찾거나 보유 개수를 세는 데 씁니다. 중복 허용, 대소문자 무시, 앞뒤 공백 무시입니다. Gameplay Tag 등록은 필요 없습니다.

Asset Manager의 내부 로딩 ID는 ARItem:에셋파일명입니다. 게임 규칙상의 키 (유형, 숫자 ID)와 구별하세요.

Stats — 소지 중 자동 적용할 수정치

Default Stat Modifiers 배열의 각 항목은 획득 시 자동 적용되고 제거 시 자동 회수됩니다. 무기·유물에 사용하며 소모품은 현재 이 배열을 자동 적용하지 않습니다.

항목의미
Stat Type수정할 스탯 선택
OperationFlat 고정치, AdditivePercent 합연산 %, Multiplicative 독립 곱. IndependentDamageReduction은 전체·물리·화염·마법 피해 감소율에만 사용 가능
Value고정치 20은 +20, 합연산 20은 +20%, 곱연산 1.2는 ×1.2. IndependentDamageReduction의 50은 피해 50% 감소이며 0.5가 아닙니다.
Duration / Source기본 수정치의 지속시간은 등록 과정에서 무기한으로 처리되고, 출처는 해당 아이템 인스턴스로 귀속됩니다.

IndependentDamageReduction은 감소율끼리 더하지 않고 남는 피해를 곱합니다. 계산은 기본 남는 피해 비율 × ∏ Max(0, 1 - 각 Value/100)입니다. 예를 들어 이 효과 Value=50이 둘이면 0.5 × 0.5 = 0.25만 남아 최종 75% 감소입니다. 기본 피해 감소율이 20%이고 독립 감소 50이 하나라면 0.8 × 0.5 = 0.4가 남아 총 60% 감소입니다. Value=100 이상은 해당 단계에서 남는 피해가 0이며, 음수는 피해를 더 받게 합니다. 이는 일반 피해 계산상의 감소율이지, 공허 피해까지 막는 보장형 무적은 아닙니다.

시간 경과·조건부 효과는 런타임 BP의 Apply Item Stat Modifier로 구현하세요.

Skills — 무기·유물 스킬의 등록 정보

Skill Definitions 배열은 발동 가능 조건·입력·표시 정보를 담습니다. 실제 피해·이펙트는 런타임 BP의 Execute Item Skill에서 만듭니다. 스킬 없는 패시브·소모품은 비워 둡니다.

항목의미
Skill Id아이템 내 유일한 스킬 이름. 실행 이벤트에서 분기할 때 사용
Input Tag / Input Priority현재는 모든 장착 아이템을 통틀어 Input Tag가 같은 스킬을 한 입력 후보로 모읍니다. Input Priority는 같은 키의 의도된 동시 발동·우선순위를 조정하며, 무기/유물 또는 액티브 1·2번 슬롯을 자동으로 구분하지 않습니다. 실제 물리 키 연결은 Input Action·IMC에서 수행합니다.
Resource Cost / Base Cooldown / Minimum Cooldown마나·스태미나 소모와 쿨다운
Action Request액션 태그, 경직·기절·구르기·이동에 의한 취소 규칙, 진행 중 이동/구르기 차단 여부
Display Name / Description / Icon / Show On HUD / HUD Sort OrderHUD와 툴팁용 표시 정보
현재 구현에는 장착 슬롯별 자동 입력 분리가 없습니다. 서로 다른 액티브 유물에 같은 Input Tag를 지정하면 둘 다 후보가 됩니다. 슬롯별 입력이 구현되기 전에는 의도치 않은 겹침이 없는지 확인하세요. 향후에는 에셋에 물리 키나 ‘액티브 1번’을 고정하지 않고 아이템 내부 스킬 번호를 저장한 뒤, 장착된 무기/액티브 유물의 실제 슬롯 번호와 합쳐 입력을 연결할 예정입니다. 예: 무기 스킬 1…N, 액티브 1번의 스킬 1…N, 액티브 2번의 스킬 1…N. 장착 위치가 바뀌면 같은 유물의 입력도 함께 바뀌어야 합니다.
Runtime — 실제 기능을 담은 BP 클래스

Runtime Behavior Class는 필수입니다. 무기·액티브·패시브는 ARLoadoutItemInstance 자식, 소모품은 ARConsumableInstance 자식을 넣으세요. 유형과 다른 부모 클래스는 획득 시 거부됩니다.

  • 무기·유물: On Item Registered에서 타이머·조건부 효과 시작, On Item Unregistered에서 해제, Execute Item Skill에서 실제 스킬 실행
  • 소모품: Can Use Consumable에서 사용 가능 여부, Execute Consumable Use에서 즉발 효과 구현
  • 아이템이 제거되어도 남으면 안 되는 타이머·바인딩·효과는 등록 해제 이벤트에서 정리
데이터만 있는 무기·유물이라면 기본 ARLoadoutItemInstance 클래스를 사용할 수 있습니다. 소모품은 사용 효과를 구현한 자식 BP가 필요합니다.
Guarantees — 슈퍼아머와 CC 면역

두 효과는 Default Stat Modifiers의 숫자 스탯이 아니라 별도 보장 효과입니다. 유물 런타임 BP에서 Apply Item Super Armor 또는 Apply Item CC Immunity를 호출하세요. 둘 다 Duration에 초를 입력하고, -1은 무기한입니다. 아이템 제거 시 그 아이템이 부여한 핸들만 자동 회수됩니다. 원한다면 반환된 핸들로 Remove Own Item Super Armor / Remove Own Item CC Immunity를 호출해 먼저 해제할 수도 있습니다.

스킬 행동에만 묶으려면 Apply Action Super Armor / Apply Action CC Immunity를 사용하세요. 행동 종료·취소 시 자동 정리됩니다. 슈퍼아머는 경직만 막고 그로기 피해·상태이상은 막지 않습니다. CC 면역은 새 기절·속박의 적용을 차단하며, 이미 걸린 상태를 해제하지는 않습니다. 향후 추가하는 CC는 상태이상 데이터 에셋의 Is Crowd Control을 켜야 합니다. 일반 화상 등은 CC 면역에 영향받지 않습니다.

UI — 아이템 전용 게이지·스택 및 버프 아이콘

UI State Display Definitions는 아이템 자체의 별도 게이지·소형 스택 등을 위한 통로입니다. State Id, 표시 이름·아이콘, Display Type, 표시 위치를 정하고 런타임에서 Set Item UI State로 갱신합니다. 이 상태는 스탯 효과 중첩 수와는 별개이며, 과거의 Set Item UI Number 기반 패시브 HUD 문자 표시는 제거되었습니다.

버프·디버프와 중첩 아이콘은 Default Stat Modifiers 또는 런타임 Apply Item Stat Modifier의 FARStatModifierSpec를 사용합니다. 고유 Source Id를 입력하고 HUD Display를 Buff/Debuff로 고른 뒤 HUD Name과 HUD Icon을 지정하세요. bStackOnly를 켜면 스탯을 바꾸지 않고 중첩 하나만 기록합니다. 같은 Source Id를 여러 번 적용하면 독립 중첩되며 Get Modifiers By Source의 Stack Count로 읽습니다. 하나의 중첩이 스탯을 여러 개 바꾸면 첫 적용의 반환 핸들을 나머지 Spec의 Stack Group Handle에 넣어 중첩 하나로 묶으세요. bAffectedByTenacity는 유한 지속시간만 적용 시점에 줄입니다. 아이템 런타임에서 명시한 Source Id는 이제 보존되며 해제 시 각 적용 핸들로 정리됩니다.

기본 스탯 효과의 묶음·중첩 예시

데이터 에셋의 Default Stat Modifiers에서는 같은 Source Id를 적은 여러 항목이 아이템 장착 시 자동으로 중첩 하나로 묶입니다. 런타임 BP에서 여러 항목을 적용할 때만 첫 반환 핸들을 다음 항목의 Stack Group Handle에 넘기세요. 서로 독립적인 중첩을 추가할 때는 이 핸들을 비워 둡니다. Get Modifiers By Source는 실제 수정치 수가 아니라 묶음 수를 반환합니다.

Evolution — 무기일 때만 사용
필드의미
Evolution Group Id같은 진화 계열의 이름
Evolution Stage현재 단계. 1 이상

진화는 같은 객체를 수정하는 것이 아니라, 기존 무기를 새 정의의 무기로 교체합니다. 다른 유형은 이 필드를 비워 두세요.

종류별 제작 절차

  1. Content/Game/Objects/Items 아래 유형별 폴더에서 Data와 Runtime을 구분합니다.
  2. Data에 Data Asset → ARItemDefinition을 생성합니다. 별도 무기/유물/소모품 Definition 클래스는 사용하지 않습니다.
  3. Item Type Tag와 유형 내 중복되지 않는 양의 Item Id를 지정합니다. 필요한 계열명은 Additional Tags에 문자열로 더합니다.
  4. 무기·유물은 ARLoadoutItemInstance 계열, 소모품은 ARConsumableInstance 계열의 런타임 BP를 만들고 Runtime Behavior Class에 연결합니다.
  5. 상세 설명은 Display에 적고, 자동 스탯은 Stats에, 실제 조건부·스킬·사용 효과는 런타임 BP에 만듭니다.
  6. 월드 배치는 ARItemPickup의 Item Definition에 이 에셋을 지정합니다. 상점·보상 등 월드 픽업 이외의 경로는 Try Acquire Item을 호출할 수 있습니다.
  7. 저장 후 Validate Item Catalog로 전체 저장 에셋의 유형·ID 중복·런타임 클래스 연결을 검사합니다.
카탈로그 조회는 저장된 데이터 에셋만 검색합니다. 새 에셋을 만든 후 저장해야 Find Item By Key와 Find Items By Additional Tag가 찾을 수 있습니다. 슬롯이 찼거나 정의가 잘못되면 획득이 실패하므로 성공 결과를 확인하세요.

자주 쓰는 조회·획득 노드

Find Item By Key

입력: Item Type Tag, Item Id. 출력: 해당 ARItemDefinition 또는 없음. 중복 키가 있으면 오류 로그를 남기고 실패합니다.

Validate Item Catalog

출력: 유효 여부와 오류 문자열 배열. 저장된 모든 아이템의 유형·ID·런타임 부모를 검증합니다.

Find Items By Additional Tag

입력: 계열 문자열, 선택적 유형 필터. 출력: 일치하는 정의 배열. 계열명은 중복 가능하므로 여러 개가 나올 수 있습니다.

Count Owned Items By Additional Tag

입력: 플레이어, 계열 문자열, 선택적 유형 필터. 출력: 현재 소유한 개수. 동일 정의의 복수 인스턴스도 각각 셉니다.

Try Acquire Item

입력: 플레이어, 정의. 출력: 성공·실패 상태. 유형에 따라 장비/유물 또는 소모품 컴포넌트로 보냅니다.

기준 코드: ARItemDefinition.h, ARItemCatalogBlueprintLibrary.h, ARLoadoutComponent.cpp, ARConsumableComponent.cpp. 데이터 필드와 획득 검증은 현재 구현을 기준으로 작성했습니다.
