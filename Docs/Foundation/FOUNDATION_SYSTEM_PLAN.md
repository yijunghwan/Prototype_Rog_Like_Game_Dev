# 전투 기반 시스템 계획서

> **담당 범위:** 플레이어·공통 캐릭터·전투 기반 시스템  
> **문서 상태:** 구현 전 계획서  
> **목적:** 다른 개발자의 적·맵·콘텐츠 작업과 분리된 상태에서, 모든 전투 콘텐츠가 공통으로 사용할 확장 가능한 기반을 정의한다.

초기 Foundation은 **싱글플레이 전용**이다. 네트워크 Replication과 RPC는 구현 범위에 포함하지 않는다. 멀티플레이가 필요해지면 피해 권한, Action 예측, Runtime Instance 소유권을 별도 설계한 뒤 확장한다.

---

## 1. 담당 범위

이 문서는 `Foundation` 영역의 설계와 구현 순서를 다룬다.

### 포함

- 공통 캐릭터 기반 클래스, 플레이어 캐릭터, 환경 피해 출처 컴포넌트
- 스탯, 체력, 피해, 경직, 사망 처리
- 스태미나와 구르기
- 상태이상
- 무기 장착·교체·스킬·진화 기반 구조
- 액티브 유물·패시브 유물 기반 구조
- 플레이어 HUD에 전달할 전투 정보

### 제외

- 개별 적의 AI, 공격 패턴, 스폰 규칙
- 보스 설계
- 맵, 방 생성, 드롭 테이블
- 최종 도트 아트, 사운드, VFX 제작
- 영구 성장, 해금, 런 간 저장

제외 항목을 맡은 개발자는 Foundation의 공개 기능을 사용해 콘텐츠를 추가한다. 기반 규칙 자체를 바꿔야 할 경우에는 담당자와 먼저 논의한다.

---

## 2. 협업 경계와 폴더 원칙

사람 이름으로 된 영구 코드 폴더는 사용하지 않는다. 대신 **전투 기반 시스템**이라는 기능 경계를 Foundation으로 둔다.

```text
Action_RogueLike/
├─ Docs/
│  └─ Foundation/                       ← 이 계획서와 기반 시스템 문서
├─ Source/Action_RogueLike/
│  └─ Foundation/                       ← 담당 C++ 코드
│     ├─ Characters/
│     ├─ Components/
│     ├─ Combat/
│     ├─ Weapons/
│     ├─ Relics/
│     ├─ StatusEffects/
│     ├─ Systems/
│     └─ UI/
└─ Content/Game/
   ├─ Foundation/                       ← 기반 블루프린트·데이터 에셋
   ├─ Characters/
   ├─ Weapons/
   ├─ Relics/
   └─ UI/
```

위 구조는 Foundation의 **기능 경계**를 설명하는 그림이다. 실제 C++의 `Public`/`Private` 분리, 파일 단위 책임, Component·Data Asset·Runtime Instance 구조는 `FOUNDATION_CODE_ARCHITECTURE.md`를 기준으로 한다.

- `Source`에는 C++ 코드만 둔다.
- `Content`에는 블루프린트, UI 위젯, 스프라이트, 애니메이션, 데이터 에셋을 둔다.
- `Foundation`에는 공통 규칙만 둔다. 특정 적, 특정 맵, 특정 보스에만 필요한 코드는 해당 콘텐츠 영역에 둔다.

## 3. 핵심 구조

```text
ACharacter (언리얼 기본 클래스)
└─ AARBaseCharacter
   ├─ AARPlayerCharacter
   ├─ AARBaseEnemy
   │  └─ 이후 적·보스 클래스
   └─ 이후 플레이어·적 전용 자식 클래스
```

`AARBaseCharacter`는 플레이어와 적이 모두 쓰는 규칙만 가진다. 입력, 카메라, 유물 인벤토리처럼 플레이어만 필요한 기능은 `AARPlayerCharacter`에 둔다.

용암, 가시 함정, 낙석처럼 맵에 놓이는 환경 오브젝트는 Character를 상속하지 않는다. 필요한 일반 `Actor`에 `UARCombatSourceComponent`를 붙여 `Environment` 피해 출처로만 참여한다. 이 컴포넌트는 피해 요청의 공격자 팀·출처·로그 정보를 제공하며, 해당 Actor는 플레이어·적과 달리 피해 대상이 되지 않는다.

### 공통 컴포넌트

| 컴포넌트 | 책임 |
|---|---|
| `UARStatsComponent` | 기본 스탯, 보정값, 최종 스탯 계산 |
| `UARHealthComponent` | 체력, 피해, 회복, 사망 이벤트 |
| `UARStatusEffectComponent` | 상태이상 적용, 갱신, 중첩, 해제, 면역 |
| `UARStaggerComponent` | 즉시 경직, 경직 면역, 슈퍼아머, 선택형 그로기 게이지 |
| `UARActionComponent` | 현재 행동 등록, 시작 검증, 정상 종료, 경직에 의한 취소 |
| `UARMovementControlComponent` | 모든 플레이어·적 이동 요청의 공통 통로, 이동 잠금과 CharacterMovement 제어 |
| `UARLoadoutComponent` | 무기 1개, 액티브 유물 2개, 패시브 유물 목록, 장착·교체·진화·스킬 등록과 입력 요청 |
| `UARCombatSourceComponent` | 일반 맵 Actor가 `Environment` 팀의 피해 출처·로그 정보를 제공하도록 하는 선택형 컴포넌트 |

### 플레이어 전용 컴포넌트

| 컴포넌트 | 책임 |
|---|---|
| `UARStaminaComponent` | 현재 스태미나, 소비, 회복, 구르기 비용 처리 |
| `UARManaComponent` | 현재 MP, 소비, MP 재생, 회복 처리 |
| `UARConsumableComponent` | 가변 소모품 슬롯, 획득·사용·슬롯 수 변화와 초과 소모품 드롭 처리 |
| `UARCameraFollowComponent` | 정사영 카메라의 부드러운 추적, 거리 기반 가속과 최대 지연 제한 |
| `UARInteractionComponent` | 상호작용 후보 탐색, 거리·우선순위 검증, 현재 상호작용 대상 관리 |

### 전투 팀과 피격 대상 규칙

모든 플레이어·적 캐릭터는 `CombatTeam`을 가진다. 초기 팀은 `Player`, `Enemy`, `Environment` 세 종류다. `Environment`는 `UARCombatSourceComponent`가 붙은 일반 맵 Actor의 공격자 팀이며, 피격 대상이 되지 않는다.

| 공격자 팀 | 피해 가능 대상 |
|---|---|
| `Player` | `Enemy` |
| `Enemy` | `Player` |
| `Environment` | `Player`, `Enemy` |
| 같은 팀 | 피해 불가 |
| 모든 팀 | `Environment` 피격 불가 |

아군 피해는 초기 구현에서 항상 비활성이다. 소환수·중립 NPC·PVP처럼 추가 진영이 필요해질 때만 팀 열거형과 허용 표를 확장한다.

블루프린트의 히트박스·투사체는 충돌 채널, 팀 조회, `Can Damage Target`을 사용해 후보 대상을 먼저 걸러낸다. 그러나 이 필터는 성능과 연출을 위한 1차 처리일 뿐이다. `Apply Combat Damage`는 공격자·대상 팀을 C++에서 다시 확인하며, 허용되지 않은 조합이면 `InvalidTarget`을 반환하고 피해·보호막·흡수·적중 이벤트를 전혀 발생시키지 않는다.

| 노드 | 입력 | 반환 |
|---|---|---|
| `Can Damage Target` | 공격자 Actor, 피격 대상 Actor | 허용 여부와 사유(`Valid`, `SameTeam`, `InvalidSource`, `InvalidTarget`, `ForbiddenTarget`) |

## 4. 스탯 규칙

모든 `AARBaseCharacter`는 공통 `UARStatsComponent`를 가진다. 스탯 시스템은 아래의 모든 항목을 지원하지만, 개별 적은 필요하지 않은 값을 기본값 `0` 또는 무효 값으로 둘 수 있다.

### 공통 캐릭터 스탯

플레이어·적·보스가 전투에서 사용할 수 있는 스탯이다. `피해(Damage)`는 이 스탯 중 하나가 아니라 모든 계산 뒤 대상에게 실제로 전달된 결과의 총칭으로 사용한다.

| 분류 | 스탯 | 역할 |
|---|---|---|
| 생존 | 최대 체력 | 버틸 수 있는 최대 체력 |
| 생존 | 회복력 | 콘텐츠가 회복량을 계산할 때 선택적으로 사용하는 최대 체력 비율 기준 수치. 이 공식을 사용할 경우 회복력 100은 최대 체력의 100%에 해당하며, 자동 회복을 뜻하지 않음 |
| 방어 | 물리 방어력 | 물리 피해의 방어 계산에 쓰는 수치. 최종 최소값은 0 |
| 방어 | 화염 방어력 | 화염 피해의 방어 계산에 쓰는 수치. 최종 최소값은 0 |
| 방어 | 마법 방어력 | 마법 피해의 방어 계산에 쓰는 수치. 최종 최소값은 0 |
| 방어 | 전체 피해 감소율 | 모든 일반 피해의 최종 감소율. 독립 피해 감소 효과를 남은 피해 배율로 곱해 계산하며, 실제 감소 효과는 100%를 넘을 수 없음 |
| 방어 | 물리 피해 감소율 | 물리 피해에만 적용되는 최종 감소율. 전체 피해 감소율과 별도로 독립 곱연산 처리 |
| 방어 | 화염 피해 감소율 | 화염 피해에만 적용되는 최종 감소율. 전체 피해 감소율과 별도로 독립 곱연산 처리 |
| 방어 | 마법 피해 감소율 | 마법 피해에만 적용되는 최종 감소율. 전체 피해 감소율과 별도로 독립 곱연산 처리 |
| 방어 | 회피력 | 회피 가능한 피해 요청을 확률적으로 무효화하는 수치. 최종 상한은 캐릭터별 `최대 회피력`으로 제한 |
| 기본 전투 | 공격력 | 무기 공격·물리 계열 등 공격력 기반 기술의 기준 수치 |
| 기본 전투 | 주문력 | 화염·마법 계열 등 주문력 기반 기술의 기준 수치 |
| 기본 전투 | 경직력 | 공격의 기본 경직 피해를 강화하는 공격자 수치 |
| 기본 전투 | 이동 속도 | 이동 성능 |
| 기본 전투 | 공격 속도 | 공격 간격 또는 시전 속도 |
| 기본 전투 | 사거리 | 공격·투사체·스킬의 거리 관련 기준 수치 |
| 기본 전투 | 치명타 확률 | 치명타 발생 확률 |
| 기본 전투 | 치명타 피해량 | 치명타 발생 시 적용할 피해 배율 |
| 기본 전투 | 방어 관통률 | 대상의 양수 속성 방어력만 무시하는 비율. 수치 자체에는 상한이 없지만, 실제 관통 효과는 100%를 넘을 수 없음 |
| 기본 전투 | 흡수 | 최종 피해량에 비례해 회복하는 수치. 수치 1당 피해 1,000마다 체력 1을 회복하며 소수점은 누적 |
| 피해 증폭 | 전체 피해 증폭 | 모든 일반 피해를 증폭 |
| 피해 증폭 | 직접 피해 증폭 | 직접 피해 전달 방식만 증폭 |
| 피해 증폭 | 지속 피해 증폭 | 지속 피해 전달 방식만 증폭 |
| 피해 증폭 | 물리 피해 증폭 | 물리 속성 피해만 증폭 |
| 피해 증폭 | 화염 피해 증폭 | 화염 속성 피해만 증폭 |
| 피해 증폭 | 마법 피해 증폭 | 마법 속성 피해만 증폭 |
| 피해 증폭 | 그로기 피해 증폭 | 공격이 주는 그로기 피해만 증폭 |
| 피격 피해 증가 | 물리 피격 피해 증가율 | 대상이 받는 물리 피해를 방어 계산 뒤 별도로 증가시키는 취약 수치. 최종 최소값은 0 |
| 피격 피해 증가 | 화염 피격 피해 증가율 | 대상이 받는 화염 피해를 방어 계산 뒤 별도로 증가시키는 취약 수치. 최종 최소값은 0 |
| 피격 피해 증가 | 마법 피격 피해 증가율 | 대상이 받는 마법 피해를 방어 계산 뒤 별도로 증가시키는 취약 수치. 최종 최소값은 0 |
| 경직·그로기 | 강인함 | 기절·속박 등 상태이상 지속시간을 줄이는 저항 수치 |
| 경직·그로기 | 경직 저항력 | 최종 경직 피해보다 낮으면 일반 경직이 발생하는 방어 측 수치. 최종 상한 없음 |
| 경직·그로기 | 최대 그로기 수치 | 그로기 게이지를 사용하는 대상의 최대 게이지량 |
| 경직·그로기 | 그로기 회복 지연 시간 | 마지막 그로기 피해 뒤 게이지 회복을 시작하기까지의 시간 |
| 경직·그로기 | 초당 그로기 회복량 | 회복 중인 그로기 게이지의 초당 회복량 |

일반 적은 치명타 확률·회피력·회복력·그로기 관련 값을 `0` 또는 비활성으로 둘 수 있다. 특수 적과 보스는 같은 구조를 사용해 필요할 때만 해당 스탯을 활성화한다. `공허`는 일반 속성 및 방어력 스탯에 포함하지 않으며, 일반 무적을 관통할 수 있는 시스템성 특수 피해로 별도 정의한다.

### 플레이어 전용 스탯

플레이어 조작과 로그라이크 성장에만 직접 사용하는 스탯이다. 코드상으로는 공통 스탯 시스템이 값을 지원할 수 있으나, 초기 구현에서 적은 이를 사용하지 않는다.

| 분류 | 스탯 | 역할 |
|---|---|---|
| 로그라이크 | 행운 | 유물·드롭·확률형 특수 효과의 기준 |
| 스태미나 | 최대 스태미나 | 구르기와 향후 특수 행동에 쓰는 자원량 |
| 스태미나 | 스태미나 회복량 | 스태미나가 차오르는 속도 |
| 스태미나 | 스태미나 회복 대기시간 | 마지막 스태미나 소비 후 회복을 시작하기까지 기다리는 시간 |
| 구르기 | 구르기 스태미나 소모량 | 구르기 1회에 소비하는 스태미나. Player Character Details의 기본값에 런타임 스탯 수정치를 적용하며, 실제 소비값은 최종값을 0 이상으로 제한 |
| 구르기 | 구르기 거리 | 회피 이동 거리 |
| 구르기 | 구르기 회피 보장 시간 | 구르기 중 필중이 아닌 회피 판정 적용 피해를 100% 회피하는 시간 |
| MP | 최대 MP | 무기 스킬·향후 기술에 쓰는 자원량 |
| MP | MP 재생 | MP가 차오르는 속도 |
| 소모품 | 최대 소모품 슬롯 수 | 포션 등 독립 소모품을 보관할 수 있는 슬롯 수. 최종값은 0 이상의 정수로 처리하며, 감소 시 초과 슬롯 소모품은 월드에 드롭 |
| 스킬 | 쿨다운 감소율 | 최종 재사용 대기시간을 줄이는 비율. 최종 상한은 캐릭터별 `최대 쿨다운 감소율`로 제한 |

### 스탯과 실시간 자원의 구분

- `최대 체력`, `최대 스태미나`, `최대 MP`, `최대 그로기 수치`는 스탯이다.
- `현재 체력`, `현재 보호막`, `현재 스태미나`, `현재 MP`, `현재 그로기 수치`는 플레이 도중 계속 변하는 자원값이다.
- 체력은 최대 체력을 넘을 수 없다. 회복력은 자동 초당 재생이 아니라 별도의 회복 시점에서만 사용한다.
- 보호막은 별도 최대치 없이 임시 체력으로 구현한다. 보호막은 인스턴스별 수치와 지속시간을 가지며, 현재 보호막은 활성 인스턴스의 합계다.
- 실시간 자원은 각각 `HealthComponent`, `StaminaComponent`, `ManaComponent`, `StaggerComponent`가 관리한다. 블루프린트는 이 값을 직접 변경하지 않는다.

최종 스탯은 아래 원칙을 따른다.

```text
최종 스탯
= (Details 기본 수치 + 획득한 고정 수치)
× (1 + 합연산 보정 총합 ÷ 100)
× 모든 곱연산 보정
```

`StatsComponent`는 스탯 수정치가 추가·제거·만료될 때 해당 최종 스탯을 즉시 다시 계산해 캐시한다. 피해, 지속 피해, UI 등 다른 시스템이 `Get Final Stat`을 호출할 때는 수정치 목록을 매번 순회하지 않고 이 캐시 값을 읽는다. 따라서 수정치 목록의 크기와 무관하게 일반적인 스탯 조회는 상수 시간으로 처리한다.

무기 배율은 해당 스탯에 적용되는 곱연산 보정으로 취급한다. 같은 수치에 더해지는 보정은 합연산 보정, 기존 결과를 비율로 바꾸는 보정은 곱연산 보정으로 분리한다. 예를 들어 Details 패널에 보이는 현재 `강인함`은 기본 강인함에 모든 합연산·곱연산 보정을 적용한 최종값이다.

체력, 행운, 회복력, 회피력, 구르기 관련 값처럼 무기에 따라 달라질 필요가 적은 값은 무기 배율 적용 대상에서 제외할 수 있다. 각 무기가 어떤 스탯에 배율을 적용하는지는 무기 데이터에 명시한다. 공격의 피해가 공격력·주문력 중 무엇을 기준으로 삼는지는 이후 무기·스킬의 `DamageSpec`에서 공격별로 명시한다.

### 캐릭터별 최종 상한

아래 값은 전역 고정 상한이 아니라 각 BaseCharacter·Player·Enemy 블루프린트의 `StatsComponent` Details 패널에서 정한다. 스탯 보정을 모두 적용한 뒤 최종값을 해당 상한으로 제한한다.

| Details 항목 | 제한 대상 | 용도 |
|---|---|---|
| 최대 쿨다운 감소율 | 쿨다운 감소율 | 캐릭터 또는 보스별 쿨다운 감소 한도를 조절 |
| 최대 회피력 | 회피력 | 캐릭터 또는 보스별 회피 확률 한도를 조절 |
| 최대 치명타 확률 | 치명타 확률 | 캐릭터 또는 보스별 치명타 확률 한도를 조절 |
| 최대 강인함 | 강인함 | 장비·유물·임시 효과로 높아질 수 있는 강인함의 최종 한도를 조절 |

쿨다운 감소율은 캐릭터 상한을 높게 설정하더라도 재사용 대기시간이 정확히 0이 되는 것을 막기 위해, 각 행동이 가진 `최소 재사용 대기시간`보다 낮아질 수 없다. 이 최소값은 나중에 무기·스킬 데이터에서 정한다.

이동 속도와 공격 속도는 초기 기반에서 최종 상한을 두지 않는다. 경직 저항력도 최종 상한을 두지 않는다. 물리·화염·마법 방어력과 물리·화염·마법 피격 피해 증가율의 최종 최저치는 공통으로 `0`이며, 방어 관통률은 대상 방어력이 양수일 때만 적용한다. 전체·물리·화염·마법 피해 감소율은 감소 효과가 100%를 넘지 않으며, 음수 감소율은 받는 피해 증가로 작동할 수 있다.

### 스탯 단위·최솟값·정수화 규칙

| 스탯 종류 | 단위와 기준 | 최종 안전 규칙 |
|---|---|---|
| 이동 속도 | Unreal Unit/초 | `0` 이상, 상한 없음 |
| 공격 속도 | `100 = 1배` | 계산 시 최소 `1`로 제한, 상한 없음 |
| 사거리 | Unreal Unit 또는 콘텐츠의 기본 거리 배율 입력값 | 공격 Definition이 절대 거리/배율 사용 여부를 명시 |
| 치명타 확률·회피력·강인함 | `%` | 캐릭터별 Details 상한 적용 후 실제 확률·지속시간 계산에서는 `0~100`으로 제한 |
| 치명타 피해량 | `%`, `150 = 1.5배` | 최소 `0` |
| 방어 관통률 | `%` | 스탯 자체 상한 없음, 유효 관통은 `0~100` |
| 최대 체력 | 자원 수치 | 최소 `1` |
| 최대 스태미나·최대 MP·최대 그로기 | 자원 수치 | 최소 `0` |
| 최대 소모품 슬롯 수 | 개수 | 최종 실수값을 `Floor`한 뒤 최소 `0` |

공격 속도의 공통 시간 변환은 아래와 같다. 공격 Definition은 선딜·후딜·차지 중 어떤 구간에 공격 속도를 적용할지 명시한다.

```text
공격 속도 적용 시간
= 기본 시간 × 100 ÷ Max(최종 공격 속도, 1)
```

최대 자원 스탯이 런타임에 바뀌면 현재값은 새 최대값 이하로 즉시 제한한다. 최대값이 증가해도 현재값을 자동 회복하지 않는다. 이 변화는 `On Resource Changed`를 발생시키며, 별도 회복 효과만 현재값을 증가시킨다.

### 독립 피해 감소율 누적

전체·물리·화염·마법 피해 감소율은 일반 스탯의 `고정 + 합연산% + 곱연산%` 공식으로 합산하지 않는다. 이 네 스탯만 `IndependentDamageReduction` 정책을 사용한다. Details 기본값과 각 `독립 피해 감소` 수정치를 개별 감소 효과로 보관하고, 남은 피해 배율을 서로 곱한다.

```text
감소 효과 R 하나의 남은 피해 배율
= Max(0, 1 - Min(R, 100) ÷ 100)

최종 남은 피해 배율
= 모든 감소 효과의 남은 피해 배율을 곱한 값

표시용 최종 피해 감소율
= (1 - 최종 남은 피해 배율) × 100
```

따라서 ‘받는 피해 50% 감소’ 효과 두 개는 `0.5 × 0.5 = 0.25`의 남은 피해 배율, 즉 최종 피해 감소율 75%가 된다. 음수 감소 효과는 남은 피해 배율을 1보다 크게 만들어 받는 피해를 증가시킨다. 일반 `Apply Stat Modifier`에서 전체·물리·화염·마법 피해 감소율을 선택하면, 이 네 스탯에만 `독립 피해 감소` 수정 방식이 추가로 표시된다. 무적 보장은 이 규칙과 별개로 일반 피해의 남은 피해 배율을 강제로 0으로 만드는 관리형 항목이다.

### 회피 판정

- 최종 회피율은 캐릭터 Details의 `최대 회피력`을 상한으로 사용한다.
- 각 피해 요청은 `회피 판정 적용 여부`를 가진다. 적용된 요청만 대상의 최종 회피율로 회피 판정을 한다.
- 직접 타격은 공격 설계에 따라 회피 판정을 사용할 수 있다.
- 이미 적중해 적용된 지속 피해의 개별 틱은 기본적으로 회피 판정을 하지 않는다. 즉, 최초 적중을 회피하지 못해 화상 등 지속 피해가 적용되었다면 이후의 주기 피해는 회피 불가다.
- 피해 노드의 `필중` 옵션은 회피 판정을 건너뛴다. `필중`과 회피 적용이 함께 설정되면 필중이 우선한다.

### 흡수 적용

피해 노드는 `흡수 적용 여부`를 가진다. 체크된 피해만 최종 피해량을 기준으로 공격자의 흡수 누적값을 올린다. 체크하지 않은 피해는 흡수 스탯이 있어도 회복을 발생시키지 않는다.

### 회복력·자원·쿨다운 계산

회복력은 캐릭터가 보유할 수 있는 최종 스탯으로 유지한다. 다만 Foundation의 체력 회복 노드는 회복력을 자동으로 읽거나 특정 회복 공식을 강제하지 않는다. 포션·유물·스킬 같은 콘텐츠 블루프린트가 필요에 따라 `Get Final Stat(회복력)`을 읽어 회복량을 계산하거나, 고정 수치·최대 체력 비율 등 자체 규칙으로 회복량을 만든 뒤 공통 회복 노드에 전달한다. 자동 체력 재생은 초기 기반에 넣지 않는다.

공통 회복 노드는 전달받은 회복량을 현재 체력에 적용하고 최대 체력으로만 제한한다. 회복력 100이 어떤 콘텐츠에서 최대 체력의 100% 회복을 뜻하게 할지는 해당 콘텐츠 설계가 정한다. 체력은 어떤 회복 방식으로도 최대 체력을 넘을 수 없다.

MP는 초당 재생량을 소수점까지 누적해 처리한다.

```text
누적 재생량 += 최종 재생량 × DeltaTime
적용량 = Floor(누적 재생량)
누적 재생량 -= 적용량
현재 MP = Min(최대 MP, 현재 MP + 적용량)
```

스태미나는 소비 직후 즉시 회복하지 않는다. 모든 스태미나 소비는 공통 `Consume Stamina` 처리로 들어가며, 성공한 소비마다 마지막 소비 시점을 갱신한다. 지속적으로 스태미나를 소비하는 행동도 매 소비마다 같은 규칙을 사용한다.

```text
스태미나 소비 성공
→ 현재 스태미나 감소
→ 마지막 스태미나 소비 시점 = 현재 시간

현재 시간 >= 마지막 스태미나 소비 시점 + 스태미나 회복 대기시간
→ 스태미나 누적 재생량 += 초당 스태미나 회복량 × DeltaTime
→ 적용량 = Floor(스태미나 누적 재생량)
→ 스태미나 누적 재생량 -= 적용량
→ 현재 스태미나 = Min(최대 스태미나, 현재 스태미나 + 적용량)
```

```text
실제 쿨다운 감소율
= Min(최종 쿨다운 감소율, Details 최대 쿨다운 감소율)

최종 쿨다운
= Max(스킬 최소 쿨다운,
      기본 쿨다운 × (1 - 실제 쿨다운 감소율 ÷ 100))
```

### 일반 피해 계산: 물리·화염·마법

피해 전달 방식은 `직접`과 `지속`으로 구분하고, 일반 피해 속성은 `물리`, `화염`, `마법`으로 구분한다. 모든 중간 계산은 실수로 유지하고, 최종 피해를 체력·보호막에 적용하기 직전에만 내림한다.

#### 1. 명중과 회피

```text
필중 = true
→ 무조건 명중

필중 = false, 회피 판정 적용 = true
→ Random < Clamp(대상 최종 회피력, 0, 대상 최대 회피력) 이면 회피

회피 성공
→ 해당 피해 이벤트 종료
```

지속 피해의 개별 틱은 기본적으로 회피 판정을 사용하지 않는다. 최초 직접 타격을 회피하지 못해 화상 등이 적용되었다면, 그 뒤의 틱은 회피 불가다.

#### 2. 기본 피해, 증폭, 치명타

무기·스킬은 이후 `공격력 계수`, `주문력 계수`를 데이터로 가진다. 계수의 구체적 값은 무기 제작 단계에서 결정한다.

```text
기본 피해
= 공격 기본 피해
+ (공격력 × 공격력 계수)
+ (주문력 × 주문력 계수)

총 피해 증폭률
= 전체 피해 증폭
+ 직접/지속 피해 증폭
+ 물리/화염/마법 피해 증폭

증폭 후 피해
= 기본 피해 × Max(0, 1 + 총 피해 증폭률 ÷ 100)
```

```text
치명타 가능
→ Random(0 이상 100 미만)
  < Clamp(최종 치명타 확률,
          0,
          Min(캐릭터 최대 치명타 확률, 100))
이면 치명타 성공

치명타 성공
→ 치명타 적용 피해
= 증폭 후 피해 × (치명타 피해량 ÷ 100)
```

회피와 치명타 난수는 C++ Resolver가 주입받은 `FRandomStream`으로 판정한다. 자동화 테스트는 고정 Seed 또는 지정된 Roll 값을 사용해 결과를 재현한다.

치명타 피해량 `150`은 1.5배를 뜻한다. 지속 피해도 피해 요청의 치명타 적용 여부를 켜면 동일한 방식으로 치명타를 적용할 수 있다.

#### 3. 방어 관통과 속성 방어력

방어 관통률은 대상 방어력이 양수일 때만 적용한다. 물리·화염·마법 방어력의 최종값은 공통으로 `0`보다 낮아질 수 없다.

```text
대상 속성 방어력 > 0
→ 유효 방어력
= 대상 속성 방어력
 × (1 - Clamp(공격자 방어 관통률, 0, 100) ÷ 100)

대상 속성 방어력 = 0
→ 유효 방어력 = 0

방어력 적용 후 피해
= 치명타 적용 피해 × 100 ÷ (100 + 유효 방어력)
```

#### 4. 속성별 피격 피해 증가, 전체·속성별 피해 감소율과 최종 피해

속성별 피격 피해 증가율은 공격자의 피해 증폭과 별개로, **피격 대상**이 보유하는 취약 수치다. 물리·화염·마법 피해에만 존재하며 공허에는 적용하지 않는다. 이 수치는 방어력 계산 뒤, 전체·속성별 피해 감소율 계산 전에 적용한다. `피해 증감식 적용`이 꺼진 피해 요청은 공격자 피해 증폭과 대상의 속성별 피격 피해 증가를 모두 적용하지 않는다.

```text
속성별 피격 피해 증가율
= 대상의 물리 / 화염 / 마법 피격 피해 증가율

피격 증가 적용 후 피해
= 방어력 적용 후 피해
 × (1 + 속성별 피격 피해 증가율 ÷ 100)
```

```text
전체 남은 피해 배율
= 대상 전체 피해 감소율의 최종 남은 피해 배율

속성별 남은 피해 배율
= 대상 물리 / 화염 / 마법 피해 감소율의 최종 남은 피해 배율

계산 피해
= 피격 증가 적용 후 피해
 × 전체 남은 피해 배율
 × 속성별 남은 피해 배율

최종 피해
= Max(1, Floor(계산 피해))
```

단, 회피 성공, 일반 무적, 전체 또는 해당 속성의 최종 남은 피해 배율이 `0`, 기본 피해가 0 이하인 경우에는 최소 피해 1을 적용하지 않고 피해 결과를 0으로 처리한다. 일반 무적에 의해 피해가 0이 된 경우에는 해당 일반 피해 이벤트의 흡수·경직·그로기·상태이상도 적용하지 않는다.

### 공허 피해 계산

공허는 일반 속성 방어력을 갖지 않는 시스템성 특수 피해다. 공허 피해도 필중·회피, 기본 피해, 전체 피해 증폭, 직접/지속 피해 증폭, 치명타 규칙을 그대로 적용한다. 단, 공허 전용 피해 증폭 스탯은 초기 기반에 넣지 않는다.

```text
명중/회피
→ 기본 피해
→ 전체·직접/지속 피해 증폭
→ 치명타
→ Floor 및 최소 피해 1 보장
→ 보호막·체력 적용
```

공허 피해는 물리·화염·마법 방어력, 방어 관통률, 전체·물리·화염·마법 피해 감소율과 일반 무적을 무시한다. 피해 요청의 `보호막 무시`가 켜진 경우에만 보호막도 무시한다. 경직·그로기·상태이상 적용 여부는 공허 속성 자체가 결정하지 않고, 피해 요청의 별도 효과로 결정한다.

### 보호막·흡수·적중시 효과

보호막은 여러 인스턴스가 단순 합산되며, 각각의 지속시간은 독립적이다.

```text
현재 보호막 = 활성 보호막 인스턴스의 잔여량 합계
보호막 피해 = Min(현재 보호막, 최종 피해)
체력 피해 = 최종 피해 - 보호막 피해
```

새 보호막은 보호막 스택의 최상단에 넣는다. 피해는 **가장 최근에 받은 보호막부터** 차감한다. 한 인스턴스가 0이 되면 제거하고, 남은 피해를 그 이전 인스턴스에 계속 적용한다. 인스턴스의 지속시간이 끝나면 남은 양만 제거한다.

```text
흡수 적용 여부 = true
→ 흡수 누적값 += 최종 피해 × 공격자 흡수 ÷ 1000
→ 누적값이 1 이상이면 정수만큼 공격자 체력 회복
→ 소수점은 누적값에 유지
```

흡수는 보호막에 막힌 피해를 포함한 최종 피해량을 기준으로 계산한다.

`타격당 추가 피해` 스탯은 사용하지 않는다. 대신 직접 피해 요청은 `적중시 효과 적용` 옵션을 가진다. 이 옵션이 켜진 직접 타격이 회피·일반 무적에 막히지 않고 성공하면 `On Damage Hit` 이벤트가 발생하며, 유물·무기 런타임 BP는 이 이벤트를 받아 화상 부여, 보호막 획득, 별도 추가 피해 등 원하는 효과를 기존 공통 노드로 구현한다.

적중시 효과가 별도 피해를 발생시킬 때는 새 피해 요청의 `적중시 효과 적용`을 기본적으로 끈다. 따라서 적중 효과가 자기 자신을 다시 호출해 무한히 연쇄되는 일이 없다. 특별히 연쇄를 의도하는 콘텐츠는 별도 횟수·깊이 제한을 가진 전용 규칙을 나중에 추가한다.

## 5. 플레이어 기본 기능

### 조작

플레이어 입력은 언리얼 Enhanced Input의 `IMC_Player`에서 액션으로 관리한다. 키 배치는 IMC에서 바꿀 수 있으며, 실제 이동·구르기·마우스 조준의 처리 규칙은 `AARPlayerCharacter` C++가 가진다.

| 입력 액션 | 초기 입력 | 책임 |
|---|---|---|
| `IA_Move` | `WASD` | C++가 2D 이동 벡터로 변환해 기본 이동 처리. 관리형 `Can Basic Move`가 꺼져 있으면 입력을 무시 |
| `IA_Roll` | `Space Bar` | C++가 `ActionComponent`에 구르기 행동 요청 |
| `IA_PrimaryAttack` | 마우스 좌클릭 | 이후 무기 블루프린트의 기본 공격 행동 요청 |
| `IA_Aim` | 마우스 커서 월드 위치 | C++가 커서를 탑뷰 월드 평면에 투영해 바라보는 방향 계산 |
| 이후 무기 스킬·액티브 유물 액션 | 추후 지정 | 모두 IMC 액션에서 논리적 스킬 입력 태그를 전달 |
| `IA_UseConsumableSlot` | `1`, `2`, `3`… | 숫자키와 같은 번호의 소모품 슬롯에 즉발 사용 요청을 전달. 슬롯 증가 시 `4`, `5`처럼 순서대로 확장 |

`IMC_Player`의 등록은 Player Controller가 담당하고, Player Character는 Enhanced Input 액션을 바인딩해 실제 플레이어 행동을 수행한다. 마우스 조준은 단순 키 바인딩이 아닌 커서 좌표를 쓰므로 매 프레임 C++ 조준 로직이 갱신한다.

### 탑뷰 카메라

이 프로젝트의 화면 표현은 **64×64 도트 그래픽과 Paper2D**를 기준으로 한다. 따라서 기본 카메라는 원근이 아닌 **정사영(Orthographic) 탑뷰 카메라**를 사용한다. 고정된 탑뷰 회전과 `Ortho Width`를 유지하며, 플레이어를 목표점으로 부드럽게 추적한다. 프로토타입 초기에는 조준 방향 오프셋을 사용하지 않고 플레이어 중심을 유지한다.

캐릭터·적의 시각 표현은 Paper2D 스프라이트/플립북으로 구성한다. 픽셀 아트가 흐려지거나 화면 이동 중 흔들려 보이지 않도록, 스프라이트 텍스처는 Nearest 필터링을 사용하고 카메라 `Ortho Width`와 목표 해상도는 정수 배율을 유지하도록 별도로 조정한다. 이것은 연출 규칙이 아니라 전체 콘텐츠가 따라야 할 렌더링 기준이다.

```text
플레이어와 카메라 목표점이 가까움
→ 낮은 추적 속도로 부드럽게 따라감

거리가 추적 임계값을 넘음
→ 거리 비례로 더 높은 추적 속도를 사용

최대 허용 거리 초과
→ 매우 빠르게 따라잡아 플레이어가 화면에서 벗어나지 않게 함
```

카메라의 이동 감각은 `AARPlayerCharacter` C++ 또는 전용 C++ 카메라 추적 컴포넌트가 담당한다. 고정된 카메라 컴포넌트(필요 시 스프링암 포함)의 실제 위치를 블루프린트 Tick으로 직접 옮기지 않는다. 대신 아래 튜닝값은 Details 또는 카메라 데이터 에셋으로 노출해 코드 수정 없이 조절한다.

- 기본 추적 속도
- 추적 가속을 시작하는 거리
- 최대 추적 속도
- 최대 허용 카메라 지연 거리
- 정사영 폭(`Ortho Width`)과 고정 회전
- 목표 해상도에서의 픽셀 정수 배율

카메라 흔들림, 정사영 폭을 이용한 줌 연출, 보스 연출 같은 콘텐츠성 효과는 이후 블루프린트·시퀀스로 추가할 수 있지만, 기본 추적 규칙은 C++가 항상 권한을 가진다.

### 구르기

- 구르기 시작 시 플레이어의 최종 `구르기 스태미나 소모량`을 `Try Consume Stamina`으로 소비한다. Details의 기본값과 무기·유물·버프 등의 수정치가 모두 반영되며, 최종 소모값이 `0`이면 스태미나 없이 시작할 수 있다.
- 짧은 거리 이동하고, 정해진 회피 보장 시간을 가진다. 이 시간에는 필중이 아닌 회피 판정 적용 피해를 100% 회피한다. 필중 피해는 정상 적중하며, 이미 적용된 지속 피해 틱은 기본적으로 회피 판정을 하지 않으므로 계속 적용된다.
- 연속 사용은 가능하지만 스태미나가 부족하면 사용할 수 없다.
- 구르기 중 공격 가능 여부와 후딜은 무기 또는 유물 효과로 예외를 줄 수 있다.

## 6. 상태이상, 경직, 그로기

상태이상은 개별 기능을 따로 만들지 않고 하나의 공통 규칙으로 관리한다.

### 상태이상 Definition이 가져야 할 정보

- Asset Manager용 `PrimaryAssetId`와 상태 Gameplay Tag
- 표시 이름·아이콘
- 기본 지속시간과 동일 상태 갱신 정책
- 이동·구르기·Skill Group 시작 제한
- 적용 시 Action 취소 규칙
- 해제 조건과 면역 여부

런타임 남은 시간은 Definition이 아니라 `UARStatusEffectComponent`의 상태 인스턴스가 소유한다. 화상·독의 피해량과 틱 간격은 초기 상태이상 Definition에 넣지 않고 DOT Spec이 소유한다.

### 초기 상태이상

| 상태 | 초기 효과 방향 |
|---|---|
| 기절 (Stun) | 이동 불가, 현재 행동 강제 취소, 공격·무기 스킬·액티브 유물·구르기 시작 불가 |
| 속박 (Root) | 이동·구르기 불가. 공격·무기 스킬·액티브 유물은 가능 |

침묵, 둔화 같은 추가 CC와 화상 같은 상태형 DOT는 초기 CC 구현 범위에서 제외한다. 화상·독 등 지속 피해는 이미 정의한 `Apply Damage Over Time`으로 독립 구현할 수 있으며, 필요해질 때 상태이상 정의와 연결한다.

### 상태이상 지속시간과 동일 상태 처리

```text
최종 상태이상 지속시간
= 기본 지속시간
 × (1 - Clamp(대상 강인함, 0, 100) ÷ 100)
```

강인함이 100 이상이면 상태이상 지속시간은 0이므로 해당 상태이상은 적용하지 않는다.

- 서로 다른 종류의 상태이상은 독립적으로 동시에 적용한다.
- 동일한 기절·속박은 중첩하지 않으며, 기존 남은 시간과 새 최종 지속시간 중 더 긴 값만 유지한다.
- 지속 피해의 중첩 방식은 효과 정의 또는 `Apply Damage Over Time` 요청이 지정한다. 같은 지속 피해 이름을 독립 중첩으로 둘 수도 있고, 같은 이름의 기존 지속 피해 하나만 유지하며 지속시간을 초기화하는 방식으로 둘 수도 있다.
- 화상 등의 지속 피해 틱 간격은 초기 기준 `0.25초`다.
- 지속 피해는 적용 직후 즉시 틱을 주지 않는다. 첫 피해는 지정한 틱 간격이 지난 뒤 발생하며, 이후에도 지정한 간격마다 지속시간 안에서만 발생한다.

### 기절·속박의 공통 행동 제어

기절과 속박은 `값이 1이면 멈춤` 같은 스탯이 아니다. `StatusEffectComponent`가 활성 상태 태그와 남은 시간을 소유하고, `AARBaseCharacter`·`ActionComponent`·이동 시스템이 그 상태를 공통으로 조회하는 방식이다. 따라서 플레이어와 이후 적 캐릭터가 같은 규칙을 자동으로 사용하며, 적 개발자가 개별 공격마다 별도 예외 처리를 할 필요가 없다.

캐릭터는 `bIsStunned`, `bIsRooted`처럼 콘텐츠가 직접 쓰는 변경 가능한 Boolean을 소유하지 않는다. 필요할 때 블루프린트·UI·애니메이션이 읽는 `Is Stunned`, `Is Rooted`, `Has Status Effect`는 `StatusEffectComponent`의 활성 효과 목록에서 계산한 **읽기 전용 결과값**이다. 상태이상은 항상 `Apply Status Effect`와 `Remove Status Effect`로만 바꾼다. 따라서 강인함에 따른 최종 지속시간, 동일 기절·속박의 더 긴 시간 갱신, 면역과 해제 처리가 한 곳에서 일관되게 적용된다.

```text
속박 또는 기절 적용
→ AARBaseCharacter C++가 CharacterMovement의 속도·가속을 즉시 0으로 만듦
→ CharacterMovement를 MOVE_None 상태로 전환해 표준 이동 자체를 잠금
→ AIController가 진행 중인 MoveTo 요청을 중단
→ 플레이어 C++는 이동 입력을 무시
→ 적의 AddMovementInput·AI MoveTo는 CharacterMovement를 사용하므로 공통으로 이동 불가

모든 이동 잠금 상태 해제
→ 이전 CharacterMovement 모드를 복구하고, AI는 다음 행동 갱신에서 새 MoveTo를 요청
```

서로 다른 상태가 동시에 이동을 막을 수 있으므로 단일 Boolean을 직접 켜고 끄지 않는다. 활성 기절 또는 속박이 하나라도 있으면 이동 잠금은 유지되며, 마지막 이동 잠금 상태가 끝날 때만 이동을 재개한다.

```text
기절 적용
→ 이동 잠금
→ ActionComponent가 현재 행동을 Stun 사유로 강제 취소
→ 공격·무기 스킬·액티브 유물·구르기 시작 요청 거부

속박 적용
→ 이동 잠금
→ 진행 중 구르기만 Root 사유로 취소
→ 공격·무기 스킬·액티브 유물은 계속 허용
```

속박은 일반 공격을 취소하지 않는다. 이동을 포함한 모든 행동도 위치를 직접 바꾸지 않고 공통 이동 통로를 사용하므로, 속박 중에는 실제 이동만 자동으로 정지한다.

**공통 이동 고정 규칙:** 플레이어 이동, 적 추적·순찰, 구르기, 돌진, 점프, 넉백은 모두 `UARMovementControlComponent`를 거쳐 `CharacterMovement`로 실행한다. 행동은 이동 방향·속도·지속시간만 공통 이동 통로에 요청하며, 별도의 위치 변경 방식을 만들지 않는다. `SetActorLocation`, 블루프린트 Timeline, 등록되지 않은 이동 타이머로 Actor 위치를 계속 직접 바꾸는 방식은 사용하지 않는다.

이동 잠금의 초기 구현은 `CharacterMovement`를 `MOVE_None`으로 전환하는 방식이다. 이후 특정 이동 행동과 충돌하는 문제가 확인되면, 같은 공통 이동 통로 안에서 속박 대상의 최종 이동 속도를 `0`으로 만드는 방식으로 교체할 수 있다. 어느 경우에도 적 개발자는 개별 CC 예외 처리를 만들지 않는다.

### 통합 지속 피해 처리기

지속 피해는 효과마다 블루프린트 타이머를 생성하지 않는다. 월드 전투 시스템의 단일 `DamageOverTimeScheduler`가 모든 활성 지속 피해 인스턴스 목록을 관리하고, 갱신 시점에 도래한 인스턴스만 처리한다.

각 `DamageOverTimeInstance`는 대상·시전자, 원본 피해 요청, 출처 분류·이름, 시작·종료 시각, 틱 간격, 다음 틱 예정 시각, 지속 피해 이름 및 중첩 방식을 독립적으로 가진다. 기본 틱 간격은 `0.25초`지만, 인스턴스별 설정값이므로 화상 0.25초, 독 1초, 특수 효과 0.1초처럼 서로 다른 간격을 동시에 지원한다.

지속 피해 인스턴스는 최종 피해량을 저장하거나 스탯 변경 이벤트를 직접 구독하지 않는다. 틱 시점에 통합 처리기가 원본 `DamageRequest`를 실행하며, 피해 계산기는 시전자와 대상의 `StatsComponent`에 캐시된 **현재 최종 스탯**을 읽는다. 따라서 지속 피해가 적용된 뒤 공격력·피해 증폭·방어력 등의 수정치가 바뀌면, 다음 틱부터 변경된 수치가 자동 반영된다. 스탯 변경 시 비용은 해당 스탯 캐시의 재계산 한 번이며, 모든 지속 피해 인스턴스를 순회하거나 갱신하지 않는다.

`Apply Damage Over Time`은 중첩 방식을 명시적으로 받는다. `독립 중첩`이면 같은 이름의 지속 피해도 각각 별도 인스턴스로 남아 각자의 틱·지속시간·피해를 처리한다. `같은 이름 지속시간 갱신`이면 같은 이름의 기존 인스턴스를 하나만 유지하고, 새 인스턴스를 만들지 않은 채 기존 인스턴스의 종료 시각을 새 효과의 기본 지속시간만큼 초기화한다. 기존 피해 요청과 시전자는 유지하며, 피해를 비교·교체하지 않는다. 이 방식은 화상처럼 비중첩 DOT로 동작하게 하려는 효과가 선택한다.

`같은 이름 지속시간 갱신` 방식은 같은 이름이 같은 DOT 정의를 뜻한다는 전제를 가진다. 새 요청의 틱당 기본 피해, 총 지속시간 또는 틱 간격이 기존 인스턴스와 다르면 C++는 기존 인스턴스를 그대로 유지하고 개발 로그에 대상·지속 피해 이름·서로 다른 값을 경고한다. 서로 다른 수치의 DOT를 의도했다면 반드시 별도의 지속 피해 이름을 사용한다. 초기에는 독립 중첩의 상한을 강제하지 않되, 통합 처리기는 활성 인스턴스 수가 설정 가능한 경고 임계값을 넘으면 개발 로그에 출처·대상·개수를 출력한다.

프레임이 크게 끊겨 하나 이상의 틱 시점이 지나간 경우, 통합 처리기는 지난 틱을 버리지 않는다. 현재 전투 시간이 지난 `NextTickTime`마다 피해를 모두 순서대로 처리한 뒤 다음 틱 시각을 갱신한다. 따라서 프레임 저하로 총 지속 피해량이 줄어들지 않는다. 다만 긴 멈춤 뒤에는 밀린 피해가 한 프레임에 몰릴 수 있으므로, 경고 임계값 초과 시 개발 로그에 기록한다.

전체 게임이 정식으로 일시정지된 경우의 지속 피해 틱·종료 시각 처리 여부는 이후 게임 일시정지 규칙을 따른다.

시전자가 사망하거나 월드에서 제거되어 더 이상 참조할 수 없게 되더라도, 이미 등록된 지속 피해는 사라지지 않는다. 처리기는 해당 시점의 시전자 최종 공격 관련 스탯을 스냅샷으로 보관하고, 남은 지속 피해는 그 스냅샷을 사용해 종료 시점까지 계산한다. 시전자가 유효한 동안에는 계속 현재 최종 스탯을 읽는다.

### 일반 경직: 즉시 판정 방식

일반 경직은 누적 게이지를 쓰지 않는다. 공격이 가진 **경직 피해**와 대상의 **경직 저항력**을 한 번에 비교해, 기준을 넘는 공격만 짧은 행동 불가를 발생시킨다. 강인함은 상태이상 지속시간 감소에만 사용하며, 경직 판정에는 사용하지 않는다.

```text
최종 경직 피해
= Floor(공격 기본 경직 피해
× (1 + 공격자 경직력 ÷ 100)
× 공격별 경직 배율)

최종 경직 피해 > 대상 경직 저항력
→ 일반 경직 성공
```

일반 경직이 성공하면 C++ `StaggerComponent`가 아래 순서로 처리한다.

```text
1. 현재 이동 즉시 중단
2. ActionComponent에 현재 행동 취소 요청 (취소 사유: Stagger)
3. Staggered 행동 제한 부여
4. 경직 종료 뒤 짧은 경직 면역 부여
```

제한 중에는 이동·공격·무기 스킬·액티브 유물을 사용할 수 없다. 경직은 기본적으로 넉백을 포함하지 않는다. 넉백은 필요해질 때 공격별 별도 효과로만 추가한다.

각 플레이어·적 블루프린트의 `StaggerComponent` Details 패널에는 상태 소유 값만 설정한다.

- `경직 가능`
- `기본 경직 시간`
- `경직 후 면역 시간`

`경직 저항력`은 `StatsComponent`가 소유하는 최종 스탯이며 `StaggerComponent`가 읽는다. 같은 값을 두 Component의 Details에 중복 보관하지 않는다.

### 슈퍼아머: 기술 중의 임시 상태

슈퍼아머는 영구 스탯이 아니라, 특정 기술·공격 동작·버프 중에만 활성화되는 임시 상태다. 여러 출처가 동시에 부여할 수 있으므로 단일 Boolean으로 직접 설정하지 않고, 출처별 활성 목록으로 관리한다.

```text
기술 시작 → Super Armor 출처 추가
기술 진행 → 일반 경직 판정 무시
기술 종료 → 해당 Super Armor 출처 제거
```

- 슈퍼아머는 기본적으로 **일반 경직만** 막는다.
- 피해, 화상·감전 같은 상태이상, 그로기 게이지 감소는 기본적으로 정상 적용된다.
- 기절 같은 강한 CC를 막을지 여부는 별도 상태 규칙으로 둔다.
- 활성 출처가 하나라도 있으면 슈퍼아머가 활성 상태다. 하나의 출처가 끝나도 다른 출처가 남아 있으면 비활성화하지 않는다.
- 블루프린트는 `Apply Super Armor`와 `Remove Super Armor` 노드로 출처·지속시간을 관리한다.

### 선택형 그로기 게이지

그로기 게이지는 보스와 필요한 특수 잡몹에만 선택적으로 활성화한다. 일반 경직과 독립적이며, 기본 잡몹은 꺼둘 수 있다.

```text
유효한 그로기 피해 발생
→ 그로기 게이지 감소
→ 일정 시간 추가 피해가 없으면 빠르게 회복
→ 게이지 0 도달
→ C++가 OnGroggyGaugeDepleted 이벤트만 발송
→ 대상 블루프린트가 전용 그로기 연출·기믹을 실행
```

```text
최종 그로기 피해
= Floor(공격 기본 그로기 피해
× (1 + 공격자 경직력 ÷ 100)
× (1 + 공격자 그로기 피해 증폭 ÷ 100))
```

그로기 피해는 체력 피해처럼 대상의 현재 그로기 수치를 감소시키지만, 체력 피해와는 독립적으로 계산한다. 경직력에서 시작하고 그로기 피해 증폭을 추가로 적용한다. 치명타, 물리·화염·마법 방어력, 일반 피해 증폭은 그로기 피해에 적용하지 않는다. 공격별 기본 그로기 피해가 `0`이면 그로기 피해를 주지 않는다. 지속 피해의 틱도 그로기 피해를 주도록 설정된 경우, 매 틱이 마지막 그로기 피해 시점을 갱신한다.

`StaggerComponent` Details 패널의 그로기 상태 설정은 아래와 같다.

- `그로기 게이지 사용`

`최대 그로기 수치`, `그로기 게이지 회복 대기시간`, `초당 그로기 게이지 회복량`은 `StatsComponent`가 소유한다. `StaggerComponent`는 현재 그로기와 마지막 피해 시각, 고갈 잠금 상태만 소유하고 최종 스탯 변경 이벤트를 구독한다.

```text
마지막 그로기 피해 후 회복 대기시간 경과
→ 현재 그로기 수치
= Min(최대 그로기 수치,
       현재 그로기 수치 + 초당 그로기 회복량 × DeltaTime)
```

게이지가 `0`이 되면 C++는 자동 기절, 자동 피해 증폭, 자동 게이지 초기화를 하지 않는다. 대신 `OnGroggyGaugeDepleted` 이벤트를 한 번 보내고 게이지를 잠근다. 보스 블루프린트는 이 이벤트를 받아 고유 그로기 패턴을 실행하고, 원하는 시점에 `Reset Groggy Gauge`로 게이지를 다시 열고 초기화한다. HUD는 필요할 경우에만 `OnGroggyGaugeChanged` 이벤트를 구독해 게이지를 표시한다.

## 7. 무기 시스템

### 공통 규칙

- 플레이어는 한 번에 무기 하나만 장착한다.
- 새 무기를 얻어 교체하면 기존 무기는 버려진다.
- 무기는 기본 공격, 무기 스킬, 스탯 배율, 진화 데이터를 가진다. 실제 공격 타이밍·히트박스·투사체·연출은 장착된 런타임 무기 블루프린트가 구현하고, 피해·자원·행동·경직의 판정과 계산은 공통 C++ 노드를 호출한다.
- 무기 스킬은 진행 중 추가되거나 강화·진화될 수 있다.
- 무기는 시스템상 `LoadoutItem`의 한 종류다. 무기라는 특수성은 무기 1개 장착 제한, 무기 HUD, 진화 규칙에서만 적용한다.

### 무기 데이터 에셋과 런타임 객체

무기 정의는 `UARLoadoutItemDefinition`을 상속한 `UARWeaponDefinition` 데이터 에셋이다. 공통 데이터 에셋 항목과 무기 전용 항목은 아래와 같다.

| 구분 | 항목 | 규칙 |
|---|---|---|
| 공통 식별 | `DefinitionTag` | 게임 규칙과 조회에 사용하는 안정적인 고유 Gameplay Tag. 예: `Item.Weapon.Sword.Basic` |
| 에셋 식별 | `PrimaryAssetId` | Asset Manager가 Definition을 로드하는 정식 에셋 ID. 저장·비동기 로딩에서 사용하며 표시 이름으로 대체하지 않음 |
| 공통 분류 | `ItemTags` | `Weapon.Melee`, `Weapon.Sword`, `Element.Fire` 같은 세부 분류. 무기/액티브/패시브의 큰 분류는 데이터 에셋 클래스가 확정한다. |
| 공통 UI | `DisplayName`, `ShortDescription`, `UIIcon` | 모두 UI용 정적 정보. 텍스트는 `FText`를 사용한다. |
| 공통 설명 | `DescriptionSections[]` | 일반, 패시브, 특이사항 등 제목·본문(`FText`)을 가진 문단 목록. 제공 스탯과 스킬 설명은 중복 작성하지 않고 자동 생성한다. |
| 공통 고정 효과 | `DefaultStatModifiers[]` | 장착 중 자동 적용되는 고정 스탯 수정치. UI의 `제공 스탯` 항목도 이 목록에서 자동 생성한다. |
| 공통 스킬 | `SkillDefinitions[]` | 기본 제공 스킬 목록. 배열 길이가 기본 스킬 수이며 별도 스킬 수 필드는 두지 않는다. |
| 공통 런타임 | `RuntimeBehaviorClass` | `UARLoadoutItemInstance`를 상속한 실제 행동 Blueprint 클래스. |
| 무기 진화 | `EvolutionGroupId` | 같은 진화 계열을 묶는 식별자. |
| 무기 진화 | `EvolutionTier` | 무기의 현재 진화 단계. 프로토타입 검은 1~3단계다. |
| 무기 진화 | `EvolutionOptions[]` | 다음 단계 `UARWeaponDefinition` 참조 목록. 0개면 진화 종료, 1개면 즉시 진화, 2개 이상이면 선택 UI를 연다. 모든 선택지는 동일 진화 그룹인지 검증한다. |

무기의 월드 스프라이트·플립북, 휘두르기 애니메이션, 실제 히트박스와 투사체 생성은 데이터 에셋이 아닌 `RuntimeBehaviorClass`의 BP에 둔다. 데이터 에셋은 무엇을 보여 주고 어떤 정적 규칙을 갖는지, 런타임 BP는 장착 중 어떻게 동작하는지를 담당한다.

### 프로토타입 무기

| 무기 | 역할 | 초기 우선순위 |
|---|---|---|
| 마법 지팡이 | 원거리 투사체, 사거리·탄속·공격 속도 조합 | 기본 공격과 1개 스킬 |
| 검 | 근거리, 강한 피해와 경직 | 기본 공격, 1개 스킬, 3단 진화 |

### 검 3단 진화

1. 기본 검: 근거리 공격과 경직
2. 강화 검: 공격 범위 또는 연계 강화
3. 완성 검: 체감 가능한 고유 효과 추가

검의 진화는 기존 런타임 무기 객체를 해제하고, 선택한 다음 단계 정의로 새 런타임 무기 객체를 생성·등록하는 교체 방식이다. 따라서 기존 무기의 쿨다운, 임시 스택, 조건부 효과는 기본적으로 사라지며 새 무기는 새 상태로 시작한다. 특정 진화에서만 상태 계승이 필요해질 때 별도 계승 규칙을 추가한다.

`Request Weapon Evolution`은 현재 장착 무기의 `EvolutionOptions[]`만 읽는다. 장착 무기가 없으면 `NoEquippedWeapon`, 선택지가 없으면 `NoEvolutionAvailable`, 한 개면 즉시 교체 등록 후 `EvolvedImmediately`, 둘 이상이면 `NeedEvolutionChoice`와 진화 요청 핸들을 반환한다. 선택 UI는 `Get Weapon Evolution Options`로 후보의 표시 정보를 얻고, `Commit Weapon Evolution`에 선택한 `PrimaryAssetId`를 전달한다. 취소는 `Cancel Weapon Evolution`으로 처리한다.

## 8. 유물 시스템

### 패시브 유물

- `UARLoadoutItemDefinition`을 상속한 `UARPassiveRelicDefinition` 데이터 에셋을 사용한다. 초기 단계에는 공통 필드 외의 필수 전용 필드를 추가하지 않는다.
- 개수 제한 없이 누적한다.
- 획득 즉시 고정 스탯 또는 규칙을 보정한다.
- 예시: 탄환 관통, 경직력 증가, 구르기 후 강화 공격, 처치 시 회복
- `SkillDefinitions[]`는 보통 비어 있다. 조건부 패시브는 런타임 BP가 피격·적중·보호막·체력 등의 공통 이벤트를 구독해 구현한다.
- 동일 패시브 유물도 시스템상 각자 `InstanceId`를 가진 독립 인스턴스로 중첩 가능하다. 초기 드롭 규칙은 동일 유물을 중복 등장시키지 않는다.

### 액티브 유물

- `UARLoadoutItemDefinition`을 상속한 `UARActiveRelicDefinition` 데이터 에셋을 사용한다. 초기 단계에는 공통 필드 외의 필수 전용 필드를 추가하지 않는다.
- 최대 2개를 장착한다.
- 직접 키를 눌러 사용한다.
- 재사용 대기시간 또는 충전 규칙을 지원한다.
- 예시: 긴급 회복, 보호막, 광역 폭발
- 스킬 수가 적더라도 `SkillDefinitions[]`를 공유하며, MP·스태미나 비용과 쿨다운 및 UI 정보는 각 스킬 정의에 기록한다. 최대 2개라는 제한은 데이터 에셋이 아니라 Player의 `UARLoadoutComponent`가 관리한다.

패시브와 액티브의 차이는 데이터 에셋 클래스, 장착 제한, 스킬 등록 여부, HUD 표시 위치로 구분한다. 충전 횟수·특수 소모품 같은 액티브 유물 전용 정적 규칙이 실제로 필요해질 때만 전용 필드를 추가한다.

### 확장 원칙

새 유물은 기반 클래스를 상속하거나 정해진 이벤트를 구독해 추가한다. 개별 유물이 플레이어·무기·시간을 직접 강하게 참조하지 않도록 공통 컴포넌트와 이벤트를 통해 상호작용한다.

### 공통 런타임 장착 객체

무기, 액티브 유물, 패시브 유물은 내부적으로 공통 `UARLoadoutItemInstance`(Blueprintable `UObject`)를 사용한다. 이 객체는 월드에 배치되는 Actor가 아니라 플레이어가 소유하는 장착 중 인스턴스다. 타입만 `Weapon` / `ActiveRelic` / `PassiveRelic`으로 구분한다.

런타임 객체는 소유 Player 참조, 원본 Definition 참조, 고유 `InstanceId`, 적용한 스탯 수정치 핸들, 등록한 스킬 핸들, 이벤트 구독 핸들, 쿨다운·스택·전용 UI 상태 등 개인 상태를 가진다. C++ 내부 초기화만 이 값을 주입하며, 콘텐츠 BP는 임의의 Player나 Definition을 넣어 초기화할 수 없다. `InstanceId`는 `FGuid`, 등록된 스킬은 `FARRegisteredSkillHandle`, 각 효과는 전용 불투명 Handle을 사용한다.

`UARLoadoutComponent`는 `UPROPERTY(Transient)` 배열·슬롯으로 Runtime Instance를 강하게 소유하고 Instance의 Outer가 된다. Instance는 Owner Character를 약하게 참조하고 장착 중인 Definition을 강하게 참조한다. 제거·EndPlay 전에 Delegate 구독을 해제하므로 GC와 파괴 순서에 의존하지 않는다.

등록은 다음 순서로 원자 처리한다.

```text
정의 데이터 수신
→ RuntimeBehaviorClass로 UARLoadoutItemInstance 생성
→ 소유 Player / Definition / InstanceId 초기화
→ DefaultStatModifiers 자동 적용
→ SkillDefinitions를 ActionComponent에 등록
→ On Item Registered 이벤트 호출
→ 런타임 BP의 조건부 이벤트 구독
→ UI 변경 이벤트 발송
```

중간 단계가 실패하면 적용한 고정 스탯, 스킬 등록, 이벤트 구독을 모두 되돌리고 생성 실패로 반환한다. 제거·교체·진화는 실행 중인 해당 아이템 스킬을 종료한 뒤 `On Item Unregistered`를 호출하고, 등록 스킬·이벤트 구독·해당 `InstanceId`의 고정 및 조건부 스탯 수정치를 모두 제거한 후 UI를 갱신한다. 다른 아이템·버프의 수정치는 건드리지 않는다.

각 `SkillDefinition`은 고유 `SkillId`, 입력 태그, **`InputPriority`**, `SkillDisplayName`, `SkillIcon`, `SkillDescription`, MP 비용, 스태미나 비용, 기본 쿨다운, 초기 행동 취소 규칙(`Cancel On Stagger`/`Stun`/`Roll`/`Basic Movement Input`), HUD 표시 여부, HUD 정렬 순서, 행동 실행 정보를 가진다. 배열의 각 항목이 UI에 표시되는 독립 스킬이다. `InputPriority`는 같은 입력 태그의 실행 검사 순서를 결정하며 작은 값이 먼저다. 같은 입력 태그·같은 우선순위의 스킬은 하나의 원자적 실행 그룹으로 취급한다.

일반 스킬의 비용과 쿨다운은 `ActionComponent`가 `Execute Item Skill` 전 원자적으로 검사·소비·시작한다. MP 또는 스태미나 중 하나라도 부족하면 아무 자원도 소비하지 않고 스킬을 시작하지 않는다. 쿨다운 감소율은 스킬 발동 시점의 최종값으로 실제 쿨다운 길이를 확정하며, 진행 중인 쿨다운은 이후 쿨다운 감소율 변화로 재계산하지 않는다. 피해 사양은 기존 `DamageRequest`의 직접·지속 전달 방식, 속성, 기본 피해, 공격력·주문력 계수 등을 재사용한다. 실제 타이밍·히트박스·투사체·연출은 런타임 행동 BP가 구현하고, 피해 계산은 공통 C++ 노드를 호출한다.

런타임 아이템 BP 계약은 아래로 고정한다.

| 노드 또는 이벤트 | 종류 | 입력 | 반환 및 역할 |
|---|---|---|---|
| `On Item Registered` | 이벤트 | 없음 | 반환 없음. 고정 스탯·스킬 등록 이후 호출되며, 조건부 패시브의 공통 이벤트 구독과 초기 상태 준비에 사용한다. |
| `On Item Unregistered` | 이벤트 | 없음 | 반환 없음. 제거 직전에 호출된다. BP가 만든 임시 연출을 정리할 수 있으며, 이후 C++가 등록 기록을 최종 정리한다. |
| `Execute Item Skill` | 이벤트 | `SkillId`, `ActionHandle` | 반환 없음. 공통 행동·비용·쿨다운 검증 후 호출된다. BP는 여기서 피해·히트박스·투사체 등을 실행하고 완료 시 `End Action`으로 핸들을 종료한다. |
| `Can Execute Item Skill` | 순수 BP 함수 또는 오버라이드 | `SkillId` | 사용 가능 여부와 선택적 실패 사유를 반환. 스택·전용 자원·대상 등 아이템 고유 조건만 검사하며, 스탯·자원·스택 등 상태를 바꾸지 않는다. |
| `Apply Item Stat Modifier` | 실행 노드 | 스탯, 연산 방식, 값, 지속시간, 효과 이름, 보장 옵션 | 수정치 핸들, 성공 여부. 대상은 자동으로 소유 Player이며 출처 분류와 InstanceId도 자동 기록한다. |
| `Remove Own Item Modifiers` | 실행 노드 | 범위(전체/효과 이름/핸들), 이름 또는 핸들 | 제거 수, 성공 여부. 현재 Item Instance가 적용한 수정치만 제거한다. |
| `Get Item Owner` | 순수 조회 | 없음 | 소유 `AARPlayerCharacter`, 유효 여부. |
| `Get Item Definition` | 순수 조회 | 없음 | 원본 `UARLoadoutItemDefinition`, 유효 여부. |

초기 Foundation은 런타임 BP의 `Register Item Skill`·`Unregister Item Skill`을 제공하지 않는다. 예상 가능한 모든 스킬은 Definition의 `SkillDefinitions[]`에 미리 등록한다. 조건부로 사용할 수 없는 스킬은 등록을 제거하지 않고 `Can Execute Item Skill`에서 판정한다. 이 함수가 `false`를 반환하면 해당 우선순위 그룹은 기존 스킬·자원·쿨다운 규칙에 따라 실행하지 않는다. 완전히 새 스킬을 런타임 중 추가하는 기능은 실제 콘텐츠가 필요해질 때 별도 확장으로 설계한다.

### 아이템 전용 UI 상태 통로

스택·충전량·유물 전용 자원은 실제 규칙을 런타임 BP가 관리하고, 데이터 에셋은 어떤 형식으로 표시할지만 정의한다. 모든 LoadoutItem Definition은 선택적으로 `UIStateDisplayDefinitions[]`를 가진다.

| `UIStateDisplayDefinition` 항목 | 역할 |
|---|---|
| `StateId` | UI 상태를 식별하는 Gameplay Tag. 런타임 BP는 등록된 ID만 갱신할 수 있다. 없는 ID 요청은 무시하고 개발 로그 경고를 남긴다. |
| 표시 이름·아이콘 | HUD 및 상세 UI의 정적 표기 |
| `DisplayType` | `Gauge` / `Number` / `SmallStack` |
| `MaxDisplaySlots` | `SmallStack`일 때 1~6. 7 이상이거나 실제 최대값이 7 이상이면 숫자 표시로 전환하고 경고한다. |
| `bShowNumberAlongside` | 게이지·소형 스택에 숫자 병행 표시 여부 |
| `DisplayTarget` | `HUDOnly` / `DetailOnly` / `HUDAndDetail` |
| `UIOrder` 및 기본 표시 여부 | 같은 아이템 내 배치 순서와 초기 표시 여부 |

런타임 BP는 `Set Item UI State(StateId, CurrentValue, MaxValue, bVisible)`로 실제 값을 갱신하며 `On Item UI State Changed`가 발생한다. 데이터 에셋에는 현재값을 저장하지 않는다. 아이템 제거 시 해당 Instance의 UI 상태도 함께 제거한다.

HUD 위젯은 아이템 종류별로 서로 다르다. 무기의 상태는 무기 스킬 HUD·무기 패널, 액티브 유물의 상태는 장착된 액티브 유물 1·2번 슬롯 내부, 패시브 유물의 상태는 기본적으로 인벤토리 상세 패널과 필요 시 별도 패시브 상태 HUD에 표시한다. 어느 액티브 슬롯에 표시되는지는 데이터 에셋이 아니라 `UARLoadoutComponent`의 실제 장착 슬롯이 결정한다. 데이터 에셋은 개별 위젯 클래스를 직접 지정하지 않고, UI Manager가 `DisplayType`과 아이템 분류에 맞는 공통 위젯을 생성한다.

### 획득 요청과 월드 픽업 객체

무기·유물 콘텐츠의 실제 효과는 런타임 객체에만 있고, 월드에 놓이는 `BP_LoadoutItemPickup`은 Definition을 획득 요청으로 전달하는 얇은 Actor다. 이 Actor는 `IARInteractable`을 구현하며 플레이어가 `F` 상호작용을 해야 요청을 보낸다. 자체적으로 스탯을 적용하거나 스킬을 실행하지 않는다. 무기·액티브·패시브의 시각 연출이 다르면 이 공통 Actor의 자식 BP만 추가한다.

월드 픽업·상점·보상 선택·이벤트·제단은 모두 동일한 획득 API를 사용한다. 월드에 떨어진 `BP_LoadoutItemPickup`은 그중 `WorldPickup` 출처일 뿐이며, 아이템 획득 자체가 월드 Actor를 반드시 요구하지는 않는다.

| 노드 | 입력 | 반환 및 역할 |
|---|---|---|
| `Begin Loadout Acquisition` | Player, Item Definition, 획득 출처 정보 | 아직 아이템을 지급하지 않고 장착 가능 여부를 검사한다. 획득 요청 핸들과 결과를 반환한다. |
| `Commit Loadout Acquisition` | 획득 요청 핸들 | 다시 검증한 뒤 새 런타임 Item을 등록한다. 무기는 기존 무기를 해제·소멸한 뒤 즉시 교체하고, 액티브 유물은 비어 있는 가장 앞 슬롯에, 패시브 유물은 목록 끝에 등록한다. 성공한 경우에만 출처가 픽업 제거·상점 판매 완료·보상 소비를 처리한다. |
| `Cancel Loadout Acquisition` | 획득 요청 핸들 | 아직 Commit하지 않은 획득 요청을 변경 없이 폐기한다. |

`Begin Loadout Acquisition` 결과는 `ReadyToAcquire`, `ActiveRelicSlotsFull`, `Rejected`다. 패시브 유물은 항상 제한 없이 `ReadyToAcquire`다. 액티브 유물이 2칸 모두 차 있으면 `ActiveRelicSlotsFull`을 반환하며, F 상호작용·상점 구매·보상 수령 모두 획득하지 못하고 출처도 그대로 유지한다. 교체 선택 UI는 사용하지 않는다. 새 무기는 항상 기존 무기를 해제·소멸하고 즉시 장착하므로 `ReadyToAcquire`로 처리한다. `BP_LoadoutItemPickup`은 Commit 성공 후에만 자신을 제거한다. 상점은 가격·재고를 먼저 검증하고 Commit 성공 시에만 결제·재고 변경을 확정한다.

## 9. UI 최소 범위

초기 HUD는 플레이에 필요한 정보만 표시한다.

- 체력과 보호막
- MP와 스태미나
- 현재 장착 무기와 무기가 제공한 스킬 아이콘·입력·재사용 대기시간
- 장착 액티브 유물 2칸과 각 유물의 아이콘·재사용 대기시간·전용 스택 또는 상태 UI
- 아이템이 제공하는 별도 스택·게이지·숫자 상태 UI
- 주요 상태이상 아이콘과 남은 시간
- 마우스가 가리키는 월드 위치의 에임 표시

에임 표시는 일반 HUD 위젯이 아니라 Player C++가 마우스 위치를 월드 평면에 투영해 갱신하는 `Aim Indicator` Actor 또는 Component로 구현한다. 이후 사거리 원·설치 위치·공격 범위 미리보기에도 같은 위치 정보를 재사용한다. UI 위젯의 레이아웃과 시각 디자인은 블루프린트/UMG에서 만들고, C++ 시스템은 값 변경 이벤트만 제공한다.

### 인벤토리·장착 정보 UI

인벤토리는 별도의 보관 가방이 아니라 플레이어가 현재 장착·보유한 LoadoutItem을 조회하고, 필요할 때 유물을 폐기하는 UI다. `IA_Inventory` 입력으로 열며 초기 키는 `I`다.

```text
기본 인벤토리
├─ 좌측: 캐릭터의 현재 최종 스탯
└─ 우측
   ├─ 무기 슬롯: 1개
   ├─ 액티브 유물 슬롯: 최대 2개
   └─ 패시브 유물 목록: 제한 없음

아이템 마우스 오버
└─ 이름·짧은 설명의 간단 툴팁

아이템 선택
├─ 좌측: 선택한 무기·유물의 이미지와 제공 스탯
└─ 우측: 상세 설명, 패시브·특이사항, 스킬 설명,
          현재 스택·충전량 등 Item UI State,
          실제 적용 중인 수정치 목록
```

무기는 인벤토리에서 우클릭 폐기할 수 없다. 새 무기를 획득할 때만 기존 무기를 즉시 교체·소멸한다. 액티브·패시브 유물은 우클릭으로 확인 메뉴를 열어 폐기를 선택할 수 있다. 확인되면 Player Component가 런타임 인스턴스를 해제하고, 그 Definition을 가진 `BP_LoadoutItemPickup`을 플레이어 근처의 유효한 맵 위치에 생성한다. 이후 다시 획득하면 언제나 새 런타임 인스턴스가 생성되므로 쿨다운·스택·임시 상태는 초기화된다. 실제 장착·폐기 검증과 픽업 생성은 UI가 아니라 Player Component와 월드 획득 시스템이 처리한다.

LoadoutItem은 UI에 `LoadoutItemDisplayData`를 제공한다. 이미지·이름·짧은 설명·상세 문단·스킬 설명은 정의 데이터에서 읽고, `제공 스탯`은 DefaultStatModifiers를 사람이 읽을 수 있는 `스탯 이름 / 고정·합연산·곱연산 방식 / 수치` 목록으로 자동 변환해 출력한다. 런타임 인스턴스가 실제 적용 중인 수정치는 별도 목록으로 제공하며, 조건부·고유 효과는 DescriptionSections의 설명문으로 표시한다.

### UI 열림 상태와 입력 규칙

인벤토리·상점·진화 선택처럼 화면을 점유하는 UI는 한 번에 하나만 연다. UI가 열린다고 월드 시간, 적 AI, 투사체, 지속 피해는 멈추지 않는다. 단, Player Controller는 커서를 UI에 넘기고 해당 플레이어의 모든 게임플레이 입력을 차단한다. 즉 WASD 기본 이동, 구르기, 공격, 스킬, 포션, F 상호작용은 UI를 닫기 전까지 실행되지 않는다.

`Esc`는 현재 UI 상태에서 한 단계 이전으로 돌아간다. 예를 들어 아이템 상세 선택 상태에서는 선택을 해제해 기본 인벤토리로 돌아가고, 기본 인벤토리에서는 인벤토리를 닫는다. 진화 선택 같은 취소 가능한 이벤트 UI는 해당 요청을 취소하고 이전 게임플레이 상태로 돌아간다. 검 진화 후보 선택은 인벤토리가 아니라 독립된 전용 진화 이벤트 UI가 담당한다.

### 소모품 슬롯과 사용

포션을 포함한 소모품은 무기·유물과 같은 데이터 에셋 + 런타임 Blueprint 객체 패턴을 사용하지만, 장착 아이템이 아닌 별도 소모품 시스템으로 관리한다. `UARConsumableDefinition`은 식별 코드, 표시 이름, 짧은·상세 설명, UI 아이콘, `RuntimeBehaviorClass`를 가지며, `UARConsumableInstance`는 슬롯 하나에 든 실제 독립 소모품이다. 동일 Definition도 서로 다른 슬롯에 독립적으로 보관할 수 있다.

- `UARConsumableComponent`는 Player의 현재 슬롯과 최종 `최대 소모품 슬롯 수`를 관리한다. 초기 슬롯 수는 3이며, 이 최대치는 Details 값 및 추후 수정치로 증가하거나 감소할 수 있다.
- 한 슬롯에는 소모품 인스턴스 하나만 보관한다. 여러 개를 수량으로 합치거나 스택으로 표현하지 않는다.
- 소모품 사용은 즉발이며 쿨다운이 없다. `Try Use Consumable Slot(Player, SlotIndex)`은 유효하고 비어 있지 않은 슬롯만 사용한다. 런타임 BP의 사용 효과를 실행한 뒤 해당 인스턴스를 즉시 슬롯에서 제거한다. 이 사용은 Action을 시작·점유·취소하지 않는다.
- 기본 1~3번 슬롯은 숫자키 `1`·`2`·`3`으로 사용하며, 슬롯이 늘면 4번 슬롯은 `4`, 5번 슬롯은 `5`처럼 같은 번호의 IMC 입력으로 이어진다. 인벤토리에서는 같은 요청을 아이템 우클릭 `사용` 메뉴로 보낸다.
- 소모품 획득은 월드 `BP_ConsumablePickup`, 상점, 보상, 이벤트 등 어느 출처에서도 `Try Acquire Consumable` 공통 요청을 사용한다. 비어 있는 유효 슬롯이 없으면 획득은 거부되고 출처는 유지한다.
- 최대 슬롯 수가 감소할 때 새 최대치를 넘는 슬롯에 소모품이 있다면, 높은 슬롯 번호부터 각 인스턴스를 해제하고 같은 Definition의 `BP_ConsumablePickup`을 플레이어 근처의 유효한 맵 위치에 생성한다. 빈 초과 슬롯은 제거한다. 드롭된 소모품을 다시 획득하면 새 인스턴스가 생성된다.

| 블루프린트 노드 또는 이벤트 | 입력 | 반환·역할 |
|---|---|---|
| `Try Acquire Consumable` | Player, Consumable Definition, 획득 출처 | 첫 번째 빈 유효 슬롯에 새 인스턴스를 등록. 성공 여부·슬롯 번호·실패 사유 반환. |
| `Try Use Consumable Slot` | Player, Slot 번호 | 해당 슬롯 사용 후 즉시 제거. 성공 여부·실제 사용한 Definition·실패 사유 반환. |
| `Get Consumable Slots` | Player | 현재 최대 슬롯 수와 각 슬롯의 점유·표시 정보를 UI에 반환. |
| `On Consumable Slots Changed` | 슬롯 변경 정보 | 획득·사용·슬롯 수 증감에 따른 HUD·인벤토리 갱신 이벤트. |
| `Execute Consumable Use` | 이벤트, 소유 Player | `UARConsumableInstance` 런타임 BP가 사용 효과를 구현하는 표준 이벤트. 기존 회복·보호막·스탯 수정 공통 노드를 호출한다. |

## 13. C++와 블루프린트 역할 분리

### 결정

**C++는 전투 규칙의 권한을 가지며, 블루프린트는 개별 무기·유물의 행동과 연출을 만든다.**

이 방식은 새 콘텐츠를 빠르게 만들 수 있으면서도, 피해 계산·상태이상·UI가 무기마다 제각각 구현되는 문제를 막는다.

| C++가 책임질 것 | 블루프린트가 책임질 것 |
|---|---|
| 피해 가능 여부와 최종 피해 계산 | 검 베기 범위, 투사체 생성, 적 탐색 방식 |
| 체력·스태미나·MP·스탯 변화와 스킬 비용·쿨다운 판정 | 공격 순서, 차지, 연계, 재사용 대기시간 연출 |
| 경직과 상태이상 적용·중첩·해제 | 상태이상 VFX, 사운드, 피격 애니메이션 |
| 무기 교체·유물 슬롯·보유 규칙 | 개별 무기와 유물의 고유 행동 |
| UI에 전달하는 변경 이벤트 | UMG 위젯의 위치, 모양, 애니메이션 |

### 핵심 원칙

1. 블루프린트는 체력·스태미나·상태이상 목록을 직접 수정하지 않는다.
2. 블루프린트는 C++가 제공하는 요청 노드를 호출하고, 성공 여부와 결과를 받아 연출한다.
3. C++는 모든 무기와 유물이 공통으로 쓸 수 있는 규칙만 가진다. 검 전용 베기 모양이나 지팡이 전용 투사체 패턴은 넣지 않는다.
4. UI는 매 프레임 값을 조회하지 않고 C++ 컴포넌트가 보내는 변경 이벤트를 구독한다.
5. C++ 함수 라이브러리는 편의 노드만 제공한다. 실제 상태와 규칙은 Character 또는 각 Component가 소유한다.

## 14. 블루프린트에 제공할 C++ 노드 계약

각 노드는 블루프린트에서 사용할 수 있게 노출하되, 입력값 검증과 최종 규칙은 C++에서 처리한다.

### 14.1 스텟 수정치

모든 런타임 스텟 보정은 `UARStatsComponent`가 소유한다. 수정치의 출처 분류는 아래 네 종류로 고정한다.

```text
무기 / 유물 / 버프 / 기타
```

수정치의 안정적인 식별에는 `SourceId`를 사용하고 `DisplayName`은 UI·로그에만 사용한다. 표시 이름을 변경해도 제거와 저장 규칙이 깨지지 않아야 한다. 같은 출처 분류와 `SourceId`를 가진 **버프**는 중첩 가능하며, 각 중첩은 독립된 Handle·수치·지속시간을 가진다.

| 블루프린트 노드 | 입력 | 용도 및 반환값 |
|---|---|---|
| `Apply Stat Modifier` | 대상 캐릭터, 스텟, 계산 방식(고정 수치/합연산 %/곱연산 %), 수치, 지속시간, 출처 분류, `SourceId`, `DisplayName`, `무적 보장` 또는 `회피 보장` 선택값 | `ModifierHandle`과 성공 여부 반환. 지속시간 `-1`은 직접 제거할 때까지 유지 |
| `Remove Stat Modifier` | 대상 캐릭터, `ModifierHandle` | 정확한 수정치 하나 제거 |
| `Remove Stat Modifiers` | 대상 캐릭터, 제거 범위(모두/무기/유물/버프/기타), 선택 `SourceId` | 범위와 ID에 맞는 수정치를 모두 제거. ID가 비어 있으면 해당 범위 전체 제거 |
| `Get Final Stat` | 대상 캐릭터, 스텟 | 모든 수정치가 반영된 현재 최종 수치 반환 |
| `Get Stat Modifier Remaining Time` | 대상 캐릭터, `ModifierHandle` 또는 출처 분류·`SourceId` | Handle이면 정확한 남은 시간, 출처 조회면 가장 긴 남은 시간과 현재 중첩 수 반환. 무제한 지속 효과는 `-1` |
| `Has Stat Modifier By Source` | 대상 캐릭터, 출처 분류, `SourceId` | 적용 여부와 현재 중첩 수 반환 |
| `Remove One Stat Modifier Stack` | 대상 캐릭터, 출처 분류, `SourceId`, 제거 기준(최근 적용/가장 오래된 것) | 같은 ID로 중첩된 수정치 중 하나만 제거 |

```text
제거 범위: 유물, SourceId: Item.Relic.FireRing
→ 화염의 반지가 준 모든 스텟 수정치 제거

제거 범위: 버프, 출처 이름: 비움
→ 현재 버프성 스텟 수정치 전체 제거

제거 범위: 모두, 출처 이름: 비움
→ 모든 런타임 수정치 제거. Details 기본 스텟은 유지
```

| C++ 이벤트 | 전달값 | 용도 |
|---|---|---|
| `On Final Stat Changed` | 스텟 종류, 이전 최종값, 새 최종값 | UI·연출·무기 상태 갱신 |
| `On Stat Modifiers Changed` | 출처 분류, `SourceId`, `DisplayName`, 변경 종류(추가/제거/만료), 중첩 수, 가장 긴 남은 시간 | 버프 아이콘, 중첩 수, 남은 시간 갱신 |

`On Final Stat Changed`만으로는 최종 스텟이 상한에 막힌 경우 수정치 아이콘을 갱신할 수 없으므로, `On Stat Modifiers Changed`를 별도로 제공한다. 모든 수정치의 재계산과 지속시간 만료 처리는 C++가 담당하고, 블루프린트는 스텟 값을 직접 설정하지 않는다.

`무적 보장` 선택값은 `전체 피해 감소율` 수정치를 선택했을 때만 블루프린트 Details에 표시한다. 이를 켜면 수치가 단순히 `+100` 되는 것이 아니라, 같은 SourceId·지속시간을 가진 관리형 무적 항목이 함께 생성된다. 일반 피해 계산기는 하나라도 활성인 관리형 무적 항목이 있으면 전체 남은 피해 배율을 정확히 `0`으로 처리한다. 따라서 기존 감소 페널티나 다른 수정치와 관계없이 무적이 보장된다. 공허 피해는 이 무적을 무시한다. SourceId 또는 Handle로 수정치를 제거하거나 시간이 만료되면 연결된 관리형 무적도 함께 제거된다.

`회피 보장` 선택값은 `회피력` 수정치를 선택했을 때만 블루프린트 Details에 표시한다. 이를 켜면 수치가 단순히 회피력에 더해지는 것이 아니라, 같은 SourceId·지속시간을 가진 관리형 회피 보장 항목이 함께 생성된다. 피해 요청이 필중이 아니고 회피 판정 적용 상태라면, 회피력 상한과 관계없이 회피를 확정한다. 필중 피해는 회피 보장을 무시하며 정상 적중한다. 구르기는 이 방식을 사용한다. SourceId 또는 Handle로 수정치를 제거하거나 시간이 만료되면 연결된 회피 보장도 함께 제거된다.

### 14.1a 자원 소비·회복

체력·스태미나·MP의 현재값은 각각 해당 Component만 변경한다. 블루프린트는 변수에 직접 값을 대입하지 않고 아래 노드를 사용한다. 회복은 사망한 대상에게 적용하지 않으며, 부활은 이후 별도 시스템으로 설계한다.

| 블루프린트 노드 | 입력 | 처리와 반환값 |
|---|---|---|
| `Restore Health` | 대상, 회복 수치, 출처 분류, 출처 이름, 로그용 회복 이름 | 전달받은 회복 수치를 현재 체력에 적용하고 최대 체력으로 제한. 실제 회복량 반환 |
| `Restore Stamina` | 대상, 회복 수치, 출처 분류, 출처 이름, 로그용 회복 이름 | 현재 스태미나에 고정 수치를 더하고 최대 스태미나로 제한. 스태미나 소비 후 회복 대기시간은 변경하지 않음. 실제 회복량 반환 |
| `Restore MP` | 대상, 회복 수치, 출처 분류, 출처 이름, 로그용 회복 이름 | 현재 MP에 고정 수치를 더하고 최대 MP로 제한. 실제 회복량 반환 |

| `Try Consume MP` | 대상, 소비 수치, 출처 분류, 출처 이름 | 충분한 MP일 때만 차감. 성공 여부와 현재 MP 반환 |
| `Can Afford Resource Cost` | 대상, MP·스태미나 비용 목록 | 실제 소비 없이 모든 비용을 낼 수 있는지와 부족한 자원 종류 반환 |
| `Try Consume Resources` | 대상, MP·스태미나 비용 목록, 출처 분류, 출처 이름 | 비용 전체를 원자적으로 소비. 하나라도 부족하면 아무 자원도 소비하지 않으며, 성공 여부·실제 소비량·소비 후 값을 반환 |
| `Get Current Resource` | 대상, 자원 종류(체력/보호막/스태미나/MP/그로기) | 현재값과 최대값 반환. UI·조건부 행동 조회용 |

| C++ 이벤트 | 전달값 | 용도 |
|---|---|---|
| `On Resource Changed` | 대상, 자원 종류, 이전값, 현재값, 최대값, 변화량, 변화 원인(피해/회복/소비/재생/기타), 출처 분류·이름 | HUD, 회복·소비 연출, 조건부 유물 효과 |

세 회복 노드는 자원값을 직접 변경하지 못하게 하는 공통 안전 창구다. 포션·유물·스킬 블루프린트는 고정 수치, 회복력 기반 수치, 최대치 비율 등 자신이 정한 회복량을 계산한 뒤 이 노드를 호출한다. 블루프린트는 현재 체력·스태미나·MP 변수를 직접 대입하지 않는다.

### 14.2 피해와 경직

무기 블루프린트는 타격 대상과 공격 정보를 담은 `DamageRequest`를 만들어 C++에 전달한다. `DamageRequest`에는 최소한 아래 정보가 들어간다.

- 공격자와 피격 대상
- 공격 기본 피해, 공격력 계수, 주문력 계수
- 전달 방식(직접/지속)과 속성(물리/화염/마법/공허)
- 필중, 회피 판정 적용, 치명타 적용, **피해 증감식 적용**, 방어력 무시, 흡수 적용, 보호막 무시, **적중시 효과 적용** 여부
- 출처 분류·이름, 로그용 피해 이름·공격 태그

`피해 증감식 적용`을 끄면 전체·직접/지속·속성별 공격자 피해 증폭과 대상 속성별 피격 피해 증가를 적용하지 않는다. 전체·속성별 피해 감소율은 방어 규칙이므로 이 옵션과 무관하게 적용한다. `방어력 무시`를 켜면 물리·화염·마법 피해 계산에서 공격자의 방어 관통률을 강제로 `100%`로 취급한다. 즉 양수 방어력은 `0`이 된다. 전체·속성별 피해 감소율은 방어력과 별개로 그대로 적용한다. 방어 관통률은 속성별로 나누지 않는 단일 스탯이며, 대상의 해당 속성 방어력이 양수일 때만 작동한다. `보호막 무시`는 공허에 한정하지 않으며 모든 피해 속성에서 선택할 수 있다.

| 블루프린트 노드 | C++ 처리 | 반환 또는 이벤트 |
|---|---|---|
| `Apply Combat Damage` | 명중·회피, 증감식, 속성 방어력, 전체·속성별 피해 감소율, 보호막, 흡수 처리 | 결과 상태(적용/회피/차단/무효), 실제 피해량, 보호막/체력 피해량, 치명타·처치 여부, `DamageHitContext` |
| `Apply Damage Over Time` | 개별 타이머를 만들지 않고 통합 지속 피해 처리기에, 요청한 중첩 방식의 인스턴스를 등록. 공통 피해 공식을 지정한 틱 간격으로 지속시간 동안 반복하며, 첫 틱은 적용 직후가 아니라 틱 간격 뒤에 시작 | `DamageOverTimeHandle`, 지속 피해 인스턴스 정보, 각 틱의 피해 결과 |
| `Remove Damage Over Time` | 핸들 또는 범위·출처 이름·피해 이름에 맞는 지속 피해 인스턴스를 조기 종료 | 제거된 인스턴스 수 |
| `Apply Stagger and Groggy Damage` | 경직력 기반 경직·그로기 피해 계산, 경직 저항력·슈퍼아머·경직 면역 판정, 그로기 게이지 갱신 | 최종 경직/그로기 피해량, 경직 성공 여부, 그로기 게이지 결과 |
| `Apply Super Armor` | 출처와 지속시간을 가진 슈퍼아머 활성 목록에 항목 추가 | 현재 활성 여부 |
| `Remove Super Armor` | 범위·출처 이름에 맞는 슈퍼아머 항목 제거 | 현재 활성 여부 |
| `Is Super Armor Active` | 활성 슈퍼아머 출처 존재 여부 확인 | 현재 활성 여부 |
| `Reset Groggy Gauge` | 그로기 기믹 종료 후 게이지 재설정·잠금 해제 | 현재 게이지 |
| `Apply Shield` | 대상에게 수치·지속시간·출처를 가진 보호막 인스턴스 추가 | `ShieldHandle`, 현재 보호막 총량 |
| `Remove Shield` | 핸들 또는 제거 범위·출처 이름·수명 필터에 맞는 보호막 인스턴스 제거 | 제거 인스턴스 수, 제거 수치, 현재 보호막 총량 |
| `Get Current Shield` | 대상의 모든 활성 보호막 잔여량 합계를 조회 | 현재 보호막 총량 |
| `On Death` | 실제 체력 피해로 현재 체력이 0 이하가 될 때 한 번 발생 | 사망 대상, 마지막 피해 공격자, 전달 방식, 속성, 피해 출처 분류·이름, 로그용 피해 이름 |

`Apply Stagger and Groggy Damage`는 `On Damage Hit` 또는 `Apply Combat Damage`가 반환한 `DamageHitContext`, 기본 경직 피해, 기본 그로기 피해, 공격별 경직 배율, 출처 분류·이름과 로그용 이름을 입력으로 받는다. 유효한 적중 맥락이 아닌 경우에는 아무 처리도 하지 않는다. 이 규칙으로 회피·일반 무적에 막힌 공격이 경직·그로기만 적용하는 실수를 방지한다.

DOT 틱이 경직·그로기 피해를 주어야 하면 `FARDamageOverTimeSpec`에 선택적 `FARStaggerRequestTemplate`을 함께 저장한다. 중앙 처리기는 각 틱의 유효한 `DamageHitContext`로 템플릿을 실행한다. 템플릿이 없으면 DOT는 체력 피해만 적용한다. 이 방식으로 DOT를 부여한 런타임 아이템이 제거되거나 시전자가 사망한 뒤에도 남은 틱의 규칙이 유지된다.

`Apply Damage Over Time`은 공통 피해 입력에 지속시간, 틱 간격, 틱당 피해, 지속 피해 이름, 중첩 방식(독립 중첩/같은 이름 지속시간 갱신)을 추가로 받는다. 후자를 고르면 대상에게 같은 이름의 지속 피해가 이미 있을 때 새 인스턴스를 만들지 않고, 같은 피해·지속시간·틱 간격인지 검증한 뒤 기존 인스턴스의 지속시간만 초기화한다. 서로 다른 정의라면 기존 효과를 건드리지 않고 개발 경고를 출력한다. `Remove Damage Over Time`은 대상, 선택 `DamageOverTimeHandle`, 제거 범위(모두/무기/유물/버프/기타), 선택 출처 이름, 선택 로그용 피해 이름을 입력으로 받는다. 화상 해제, 정화, 보스 페이즈 전환, 장판 범위 이탈 등에 사용한다.

`Apply Shield`는 대상, 보호막 수치, 지속시간, 출처 분류(무기/유물/버프/기타), 출처 이름을 입력으로 받는다. 지속시간 `-1`은 직접 제거 전까지 유지한다. `Remove Shield`는 대상, 선택 `ShieldHandle`, 제거 범위, 선택 출처 이름, 수명 필터(전체/시간제 보호막만/영구 보호막만)를 입력으로 받는다. `Get Current Shield`는 UI의 보호막 바, 피격 연출, 조건부 유물 효과가 대상의 현재 보호막 총량을 확인할 때 사용한다.

`Apply Super Armor`는 대상, 지속시간, 출처 분류(무기/유물/버프/기타), SourceId와 DisplayName을 입력으로 받는다. 지속시간 `-1`은 직접 제거 전까지 유지한다. `Remove Super Armor`는 Handle 또는 제거 범위와 선택 SourceId로 항목을 제거한다. 행동 중 슈퍼아머는 `Apply Action Super Armor(ActionHandle, Spec)`를 사용해 행동 종료·취소 시 자동 제거한다.

`On Death`는 사망 상태가 처음 확정될 때만 발생하며, 이미 사망한 대상이 추가 피해를 받아도 다시 발생하지 않는다. 드롭, 처치 유물, 적 사망 연출은 이 이벤트를 구독해 처리한다.

피해 한 건의 이벤트 순서는 아래로 고정한다.

```text
요청·팀·대상 검증
→ 회피/치명타/방어/감소 계산
→ 보호막과 체력 반영
→ OnHealthChanged / OnShieldChanged
→ OnDamageReceived 또는 OnDamageEvaded / OnDamageBlocked
→ 공격자 OnDamageHit
→ 흡수 누적 및 정수 회복 적용
→ 사망이 확정된 경우 OnDeath 1회
```

`DamageResult`는 콜백 전에 처치 여부까지 확정하므로 OnHit·처치 효과가 같은 결과를 읽는다. 이벤트 처리 중 발생한 새 피해는 별도의 요청으로 큐에 넣고 현재 피해 이벤트가 끝난 뒤 처리한다. 기본 OnHit 추가 피해는 `적중시 효과 적용=false`이며, 전투 Subsystem은 비정상 순환을 잡기 위한 설정 가능한 연쇄 깊이 경고를 제공한다.

| 피해 이벤트 | 발생 조건 | 전달값 | 용도 |
|---|---|---|---|
| `On Damage Hit` | 직접 피해가 성공했고 해당 요청의 `적중시 효과 적용`이 켜짐 | 공격자, 피격 대상, `DamageHitContext`, 최종/보호막/체력 피해, 속성, 치명타 여부, 출처 분류·이름, 로그용 피해 이름 | 경직·그로기 노드 호출, 적중 유물·무기 효과 |
| `On Damage Received` | 직접·지속 피해가 회피·일반 무적에 막히지 않고 적용 성공 | 공격자, 최종/보호막/체력 피해, 전달 방식, 속성, 치명타 여부, 출처 분류·이름, 로그용 피해 이름 | 피격 VFX, 방어형 유물, 피해 로그 |
| `On Damage Evaded` | 회피 판정 성공 | 공격자, 피격 대상, 전달 방식, 속성, 출처 분류·이름 | 회피 연출, 회피 반응 효과 |
| `On Damage Blocked` | 일반 무적 또는 전체·해당 속성 피해 감소의 남은 피해 배율이 0이 되어 일반 피해가 완전히 차단 | 공격자, 피격 대상, 전달 방식, 속성, 출처 분류·이름 | 무적 피격 연출, 방어형 반응 효과 |
| `On Shield Broken` | 피해로 현재 보호막이 양수에서 0으로 전환 | 보호막이 깨진 대상, 공격자, 마지막 피해 결과 | 보호막 파괴 연출, 보호막 파괴 반응 효과 |

검 블루프린트는 베기 범위와 맞은 대상을 찾은 뒤, 피해가 있으면 `Apply Combat Damage`를 호출하고 경직·그로기 효과가 있으면 `Apply Stagger and Groggy Damage`를 호출한다. 방어력 계산, 체력 차감, 경직 저항력 비교, 그로기 게이지 갱신은 블루프린트에 복제하지 않는다.

### 14.3 상태이상(CC)

상태이상은 `UARStatusEffectDefinition` 데이터 에셋으로 정의한다. 개별 상태이상마다 새로운 복잡한 블루프린트 그래프를 복사하지 않는다. 초기 Definition 필드는 `PrimaryAssetId`, 상태 Gameplay Tag, 표시 이름·아이콘, 기본 지속시간, 동일 상태 갱신 정책, 이동 차단, 구르기 차단, 신규 Skill Group 차단, 적용 시 Action 취소 사유다. 초기 콘텐츠는 `Stun`과 `Root` 두 Definition만 만든다.

| 블루프린트 노드 | 용도 |
|---|---|
| `Apply Status Effect` | 대상, `StatusEffectDefinition`, 선택 지속시간 Override, `SourceId`를 받아 강인함 반영 후 적용 또는 갱신 |
| `Remove Status Effect` | 특정 상태이상 제거 |
| `Has Status Effect` | 상태이상 보유 여부 확인 |
| `Is Stunned` / `Is Rooted` | 현재 활성 상태이상 목록에서 계산한 읽기 전용 기절·속박 상태 확인 |
| `Get Status Remaining Time` | UI·연출용 남은 시간 조회 |
| `Can Perform Action` | 이동, 기본 공격, 무기 스킬, 유물 사용 가능 여부 확인 |

초기 상태이상 식별자는 확장 가능한 게임플레이 태그 또는 C++ 열거형으로 관리한다. 규모가 커질 가능성을 고려해, 새 상태이상 추가 시 기존 노드를 수정하지 않아도 되는 데이터 중심 구조를 우선한다.

### 14.4 행동(Action) 생명주기

기본 공격, 무기 스킬, 액티브 유물은 시스템상 모두 같은 **스킬 행동(Skill Action)** 으로 취급한다. 무기 여부는 UI·장착 슬롯·진화 규칙에서만 특별 취급하며, 행동 시작·취소·피해·스킬 실행의 공통 구조는 공유한다. 구르기는 별도의 **Roll Action**이다. 블루프린트는 자체적으로 행동을 시작하지 않는다.

포션·소모품은 즉발 효과다. 사용 즉시 자원 회복 또는 효과 요청을 실행하며 `ActionComponent`의 진행 중 행동을 취소하거나 새 행동을 점유하지 않는다. 사용 애니메이션·사운드는 재생될 수 있으나 전투 행동 규칙에는 영향을 주지 않는다.

| 블루프린트 노드 또는 이벤트 | 용도 |
|---|---|
| `Try Start Action` | 행동 가능 여부를 확인하고 현재 행동으로 등록. 성공 시 Action Handle 반환 |
| `Can Start Action` | 현재 상태에서 행동 시작이 가능한지 확인 |
| `End Action` | Action Handle에 해당하는 행동을 정상 종료 |
| `Cancel Current Action` | C++가 경직·사망 등으로 현재 행동을 취소할 때 사용 |
| `Set Action Cancel Rule` | 진행 중인 Action Handle의 취소 사유별 허용 여부를 변경. 차지 단계·후딜 단계처럼 행동 도중 규칙을 바꿔야 할 때만 사용 |
| `Set Action Roll Blocked` | 해당 Action Handle이 유지되는 동안 플레이어의 구르기를 막거나 다시 허용. 종료·취소 때 자동 해제 |
| `Set Action Basic Movement Blocked` | 해당 Action Handle이 유지되는 동안 WASD 기본 이동을 막거나 다시 허용. 종료·취소 때 자동 해제 |
| `Action Delay` | Action Handle에 귀속된 선딜·후딜 대기. 행동이 취소되면 완료 핀으로 진행하지 않으며 취소 경로로 전환 |
| `Register Action Hitbox` | Action Handle이 유효한 동안만 활성인 히트박스를 등록. 행동 종료·취소 때 자동 해제 |
| `Apply Action Stat Modifier` | 해당 행동이 유지되는 동안만 스탯 수정치를 적용. 정상 종료·취소 때 자동 제거 |
| `On Action Cancelled` | 무기·유물 블루프린트가 취소 사유를 받고 연출을 정리하는 표준 이벤트 |
| `On Action Ended` | 무기·유물 블루프린트가 정상 종료를 받고 연출을 정리하는 표준 이벤트 |

`Try Start Action`은 현재 상태가 허용하는 행동인지, 진행 중인 행동과 충돌하지 않는지, 자원과 재사용 대기시간이 충족되는지 같은 공통 조건을 검사한다. 블루프린트는 시작한 행동마다 아래 **취소 규칙 체크박스**만 정하면 된다. 기본값은 경직·기절 취소 `true`, 구르기 취소 `false`다.

| Action 취소 규칙 | 의미 |
|---|---|
| `Cancel On Stagger` | 실제 경직이 성립하면 이 행동을 `Stagger` 사유로 취소 |
| `Cancel On Stun` | 기절이 성립하면 이 행동을 `Stun` 사유로 취소 |
| `Cancel On Roll` | 구르기가 실제로 시작되면 이 행동을 `Roll` 사유로 취소 |
| `Cancel On Basic Movement Input` | WASD 등 기본 이동 입력이 실제로 받아들여지면 이 행동을 `BasicMovement` 사유로 취소 |

구르기 가능 여부는 위 체크박스와 별개로 Player Character의 관리형 `Can Roll` 값이 결정한다. 차지 공격처럼 구르기 자체를 막고 싶은 행동은 `Set Action Roll Blocked(true)`를 사용한다. 이 노드는 블루프린트에서는 Boolean 하나로 쓰지만, C++ 내부에서는 Action Handle에 귀속된 구르기 차단 요청으로 관리한다. 따라서 서로 다른 효과가 동시에 구르기를 막아도 한 효과가 끝났다고 다른 효과의 차단이 잘못 풀리지 않으며, 행동의 정상 종료·강제 취소 때 자신의 요청은 자동 해제된다.

기본 이동도 같은 방식으로 Player Character의 관리형 `Can Basic Move` 값으로 제어한다. `Set Action Basic Movement Blocked(true)`는 WASD 같은 **기본 이동 입력만** 막는다. 스킬이 `MovementControlComponent`에 직접 요청한 돌진·밀기·끌려감 같은 행동 이동은 이 값 때문에 막히지 않는다. 반면 기절·속박처럼 실제 이동 자체를 봉쇄하는 CC는 기존의 공통 이동 잠금으로 처리하며, 기본 이동과 행동 이동을 모두 멈춘다. `Can Basic Move`도 내부적으로는 Action Handle별 차단 요청을 합산해 계산하므로, 한 행동이 종료되어도 다른 행동의 이동 차단이 남아 있으면 유지된다.

반대로 구르기가 허용된 상태에서 `Cancel On Roll`이 꺼진 행동은 구르기 시작 뒤에도 그대로 진행된다. 이것이 구르면서 유지되는 시전·오라·특수 공격을 만드는 방식이다. 기본 이동이 허용된 상태에서 `Cancel On Basic Movement Input`이 켜진 행동은 WASD 입력으로만 끊을 수 있다. 단, `Set Action Basic Movement Blocked(true)`가 켜진 동안에는 기본 이동 입력 자체가 받아들여지지 않으므로 그 입력으로 행동이 취소되지 않는다. 차지 공격은 시작 시 구르기와 기본 이동을 모두 막고, 후딜에서 각각 해제할 수 있다. 가벼운 기본 공격은 이동을 막지 않은 채 `Cancel On Roll` 또는 `Cancel On Basic Movement Input`을 원하는 감각에 맞게 켤 수 있다.

사망은 항상 모든 행동을 취소하므로 체크박스로 끄지 않는다. 속박은 진행 중인 구르기만 취소하며, 일반 스킬 행동의 취소 여부는 바꾸지 않는다. 취소 규칙이 단계마다 달라져야 하는 특수 스킬만 `Set Action Cancel Rule`을 사용한다.

스킬은 `Input.Skill.Primary`, `Input.Skill.1`, `Input.Skill.2`처럼 실제 키와 분리된 **입력 태그(Input Tag)** 를 가진다. IMC의 각 입력 액션은 하나의 입력 태그를 전달하며, 런타임 객체가 같은 입력 태그로 등록한 스킬은 한 번의 입력에 함께 실행된다. 예를 들어 `Input.Skill.1`을 Q에 매핑하면, 무기·액티브 유물 등 여러 객체가 등록한 `Input.Skill.1` 스킬이 모두 대상이 된다.

`ActionComponent`는 한 번의 입력으로 시작된 스킬들을 `Skill Group Action`으로 묶어 관리한다. 그룹은 `FARSkillGroupHandle` 하나를 가지며 각 참여 스킬은 별도의 `FARActionHandle`을 가진다. 따라서 참여 스킬마다 종료 시점과 구르기 취소 허용 여부가 달라도 안전하게 관리할 수 있다. 같은 입력 태그의 스킬은 `InputPriority` 오름차순으로 검사하며, 같은 우선순위의 스킬만 하나의 원자적 우선순위 그룹이 된다.

```text
1. 플레이어의 공통 행동 가능 여부 검사
2. 가장 낮은 InputPriority 그룹 검사
   → 같은 우선순위의 모든 스킬이 등록 상태·쿨다운·고유 사용 조건을 통과해야 함
   → 통과하면 그 그룹의 MP·스태미나 비용을 임시 자원값에 예약
3. 다음 InputPriority 그룹을 남은 임시 자원값으로 검사
4. 어떤 우선순위 그룹이 실패하면 그 그룹과 이후 그룹의 검사를 중단
5. 앞서 통과한 그룹이 하나 이상이면 예약 총비용을 한 번에 실제 소비하고,
   통과한 모든 스킬을 같은 프레임에 실행
```

따라서 기본 공격을 `InputPriority = 0`, 3초마다 나가는 추가 공격을 `InputPriority = 1`로 두면, 추가 공격이 쿨다운이더라도 기본 공격은 정상 실행된다. 반대로 같은 우선순위의 의도적 동시 스킬 중 하나가 쿨다운·조건·자원 부족이면 그 우선순위 그룹 전체와 이후 우선순위는 실행되지 않는다. 통과한 그룹이 하나도 없으면 행동·자원 소비·쿨다운 시작이 모두 발생하지 않는다. 그룹은 참여한 모든 스킬 행동이 종료될 때 끝난다.

모든 정적 검사와 런타임 `CanExecuteItemSkill`이 끝난 뒤에만 예약 비용을 실제 소비하고 참여 스킬의 쿨다운과 Action Handle을 한 번에 Commit한다. Commit 뒤 경직·기절·구르기·아이템 제거로 취소되더라도 기본적으로 소비 자원과 쿨다운은 환불하지 않는다. 환불은 별도 콘텐츠 효과가 명시적으로 자원 회복·쿨다운 변경 노드를 호출할 때만 발생한다. 인벤토리에서 실행 중 아이템을 제거하면 해당 Item Instance가 소유한 참여 Action만 `ItemRemoved` 사유로 취소하고, 그룹의 다른 참여 Action은 각자의 규칙대로 계속된다.

초기 행동 취소 규칙은 아래로 고정한다.

```text
진행 중인 Skill Group Action
→ 다른 입력 태그의 Skill Group 요청: 거부
→ Roll 요청: Player의 Can Roll 값과 스태미나가 충족되면 Roll 시작
   → Cancel On Roll이 켜진 행동만 Roll 사유로 취소
   → 꺼진 행동은 Roll과 병행하여 계속 진행

진행 중인 Roll Action
→ Skill Group 요청: 초기에는 거부
→ Roll 재요청: 거부

즉발 포션·소모품
→ 위 행동 점유·취소 규칙과 무관하게 즉시 사용
```

스킬 연계는 행동 중간 취소가 아니라, 이전 Skill Group Action이 모든 참여 스킬의 `End Action`으로 정상 종료된 뒤 다음 입력 그룹을 허용하는 방식으로 시작한다. 구르기 **중 새 스킬을 시작하는** 특수 규칙은 실제 콘텐츠에서 필요해질 때 별도 옵션으로 추가한다. 현재 범위는 이미 시작된 행동을 구르기와 병행할 수 있게 하는 데까지다.

경직이 실제로 성립하면 `Stagger` 사유로, 기절이 성립하면 `Stun` 사유로 모든 진행 중 Skill Group Action과 Roll Action을 강제 취소한다. 슈퍼아머는 경직 자체가 성립하지 않게 하는 규칙이며, 기절 취소 면역을 뜻하지 않는다. 이미 생성되어 날아가는 투사체나 이미 적용된 피해는 되돌리지 않는다. 취소 대상은 현재 진행 중인 공격의 이후 단계와 그 행동에 귀속된 타이머·히트박스·이동·시전 중 수정치다.

### 14.5 스킬 자원·쿨다운과 Loadout

일반 무기·액티브 유물 스킬은 `SkillDefinition`에 적힌 MP 비용, 스태미나 비용, 기본 쿨다운을 `ActionComponent`가 자동으로 사용한다. 콘텐츠 BP는 일반 스킬마다 비용을 다시 차감하거나 쿨다운을 시작하지 않는다. 적중 후 추가 MP 소비, 쿨다운 즉시 초기화, 포션 회복처럼 특수한 콘텐츠만 아래 자원·쿨다운 노드를 직접 사용한다.

| 블루프린트 노드 | 입력 | 용도 및 반환 |
|---|---|---|
| `Get Skill Cooldown State` | `RegisteredSkillHandle` | 준비 여부, 남은 시간, 전체 쿨다운, 진행 비율 반환. HUD 표시용. |
| `Reset Skill Cooldown` | `RegisteredSkillHandle` | 해당 등록 스킬 쿨다운을 즉시 0으로 만들고 성공 여부 반환. |
| `Modify Skill Cooldown` | `RegisteredSkillHandle`, 변경 시간 | 음수면 남은 쿨다운 감소, 양수면 증가. 변경 후 남은 시간과 성공 여부 반환. |
| `Get Registered Skill UI Data` | 플레이어 | 등록된 각 스킬의 `RegisteredSkillHandle`, `SkillId`, 소유 Item InstanceId, 이름·아이콘·설명, 입력 태그와 실제 키 표기, 출처, HUD 정렬, 비용, 쿨다운 상태를 배열로 반환. |
| `Get Loadout Inventory` | 플레이어 | 현재 무기, 액티브 유물, 패시브 유물 런타임 객체 목록을 UI에 반환. |
| `Get Loadout Item Display Data` | 런타임 Item Instance | 이미지·이름·설명·자동 생성 제공 스탯·스킬 설명·현재 상태 UI 정보를 UI 전달 구조체로 반환. |
| `Request Discard Loadout Item` | 플레이어, Item InstanceId | 인벤토리 UI에서 선택한 액티브·패시브 유물의 폐기 요청. 성공 시 런타임 객체를 해제하고 플레이어 근처에 같은 Definition의 월드 픽업을 생성한다. 무기 요청은 거부한다. |
| `Begin Loadout Acquisition` | 플레이어, Item Definition, 획득 출처 | 장착 가능 여부만 검사하고 획득 요청 핸들과 결과를 반환. |
| `Commit Loadout Acquisition` | 획득 요청 핸들 | 실제 등록을 원자 처리하고 결과·새 Item Instance를 반환. 무기는 기존 장착 무기를 즉시 교체·소멸하며, 액티브 유물 슬롯이 모두 찬 경우에는 Commit할 수 없다. |
| `Cancel Loadout Acquisition` | 획득 요청 핸들 | 획득·교체 요청을 변경 없이 취소. |
| `Request Weapon Evolution` | 플레이어, 진화 출처 | 현재 무기의 진화 선택지를 검사. 없음/즉시 진화/선택 필요 결과와 필요 시 요청 핸들을 반환. |
| `Get Weapon Evolution Options` | 진화 요청 핸들 | 다음 단계 무기 후보의 UI 정보 목록 반환. |
| `Commit Weapon Evolution` | 진화 요청 핸들, 선택 `PrimaryAssetId` | 현재 무기를 해제하고 검증된 다음 단계 무기를 새로 등록. |
| `Cancel Weapon Evolution` | 진화 요청 핸들 | 진화 선택을 취소. |

`Try Use Weapon Skill`, `Try Use Active Relic`, `Equip Weapon`, `Add Passive Relic`처럼 타입별로 중복된 공개 노드는 초기 기반에 만들지 않는다. 입력·스킬 실행은 `ActionComponent`의 공통 Skill 등록 경로가, 획득·교체는 공통 Loadout Acquisition 경로가 처리한다. 무기와 액티브 유물의 차이는 각각 1개·2개 슬롯 제한과 UI·진화 규칙으로만 처리한다.

획득·진화 요청 핸들은 요청 당시의 Player, Loadout Revision, 현재 무기 InstanceId와 후보 목록을 보관한다. Commit 시 슬롯·생존·무기·Revision을 다시 검증하며, 플레이어 사망, 다른 장착 변경, UI 취소, 새 요청 생성으로 오래된 핸들이 되면 `StaleRequest`로 거부한다. 인벤토리와 이벤트 UI가 게임을 일시정지하지 않으므로 이 재검증은 필수다.

### 14.6 UI

UI에는 조회 노드보다 변경 이벤트를 제공한다.

| C++ 이벤트 | UI 갱신 대상 |

| `OnActiveRelicStateChanged` | 유물 재사용 대기시간 |

## 15. 콘텐츠 제작 흐름

### 검 블루프린트 예시

```text
입력
→ ActionComponent가 입력 태그에 등록된 SkillDefinition을 공통 검증
→ MP·스태미나 원자 소비 및 쿨다운 시작
→ Execute Item Skill(SkillId, ActionHandle)
→ 공격 애니메이션·베기 범위·카메라 흔들림 (Blueprint)
→ 맞은 대상마다 Apply Combat Damage (C++ 판정)
→ On Damage Resolved 결과 수신
→ 피격 VFX·사운드·피해 숫자 표시 (Blueprint)
```

이 흐름을 따르면 다른 개발자는 C++ 내부 계산을 몰라도 새 무기와 유물을 만들 수 있고, 기반 규칙은 한 곳에서 일관되게 유지된다.

## 17. 개발 시 금지할 패턴

- 블루프린트에서 `Health`나 `Stamina` 값을 직접 설정하는 것
- 블루프린트에서 경직 시간, 경직 면역, 그로기 게이지를 직접 관리하는 것
- 슈퍼아머를 영구 스탯처럼 설정하거나 피해 무적과 혼동하는 것
- 무기·유물 블루프린트가 `Try Start Action` 없이 자체적으로 행동을 시작하는 것
- 무기마다 방어력·회피·치명타 계산을 따로 복사하는 것
- UI가 Event Tick으로 모든 수치를 반복 조회하는 것
- 적 전용 예외를 `AARBaseCharacter`에 하드코딩하는 것
- 새 상태이상을 추가할 때 기존 상태이상 그래프를 복제하는 것

4. DOT·Stagger·Status·Action
