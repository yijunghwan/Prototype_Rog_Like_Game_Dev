구조체는 여러 값을 하나로 묶은 타입입니다. Request와 Spec은 값 묶음의 실제 핀 이름이며, 새로운 피해 종류를 뜻하지 않습니다. 각 노드 안의 펼침에서 내부값을 확인하세요.

  1. 통째 연결: Make 노드로 값을 채워 연결하거나 같은 타입의 구조체 변수를 Get해서 연결합니다.
  2. 개별 입력: 연결되지 않은 구조체 핀을 우클릭해 구조체 핀 분할(Split Struct Pin)을 선택합니다. 중첩 구조체도 분할할 수 있습니다.
  3. 결과 읽기: Break 노드 또는 출력 핀 분할로 필요한 값만 꺼냅니다. 읽기 전용 타격 기록은 임의로 성공값을 만들지 않습니다.

함수 버전·핀 노출 설정에 따라 자동 숨김 핀이나 고급 핀 표시가 다를 수 있습니다. 문서의 한글 설명은 실제 영문 핀 이름과 함께 제공합니다.

실행 Apply Combat Damage

선택한 Actor에게 지금 한 번 피해를 적용하는 실행 노드입니다. 공격자·대상·기본 피해·계수·옵션을 받아 대상 검사부터 회피·무적·피해 공식·실드/HP 차감·전투 알림·흡혈까지 처리합니다. 충돌 탐색, 경직·그로기, 개별 상태 이상은 별도로 연결합니다.

같은 피해 이름의 반복 피격 제한 · 기본 0.2초

대상 + Damage Name의 Applied 피해가 다음 허용 시각을 기록합니다. 그 전의 제한 사용 요청은 Outcome=Blocked / Failure Reason=Cooldown이며 실드·체력 차감, 흡혈·온히트, 경직용 유효 타격이 발생하지 않습니다. 회피·무적·피해 0·무효 요청은 제한을 시작하지 않습니다.

공격자·출처·속성·직접/DOT가 달라도 같은 이름이면 공유합니다. 서로 다른 대상과 이름은 독립입니다. 공허·확정 명중도 이름 제한을 우회하지 않습니다. 이후 요청의 짧은 양수 간격으로 기존 제한을 단축하지 않습니다.

None 이름 / 간격 0 / Ignore Damage Name Interval=True는 해당 요청의 검사·기록만 생략합니다. 기존 제한을 지우거나 연장하지 않습니다. 플레이어 피격 후 전체 무적과 다른 기능이며 별도 노드나 BP 타이머 없이 Request 안에서 지정합니다.

DOT는 등록 중복을 막는 것이 아니라 각 틱의 피해 적용을 제한합니다. 밀린 틱은 예정 시각 순서로 검사하므로 정상 간격의 틱을 한 프레임이라고 묶어 차단하지 않습니다.

Queued는 내부 큐에 수락된 요청이며 아직 Hit Context가 유효하지 않습니다. Blocked + Failure Reason=Cooldown이면 피해 이름별 재피격 제한에 막힌 것입니다. Invalid/Blocked/Evaded에서 HP 차감을 실행 노드로 다시 만들지 말고 실패 원인을 확인하세요.

구조체 연결: Request는 Make ARCombatDamageRequest의 출력이나 구조체 변수로 통째 연결할 수 있습니다. 입력 핀을 분할해 개별 값으로 넣을 수도 있습니다. 결과는 Break ARCombatDamageResult 또는 출력 핀 분할로 읽습니다. 위 펼침은 문서에서 내부값을 확인하는 기능이며 실제 노드의 핀 이름을 바꾸는 것이 아닙니다.

피해 이벤트 안에서 또 피해를 요청하면 재진입 보호 큐에 들어갈 수 있습니다. 이때 반환은 Queued이며 최종 수치가 아닙니다. 현재 체인의 처리 제한은 기본 256입니다. 반사/추가 타격 이벤트가 서로 끝없이 재호출되지 않도록 콘텐츠 측 조건을 두세요.

02 피해 이벤트 · 피격 후 후속 처리

적용 결과의 전체 핀 설명은 Apply Combat Damage 안의 피해 결과 펼침에 있습니다. 여기서는 결과를 받는 공용 이벤트와 발생 순서를 확인합니다.

이벤트 On Damage Received / Hit / Evaded / Blocked

피해 처리 뒤 발생하는 공용 알림입니다. 이벤트를 구독해 피격 연출이나 후속 처리를 연결할 때 사용하며, 이 이벤트 자체가 피해를 주지는 않습니다.

Subsystem 알림Subject 핀발생 조건
On Damage Received피격자 Request.TargetApplied 후. Direct와 DOT 모두 포함
On Damage Hit공격자 Request.AttackerApplied + Direct + Apply On Hit Effects=True
On Damage Evaded피격자 Request.Target회피 판정 성공
On Damage Blocked피격자 Request.Target피해 이름별 간격 차단 또는 수치 계산기 차단(무적·피해 0 등)

각 알림은 Subject Actor와 Damage Result를 제공합니다. Bind한 뒤 Subject·Target·필요한 실행 정보로 필터링해야 다른 공격의 결과를 잘못 처리하지 않습니다. 이름별 간격 차단은 Failure Reason=Cooldown입니다. 초기 팀·Actor·Health 검사에서 거절되는 Invalid 요청은 On Damage Blocked를 자동 방송하지 않습니다.

순서: 실드·HP 적용 및 Health Component의 피해/사망 알림 → On Damage Received → 조건부 On Damage Hit → 흡혈. 이벤트 안에서 추가 피해를 호출하면 큐 처리된다는 점을 고려합니다. 사망 뒤 액터 파괴·연출은 해당 캐릭터 콘텐츠의 책임입니다.

ExpireAt = 등록 시점 + Duration
NextTickAt = 등록 시점 + TickInterval
NextTickAt ≤ 현재 시간 AND NextTickAt ≤ ExpireAt → 한 틱
NextTickAt += TickInterval

종료 시점과 같은 틱도 처리 대상입니다. 이상적인 1초/0.25초 설정이면 0.25·0.5·0.75·1초의 4틱입니다. 부동소수 시각과 프레임 경계 때문에 매우 촘촘한 스케줄은 실제 실행에서 검증하세요. Interval>Duration이면 발생하는 틱이 없을 수 있습니다.

프레임이 늦어지면 누락된 틱을 한 프레임에서 따라잡습니다. 각 틱의 예정 시각으로 이름별 간격을 검사하므로 한 프레임 1틱 제한이 아닙니다. 이름 제한보다 촘촘한 틱이나 같은 이름의 병렬 틱은 의도적으로 차단됩니다. 기본 Catch Up 경고 기준 32와 활성 DOT 경고 기준 512는 경고 기준이지 잘라내는 상한이 아닙니다.

같은 대상 + 같은 Damage Name은 기본 0.2초 재피격 제한을 공유합니다. Source Id가 같다는 이유로 묶이지는 않습니다. DOT의 Tick Interval은 발생 일정이고 Damage Name Interval은 실제 적용 제한입니다. 둘이 겹치면 일부 틱이 차단될 수 있으며, 의도적인 독립 중첩 피해는 무시 체크를 선택할 수 있습니다. None 이름은 제한 대상이 아닙니다.

공격자 Actor가 소멸하면 마지막 공격 스냅샷으로 남은 틱을 계속 계산하고, 공격자/팀 재검증은 생략합니다. 대상의 유효성·Health 활성 상태·Stats는 계속 필요합니다. 그때 Hit Context.Attacker=None이 될 수 있습니다. 공격자가 죽었지만 Actor가 유효한 경우는 ‘소멸’과 다르며 일반 경로로 진행합니다.

04 경직·그로기 피해 노드와 공식

직접 피해 노드의 Return Value를 그대로 받아 경직·그로기를 추가합니다. 피해가 실제로 적용됐는지와 타격 기록의 유효성을 내부에서 확인하므로, 결과를 Break하거나 Outcome을 비교하는 Branch/Switch 또는 Make ARStaggerRequest가 필요 없습니다. HP 피해를 다시 주는 노드가 아닙니다.

Apply Combat Damage는 단일 Target 요청입니다. 구체·박스 오버랩, 라인 트레이스, 범위 내 Actor 배열 수집은 콘텐츠가 구성합니다. 각 대상에 요청할 때 Attacker·Attribute·계수·옵션을 일관되게 지정합니다.

07 체력 피해 공식 · 계산 순서

아래 스탯은 이미 보정·안전 규칙을 통과한 Final Stat입니다. Damage Request에 최종 공식을 직접 계산해 넣을 필요는 없습니다. 상수·계수와 옵션만 정하고 시스템에 맡깁니다.

대상/팀 검사 → 피해 이름별 재피격 제한 → 회피 → 보장 무적 → 기본 피해 → 주는 피해 증가 → 치명타 → 방어/관통 → 받는 피해 증가 → 피해 감소 → 정수화 → 제한 기록 → 실드/HP 분배 → 이벤트·흡혈
공식 기본 피해 · 상수 + 공격력 계수 + 주문력 계수 
B = BaseDamage + AttackPower × AttackPowerCoefficient
               + SpellPower × SpellPowerCoefficient

Base Damage와 두 계수는 유한한 숫자여야 합니다. B가 0 이하이면 Blocked입니다. 에디터의 Base Damage 최소값 표시는 0이지만, 런타임은 최종 B를 확인하므로 음수 계수를 보내 피해를 보정하는 것은 권장하지 않습니다.

공격력·주문력 계수 둘 다 0이면 Base Damage만 사용합니다. 속성을 바꾸어도 계수는 자동 변경되지 않습니다.

공식 주는 피해 증가 · 합연산 
A = OverallDamageAmplification
  + (Direct이면 DirectDamageAmplification,
     DOT이면 DamageOverTimeAmplification)
  + 선택 속성의 DamageAmplification

D₁ = B × max(0, 1 + A / 100)

Apply Amplification=True일 때 적용합니다. 공허에는 속성 전용 증가 스탯이 없어 마지막 항이 0이며 전체·전달 방식 증가는 그대로 받습니다.

전체 +20, 단타 +30, 물리 +10이면 합계 +60% → 1.6배입니다. 1.2×1.3×1.1로 곱하지 않습니다.

공식 치명타 · 확률과 배수 
치명타 확률 = clamp(Final CriticalChance, 0, 100)
C = 치명타 발생 시 max(0, CriticalDamage / 100), 아니면 1
D₂ = D₁ × C

Can Crit=True일 때 매 피해 처리에서 확률을 뽑습니다. DOT도 허용하면 틱마다 치명타 판정을 합니다. 스탯 컴포넌트의 Max Critical Chance 상한도 먼저 적용됩니다(기본 100).

Critical Damage 기본 150은 1.5배입니다. 치명타가 나도 배수가 0이면 피해는 Blocked가 될 수 있습니다. Result.Critical과 Outcome을 함께 확인합니다.

공식 방어력과 관통 · 속성별 방어 
P = clamp(DefensePenetration, 0, 100)
E = max(0, 선택 속성 Defense) × (1 − P / 100)
D₃ = D₂ × 100 / (100 + E)

방어 100·관통 0이면 피해 50%, 방어 100·관통 50이면 약 66.67%가 남습니다. 관통은 고정 방어력 차감이 아닙니다.

Ignore Defense=True 또는 공허이면 이 단계만 건너뜁니다. Ignore Defense는 받는 피해 증가·피해 감소·실드·무적까지 무시하지 않습니다.

공식 받는 피해 증가 · 전체 + 속성 합연산 
T = OverallDamageTakenIncrease + 선택 속성 DamageTakenIncrease
D₄ = D₃ × max(0, 1 + T / 100)

일반 속성에서 Apply Amplification=True일 때 적용합니다. 전체 +50·화염 +20이면 화염 피해는 1.7배입니다. 전체 증가도 공허에는 적용되지 않습니다.

Apply Amplification은 공격자 쪽 증가뿐 아니라 대상 쪽 받는 피해 증가도 함께 끕니다. 치명타·방어·피해 감소는 각각 별도 규칙으로 남습니다. 받는 피해 증가 Final Stat은 현재 0 이상으로 제한됩니다.

공식 전체·속성 피해 감소 · 남는 비율의 곱 
각 감소 스탯의 일반 감소값 R
  = (BaseStat + Flat 합) × (1 + AdditivePercent 합 / 100)
                        × Multiplicative 곱
남는 비율 M = max(0, 1 − R / 100)
            × ∏ max(0, 1 − 독립감소값 / 100)

D₅ = D₄ × M전체 × M선택속성

동일 감소 스탯의 일반 보정은 먼저 합산·배율 계산하고, Independent Damage Reduction은 각각 남는 비율을 곱합니다. 전체 감소와 속성 감소도 서로 곱합니다. 공허는 이 단계 전체를 건너뜁니다.

전체 감소 20%·속성 감소 30%라면 0.8×0.7=0.56, 합계 피해 감소는 44%입니다. 독립 감소 50%를 두 개 적용하면 75% 감소입니다.

반환 정수화 · 최소 피해 · 실제 반환값 
D₅ ≤ 0 → Blocked, 피해 0
D₅ > 0 → 공식 정수 피해 N = max(1, floor(D₅))

양수인 미세 피해만 최소 1입니다. 기본 피해 0·무적·완전 감소·회피를 최소 1로 뚫지 않습니다. 배율 단계마다 반올림하지 않고 마지막에 내림합니다.

Apply Combat Damage의 반환 Final Damage는 이 N이 아니라 실제 차감 결과입니다. 실드·남은 체력으로 제한된 Shield Damage + Health Damage로 다시 기록됩니다. 체력이 부족한 대상에 큰 피해를 주면 초과 피해는 반환값에서 빠집니다. 자원이 소수일 때 결과 필드도 내림되므로 Applied이지만 기록 피해 0인 소수 경계가 있을 수 있습니다.

요약 한 줄 공식과 빠른 검산 
일반 속성:
B × max(0, 1 + A/100) × C
  × 100/(100 + E)
  × max(0, 1 + T/100) × M전체 × M속성

공허:
B × max(0, 1 + A/100) × C

각 요청 옵션이 끈 단계는 배수 1로 취급합니다. 공허도 기본 대상 검사와 회피·치명타·실드 분배를 별도로 거칩니다.

검산용 수치: B=100, A=50, 치명타 없음, E=100, T=20, M전체=0.8, M속성=1이면 100×1.5×0.5×1.2×0.8=72. 공식 정수 피해는 72이고, 실드 20·충분한 체력이면 Shield Damage=20, Health Damage=52, Final Damage=72입니다.

등록한 DOT는 이미 자체 기간·틱 간격을 처리합니다. 틱마다 DOT 등록 노드를 다시 부르는 타이머를 추가하지 마세요. 동일 Damage Name 제한도 피해 요청의 설정이며 별도 BP 타이머가 필요 없습니다. 타이머 제거는 이미 등록한 독립 DOT·실드·보정을 제거하지 않습니다.

시간 그룹 · 기능과 설정

World와 Player라는 시간 그룹이 있습니다. 선택형 기본값은 World이며 게임 Pause 시 두 그룹 모두 멈춥니다. 시간 기준은 아이템/액션의 자동 정리 수명과 별개입니다.

직접 피해는 즉시 처리하며 DOT의 기간·틱과 동일 Damage Name 제한은 World 기준입니다. 선딜 타이머는 그룹 선택이 가능하고, 대상 실드의 기간은 플레이어/그 외 대상의 자체 시간 기준을 따릅니다.
