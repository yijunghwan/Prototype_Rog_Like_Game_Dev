적 액션·공격 참고서

적이 직접 시작하는 행동의 선딜·공격·취소·종료입니다. 아이템 Execute Item Skill 경로와 비용·쿨타임 책임이 다릅니다.

노드의 용도 → 연결 대상 → 입력·출력 → 정리 책임 순서로 확인합니다. 구조체는 설명 아래에서 펼쳐 보거나 Blueprint의 Split Struct Pin / Make 노드로 연결할 수 있습니다.

권장 액션 타이머시작·종료선딜·후딜공격·판정취소·효과

권장 타이머 · 수명 선택과 연결

먼저 어느 수명이 끝날 때 예약도 없어져야 하는지 선택합니다. 새 아이템·공격 그래프에서 일반 Set Timer by Event를 기본으로 쓰지 말고, 아래 귀속 노드를 사용하세요.

적 공격에는 액션 타이머를 사용합니다. Set Item Timer by Event는 아이템 런타임 전용이라 적 Self에는 사용할 수 없습니다. 적의 상시 AI 판단 루프는 공격 액션과 분리합니다.

노드Set Action Timer by Event

스킬·적 공격의 선딜, 후딜, 반복 실행은 이 노드를 우선 사용하세요. 한 액션 실행에 예약을 귀속하여 정상 End Action·실제 Cancel·소유 Actor EndPlay 때 자동 Clear합니다.

Target
Get Action Component에서 받은 AR Action Component. 아이템에서는 Get Item Owner → Get Action Component.
Action Handle
Execute Item Skill 또는 Try Start Action에서 받은 이번 실행의 핸들. 무효/다른 관리자 핸들은 실패.
Event
매개변수 없는 Custom Event 또는 Create Event를 연결합니다. 콜백 안에서 자기 액션 종료/아이템 해제도 가능합니다.
Time
양수인 실행 간격(초). 0·음수·비유한 값은 실패. Looping=false면 이 시간 뒤 한 번 실행합니다.
Looping
반복 여부. false는 1회 예약, true는 정리될 때까지 반복합니다.
Success / Return Value
예약 성공 Bool / 실제 Timer Handle. Pause Timer by Handle·Unpause Timer by Handle·Clear and Invalidate Timer by Handle 등 기존 엔진 노드에 연결합니다.
Initial Start Delay · 고급
기본 -1은 첫 실행도 Time 뒤. 0은 다음 Timer Manager 처리 때, 양수는 지정 초 뒤 첫 실행합니다. -1 외 음수는 실패.
Max Once Per Frame · 고급
기본 true. 프레임 지연 시 밀린 반복을 같은 프레임에 여러 번 호출하지 않습니다. false면 엔진의 따라잡기 실행을 허용합니다.
적: Try Start Action → Status 성공 → 이번 Action Handle 저장
Get Action Component → Set Action Timer by Event(Action Handle, Event, Time, Looping=false)
예약 Success → 대기 / 예약 실패 → End Action과 자체 상태 정리
Event 콜백 → 대상 유효성·공격 조건 확인 → 판정 → End Action
연결 규칙Event 콜백 · 완료와 취소의 차이

흰 실행 출력은 예약 직후이지 시간이 지난 출력이 아닙니다. 실제 효과는 Event에 연결한 Custom Event 안에서 실행합니다.

매개변수
Event는 입력 핀이 없는 Custom Event / Create Event입니다. 액션 핸들·대상은 실행별 상태에 저장해 콜백에서 읽습니다.
정상 완료
1회 호출이 끝나도 액션이 자동 종료되지는 않습니다. 마지막 효과 뒤 같은 관리자·핸들로 End Action. 실패 출구도 종료합니다.
자동 취소/해제
타이머에는 Cancelled 출력이 없습니다. On Item Skill Cancelled / On Action Cancelled / On Item Unregistered에서 자체 변수·연출·구독을 정리합니다.
콜백의 대상
귀속 수명과 별개로 대상 Actor가 삭제되거나 사망할 수 있습니다. Is Valid·사망·거리 등 콘텐츠 조건을 다시 확인합니다.
동시 실행
하나의 저장 변수로 이전 실행 핸들을 덮어쓰지 마세요. 중복 실행을 막거나 실행별 상태를 구분해야 합니다.
주의점중복 예약·Pause·이미 적용한 효과

전용 타이머는 예약의 수명만 관리합니다. 콘텐츠의 모든 상태를 자동 되돌리는 기능은 아닙니다.

중복 예약
호출마다 독립된 Timer가 생깁니다. 같은 Event를 넣어도 덮어쓰지 않습니다. Tick마다 시작하지 말고 등록/실행 시 한 번 시작하거나 Does Timer Exist by Handle 등으로 중복을 막습니다.
Pause / Unpause / Clear
Return Value를 Timer Handle 변수에 저장해 엔진 노드에 연결합니다. Pause는 남은 시간을 보존하며, 수명이 끝나면 일시정지 중이어도 제거됩니다. Clear한 타이머는 Unpause로 되살릴 수 없습니다.
CC와 취소 규칙
경직/기절 자체가 모든 타이머를 중단시키지는 않습니다. 해당 Action이 실제 취소되어야 액션 타이머가 제거됩니다. 아이템 보유 타이머는 별개입니다.
기존 일반 Timer
새 노드로 자동 전환되지 않습니다. 일반 Timer는 직접 Clear하거나 원하는 귀속 노드로 교체해야 합니다.
이미 적용한 효과
일반 스탯 보정·독립 투사체·등록한 DOT·Bool·구독은 타이머 Clear만으로 사라지지 않습니다. 각각의 귀속/제거 정책을 따릅니다.
단순 1회 대기
Looping=false로 한 번 예약할 수 있습니다. 순차 실행과 Completed/Cancelled 분기가 필요한 액션 대기는 Action Delay도 사용할 수 있습니다. 일반 Delay에는 귀속 수명이 없습니다.
00공격 액션 시작 · 핸들 · 종료
프로젝트 노드시작 전 판단 · Is Action Active / Can Start Action

거리·대상·쿨타임·패턴 조건은 적 AI 쪽에서 판단합니다. 이미 공격 중이면 반복 Tick에서 또 시작하지 않도록 저장 핸들을 검사하세요.

Is Action Active
Target=Action Component, Handle=저장한 행동 핸들 → 활성 Bool. 유효한 Actor 참조 검사와 다릅니다.
Get Active Action Count
이 관리자의 전체 활성 행동 수. 특정 공격만 추적하려면 그 공격 핸들을 검사합니다.
Can Start Action
Target=Action Component, Request=실행하려는 설정 → FARRequestStatus. 사전 조회만 하며 액션을 만들지 않습니다.

현재 공통 검사에는 죽음·경직·활성 구르기·스킬 차단 상태 등이 포함됩니다. 일반 공격 하나가 활성이라는 이유만으로 또 다른 일반 공격이 거절되는 구조는 아닙니다. 실제 시작 때는 Try Start Action이 다시 검사합니다.

프로젝트 노드Try Start Action

새 행동을 시작하고 이번 실행의 Action Handle을 발급합니다. 액션 Request 자체가 스킬 이름이나 공격 내용은 아닙니다.

Target
적 자신의 Action Component. BeginPlay에 캐시한 변수 Get을 사용해도 됩니다.
Request
FARActionRequest 구조체. 통째로 연결하거나 핀 우클릭 → Split Struct Pin으로 세부 설정을 넣습니다.
Status
FARRequestStatus. Break/Split으로 Result를 꺼내 EARRequestResult의 Success와 비교해 분기합니다. 숫자 0 하드코딩 대신 enum 이름을 사용합니다.
Return Value
FARActionHandle. Success에서 Set AttackHandle의 값 입력에 연결하고, 흰 실행선도 Set을 통과시킵니다. 실패 핸들로 대기/효과를 시작하지 않습니다.
구조체Request 펼치기 · 잠금·취소·연결 정보
Cancel Rules
경직/기절/구르기/일반 이동 입력에 대한 자동 취소 선택. 아래 취소 항목 참조.
Block Basic Movement While Active
활성 중 일반 이동을 잠금. 정지형 공격의 선딜에 사용합니다.
Block Roll While Active
활성 중 새 구르기를 차단.
Is Roll Action
이 행동이 구르기 자체인지. 일반 적 공격이면 false.
Skill Group Handle
별도 스킬 그룹 연결용 값. 현재 직접 TryStartAction만으로 그룹별 비용/쿨타임 시스템이 실행되지는 않습니다.
Owning Item Instance Id
아이템 소유 취소 연결용 GUID. 일반 적 직접 공격은 아이템 ID를 억지로 채우지 않습니다.

Action Tag는 현재 Request에 없습니다. 액션을 식별할 때 이번 실행의 Handle을 사용합니다.

1개 핸들 변수는 동시에 1개 행동을 저장할 때 적합합니다. 동시 패턴을 만들면 행동별 변수나 배열/맵을 사용하고, 완료·취소 콜백에서 다른 행동 핸들을 덮어쓰지 마세요.

프로젝트 노드End Action / Cancel Action

행동을 정상적으로 끝내거나 특정 행동을 중단합니다. 효과/잠금 회수 후 해당 알림이 전달됩니다.

End Action
Target=같은 Action Component, Handle=그 실행의 핸들 → Bool. 정상 완료·범위 이탈·타깃 소멸 등 완료 경로에 종료 책임을 둡니다.
Cancel Action
같은 Target/Handle + Reason. 특정 핸들을 직접 취소하며 자동 취소 규칙 선택과 별개입니다.
Cancel Actions By Reason
관리자 전체 중 해당 사유의 취소 규칙에 맞는 행동들을 취소합니다.
Cancel All Actions
모든 행동 취소. 공격 하나만 중단할 때 남용하지 않습니다.

이미 취소된 콜백에서 또 End Action을 호출하지 않습니다. 빈 핸들/다른 적의 핸들/이미 종료된 핸들은 정상 종료가 실패합니다. End Action은 Actor 삭제가 아닙니다.

01선딜 · 후딜 · 액션에 묶인 대기
프로젝트 노드Action Delay

현재 행동이 유지되는 동안 기다리고, 시간이 끝나면 Completed를 호출합니다. 액션이 먼저 종료/취소되면 대기 타이머도 정리되고 Cancelled로 빠집니다.

Action Component
Try Start Action에 사용한 같은 적의 관리자.
Action Handle
성공 후 저장한 활성 핸들. Timer Handle과 다른 타입입니다.
Duration
대기 시간(초). 양수로 선딜/후딜 지정. 0 이하이면 정상 활성 요청은 즉시 완료될 수 있습니다.
Completed
시간을 채운 뒤 실행할 효과/판정/다음 단계. 대기 뒤 공격은 반드시 여기에 연결합니다.
Cancelled
행동 종료/취소 또는 무효 요청 등에 따른 대기 중단. 늦은 공격을 하지 않고 자체 연출·변수만 정리합니다.
상단 즉시 실행 출력
노드 호출 직후 경로이며 대기를 마친 출력이 아닙니다. 선딜 뒤 피해를 연결하지 않습니다.
순차 대기 옵션: Try Start Action Success → Set AttackHandle → Action Delay
Completed → 대상/범위 재검사 → 피해 또는 빗나감 → End Action
Cancelled → 콘텐츠 정리만

선딜→피해→후딜을 모두 같은 행동으로 묶으려면 첫 Completed에서 피해를 주고 다시 Action Delay(같은 핸들) 후 End Action을 호출합니다. 첫 선딜 완료 자체가 액션을 종료해 주지는 않습니다.

언리얼 기본 · 비교일반 Delay / Set Timer By Event와 구분

새 공격의 예약은 Set Action Timer by Event를 사용하세요. 실제 액션 취소 때 자동 제거됩니다. 기존 일반 Delay / Set Timer by Event는 Action Handle을 모르므로 수동 정리와 콜백 방어가 필요합니다.

기존 일반 Timer 사용 시
Return Value의 Timer Handle 저장 → 취소/정리에서 Clear and Invalidate Timer by Handle. 콜백에서도 생존·활성 행동 확인.
Pause / Unpause
정지한 타이머를 보존/재개. Clear로 없앤 타이머를 복구하지 않습니다.
AI 판단 Timer
공격 대기와 별개의 반복 판단 주기. 액션이 끝났다고 판단 루프를 영구 종료하지 않도록 역할을 분리합니다.

BeginPlay의 일회성 초기화, 함수의 동기 반환, 비동기 대기 콜백은 서로 다릅니다. 기다려야 하는 공격 단계는 Event Graph의 이벤트/비동기 흐름으로 구성하세요.

02피해 · 원 판정 · 히트박스 · 돌진
프로젝트 노드Apply Combat Damage

현재 대상에게 공통 공식의 직접 피해를 요청합니다. 근접·원형·투사체가 대상을 찾은 뒤 호출하는 노드이며, 이 노드만으로 범위를 탐색하지 않습니다.

Request.Attacker / Target
공격한 적 / 현재 맞힐 Actor.
Base Damage / Attack Power Coefficient
고정 기본값과 최종 공격력 계수. 공격력 비례만 원하면 Base Damage=0, 계수=원하는 배율. 공통 방어·증폭 등 후속 계산은 별도로 적용됩니다.
Damage Name
동일 이름 재피격 제한 키. 기본 Damage Name Interval=0.2초, 요청별 변경/Ignore Damage Name Interval 옵션 가능. 실제 범위·출처와 구분합니다.
Source
Category / Source Id / Display Name 출처 정보. 액션/상태 핸들과 다른 역할.
Return Value
Damage Result. 실제 성공/회피/차단 등 결과와 피해·Hit Context를 담습니다.

전체 피해 입력 핀·공식 보기. Try Start Action 성공이 피해 성공을 의미하지 않습니다.

프로젝트 노드Apply Stagger And Groggy Damage From Result

직접 피해 결과를 받아 성공한 타격에 경직/그로기만 추가합니다. HP 피해를 다시 주지 않으며 성공 결과 외에는 내부적으로 무시합니다.

흰 실행선
Apply Combat Damage 뒤에 연결합니다.
Damage Result
Apply Combat Damage Return Value를 그대로 연결.
Base Stagger Damage / Stagger Multiplier
이 타격의 경직 수치·배율. 실제 경직 가능 여부는 대상 저항/슈퍼아머 등을 거쳐 판단됩니다.
Base Groggy Damage
그로기 기본 피해. 0이면 그로기를 깎지 않습니다.
Source / Effect Name
고급 입력의 출처·효과 이름. 피해 결과를 임의로 재조립할 필요는 없습니다.

같은 성공 결과를 여러 번 전달하는 자동 중복 방지 노드는 아닙니다. 타격당 한 번 호출하세요. DOT는 별도 Spec의 매 틱 경직/그로기 체크를 사용합니다.

판정 설계한 대상 원 판정 / 여러 대상 범위 판정

한 플레이어의 XY 거리 ≤ 반경 검사는 그 플레이어에게만 피해를 줍니다. 원 안의 모든 적대 대상을 자동으로 공격하는 AoE 스캔은 아닙니다.

한 대상
대기 완료 시 현재 대상 유효성 → 적대/생존 → 거리 재검사 → Apply Combat Damage.
여러 대상
엔진 Overlap/Trace 등으로 후보 목록 획득 → 같은 Actor 중복 제거 → 높이/거리 정책 → Can Damage Target → 각 대상 피해.
Sphere Overlap Actors
3D 구 후보 목록입니다. XY 원/원기둥과 같지 않으므로 평면 게임 높이 정책을 별도로 적용합니다.
Draw Debug Circle
개발용 범위 표시. 콜리전/피해 판정이 아니며 Shipping 시 게임 연출 표시를 보장하지 않습니다.

프로젝트 노드Spawn Actor · Initialize Hitbox · Register Action Hitbox

공격 충돌 영역을 별도 Actor로 만들 때 사용합니다. 액션이 끝나면 함께 없어질 판정인지, 발사 후 독립적으로 남을 투사체인지 먼저 결정합니다.

Spawn Actor From Class
Class/Transform 지정 → 생성 참조를 Is Valid 확인. 스폰 Owner만 지정해도 액션 수명이 자동 연결되지는 않습니다.
Initialize Hitbox
ARActionHitboxActor 자식 Target. In Action Handle=활성 행동, In Combat Source=공격 적, Hit Policy=대상 수락 정책, Lifetime=양수일 때 자체 수명. 내부에서 액션 Actor 등록까지 수행합니다.
Register Action Hitbox
Target=Action Component, Handle/Hitbox Actor → Bool. 등록 Actor는 액션 종료·취소 시 Destroy. 일반 Actor도 등록 가능.
Try Accept Target / On Hitbox Target Accepted
후보 수락 및 이벤트 통보. Once Per Target=이 히트박스당 각 대상 1회, Every Accepted Overlap=중복 기록으로 막지 않음.
Reset Accepted Targets
기록 초기화. 자동 피해 틱 간격이 아닙니다.

기본 Hitbox 클래스에는 충돌 모양·실제 피해가 완성되어 있지 않습니다. 자식에서 충돌 구성/활성화, 후보 탐지, 팀 검사와 피해 호출을 연결합니다. 초기화로 등록했다면 중복 Register는 필요 없습니다.

발사 직후 End Action을 호출할 예정이라면 등록된 투사체도 그때 삭제됩니다. 액션 이후 살아야 하는 투사체는 독립 수명/거리/충돌 종료를 구현하고 액션 삭제 목록에 넣지 마세요.

프로젝트 노드Request Action Move / Request Action Velocity

돌진처럼 행동에 속한 이동입니다. 일반 이동 잠금 중에도 가능하지만 All Movement 잠금은 우회하지 않습니다.

Target / Action Handle
적의 Movement Control Component / 같은 적의 활성 행동 핸들.
Direction
XY 정규화 방향. 내부에서 Z를 제거합니다.
Scale / Speed
Move는 이동 입력 크기, Velocity는 속도(cm/s). Velocity는 양수 유한값 필요.
Return Value
요청 허용 Bool. 충돌 결과·최종 도달을 뜻하지 않습니다.

일회 이동 입력이 지속 돌진을 완성하지는 않습니다. 실행 기간의 반복 입력/종료 정지/충돌과 이동 거리를 콘텐츠에서 관리합니다. 액션 종료가 기존에 부여한 모든 속도를 자동 초기화한다고 가정하지 않습니다.

03경직·기절 취소 · 알림 · 액션 소유 효과
규칙Cancel Rules · 취소 설정과 실제 CC 발생

취소 규칙은 해당 사유의 취소 요청이 왔을 때 행동을 중단할지 선택합니다. 피해를 받았다는 사실만으로 항상 경직 취소되는 것은 아닙니다.

Cancel On Stagger / Cancel On Stun
기본 true. 실제 경직 발생/취소 설정된 기절 상태 적용 시 공통 Character 경로가 취소를 요청합니다.
Cancel On Roll / Cancel On Basic Movement Input
기본 false. 대응 입력/행동 경로가 그 사유의 요청을 보내야 적용됩니다. AI 판단 루프가 자동으로 플레이어 입력을 만드는 것은 아닙니다.
Set Action Cancel Rules
이미 활성인 행동에 새 Rules 적용. Target=관리자, Handle=이번 행동. 공격 단계별 취소 허용 정책 변경에 사용.
사망 / 수동 취소
공통 사망은 모든 행동을 취소합니다. 직접 Cancel Action도 규칙 플래그로 막는 경로가 아닙니다.

슈퍼아머가 실제 경직을 막거나 CC 면역이 기절 적용을 막으면 해당 CC 발생 경로도 달라집니다. 기절 DA는 이동 차단뿐 아니라 Cancel Actions On Apply/Action Cancel Reason과 Blocks Skill Groups까지 확인합니다.

프로젝트 노드Bind Event To On Action Cancelled / On Action Ended

Action Component의 다중 구독 이벤트입니다. 적 BP는 직접 Event On Action Cancelled를 놓아 취소를 받습니다. 정상 종료/외부 구독에는 기존 Bind도 사용 가능합니다. BeginPlay에서 한 번 Bind하고, 필요한 경우 EndPlay에서 자신이 Bind한 이벤트만 Unbind합니다.

취소 후 직접 정리할 것: 경직·기절 등으로 실제 액션이 취소되면 시스템이 액션 생명주기와 액션 귀속 자원을 처리합니다. Set Action Timer by Event와 Action Delay는 자동 정리됩니다. 일반 Set Timer by Event·독립 Actor·공격 Bool·연출은 별도 정리가 필요합니다. On Action Cancelled에서 해당 실행 핸들을 확인한 뒤 일반 Timer Handle을 Clear and Invalidate Timer by Handle에 연결하고 자체 상태를 정리하세요. 모든 경직이 무조건 취소를 일으키지는 않습니다.

On Action Cancelled
Handle / Reason을 받습니다. Reason은 Stagger, Stun, Death, Manual 등. 콘텐츠 연출·자체 변수·외부 타이머를 정리.
On Action Ended
정상 End Action의 Handle을 받습니다. 취소마다 이 이벤트까지 함께 오는 것은 아닙니다.
핸들 비교
전달된 핸들의 Id 등 식별 정보를 저장한 이번 행동과 비교. 다른 행동 알림에 내 공격 상태를 초기화하지 않습니다.
알림 시점
행동 제거·액션 소유 자원 회수 후 알림. 이미 끝난 핸들을 다시 종료하지 않습니다.

Action Delay.Cancelled에도 같은 정리를 연결했다면 중복 호출에 안전하게 작성하세요. 아이템의 On Item Skill Cancelled는 아이템 실행 기록용 이벤트이며 적 직접 Try Start Action의 대체 이벤트가 아닙니다.

프로젝트 노드Apply Action Stat Modifier / Super Armor / CC Immunity

해당 행동이 끝날 때 함께 회수되어야 하는 일시 효과를 액션 소유로 적용합니다. 일반 Apply 노드와 수명 정책이 다릅니다.

공통 Target / Handle
적의 Action Component / 활성 Action Handle.
Apply Action Stat Modifier.Spec
Stat Type/Operation/Value/Duration/Source 등 보정 구조체. 행동 중 받는 피해 증가 같은 효과.
Apply Action Super Armor.Spec
슈퍼아머 지속시간/출처. 실제 경직 방어 보장용.
Apply Action CC Immunity.Spec
새 CC 적용에 대한 관리형 면역 지속시간/출처.
출력
효과 핸들 + Success. 무효 행동에 붙일 수 없습니다.

정상 종료/취소 때 귀속 효과를 회수하며, 유한 효과는 그 자체 수명으로 먼저 끝날 수도 있습니다. 공격 종료 후에도 유지할 버프라면 일반 Actor 대상 효과와 별도 회수 정책을 선택합니다.
