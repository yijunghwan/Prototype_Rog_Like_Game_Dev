01부모 클래스 · 기본 설정 · 컴포넌트

적 디테일·상속 설정 참고서에서 클래스 디폴트와 컴포넌트 설정을 먼저 확인하세요. Combat Team·AI·스탯·체력·경직·그로기 사용·충돌을 항목별로 설명합니다.

직접 이벤트바로 놓는 Character 이벤트 · Bind 없이 구현

ARBaseEnemy/ARPlayerCharacter 등 ARBaseCharacter 자식 BP에서 우클릭 검색 또는 Overrides로 구현합니다. Self의 알림이므로 BeginPlay Bind가 필요 없습니다. 기존 디스패처는 외부 구독용으로 유지됩니다. 동일 처리는 직접 이벤트와 Bind 중 한 방식에만 연결하세요.

취소 후 직접 정리할 것: 경직·기절 등으로 실제 액션이 취소되면 시스템이 액션 생명주기와 액션 귀속 자원을 처리합니다. Set Action Timer by Event와 Action Delay는 자동 정리됩니다. 일반 Set Timer by Event·독립 Actor·공격 Bool·연출은 별도 정리가 필요합니다. On Action Cancelled에서 해당 실행 핸들을 확인한 뒤 일반 Timer Handle을 Clear and Invalidate Timer by Handle에 연결하고 자체 상태를 정리하세요. 모든 경직이 무조건 취소를 일으키지는 않습니다.

등장: Event BeginPlay
기존 엔진 이벤트 사용. 배치/스폰 Actor 모두 플레이 시작 시 실행. 부모는 BP BeginPlay 전에 알림 연결을 준비합니다.
Event On Character Death
Killing Damage 출력. 공통 사망 액션 취소·이동 잠금·상태 해제 뒤 실행. 자동 Actor 삭제는 아님.
Event On Groggy Gauge Depleted
출력 핀 없음. 자기 게이지의 실제 소진 때 호출. 복구 전 0 상태에서 매 프레임 반복되지 않음.
Event On Shield Broken
Previous Shield / Reason 출력. 피해 또는 수동 제거로 총 실드가 0이 된 경우. 파괴 기준.
Event On Damage Applied
Damage Result 출력. HP/실드 피해 적용 뒤. 피해 재적용 노드가 아니며 회피/차단은 이 성공 알림에서 제외.
Event On Action Cancelled
Action Handle / Reason. 행동·귀속 자원 회수 후 실행. 자기 핸들을 비교하며 이미 취소된 행동을 다시 종료하지 않음.
Event On Status Removed
Status 출력. 실제 상태 제거·공통 이동 잠금 갱신 후 실행. 자기 기절의 정확한 핸들 비교.

직접 이벤트에는 Target 입력이 없습니다. 일반 Actor에는 자동 제공되지 않으며, Health Component의 On Shield Broken 디스패처는 해당 컴포넌트 보유 Actor에서 구독 가능합니다.

실드On Shield Broken · 피해/수동 제거 · 총합 0

총 실드가 양수에서 0이 되는 한 번의 전이입니다. 여러 층 중 하나만 소진되고 합계가 남아 있으면 제외합니다. 기존 On Shield Changed는 추가·소비·제거·시간 만료를 계속 알립니다.

Previous Shield
작업 직전 총 실드량. 개별 실드 핸들 또는 최대 스탯이 아님.
Reason
Damage=피해 소진, Other=Remove Shield / Remove Shields By Source / Clear Shields 등 명시적 제거. 만료의 Changed도 Other일 수 있지만 Broken은 발생하지 않음.
제외
시간 만료, Ignore Shield로 실드를 남긴 체력 피해, 빈 실드 제거, 실패/오래된 핸들, 부분 소진/제거.
콜백 재진입
작업 직후 상태를 기준으로 파괴를 판정합니다. 콜백에서 새로 실드를 추가해도 원래 전이의 알림은 유지하고 새 실드는 원래 피해를 다시 받지 않습니다.

배치 제거의 총합 0 전이는 한 번만 알립니다. 파괴와 사망이 한 타격에서 발생할 수 있으므로 자신의 생존/행동 정책을 확인하세요. 이 이벤트만으로 실드 재생·기절·그로기가 자동 실행되지는 않습니다.

회복Restore Health / Mana / Stamina · 현재값 더하기

기존 현재 자원에 Amount를 더하고 최대치까지 제한합니다. 최대 스탯 보정이 아닙니다. Target=Actor, Amount=양수, Source=출처 구조체, Return Value=실제 회복량. 기본 적에는 Mana/Stamina 컴포넌트가 없으므로 필요 시 추가합니다.

90/100에서 20 회복 요청 → 현재값100, 반환값10. Restore Health는 부활 노드가 아닙니다. 힐·마나·스태미나 개별 핀 설명을 보세요.

부모 클래스ARBaseEnemy로 시작하기

기존 공통 전투·이동·CC 처리를 사용하려면 ARBaseEnemy 자식 BP를 만듭니다. ARBaseCharacter/APaperCharacter 기반이며 적 팀, ARAIController, 배치/스폰 시 AI 자동 소유 설정을 기본으로 갖습니다.

  1. Blueprint Class 생성 시 모든 클래스에서 ARBaseEnemy를 선택합니다.
  2. Class Defaults와 상속 컴포넌트에서 체력·스탯·그로기 설정을 확인합니다.
  3. 외형 Sprite/Flipbook 또는 별도 Mesh를 추가합니다. 외형 스케일과 Capsule 충돌 크기는 따로 확인합니다.
  4. 레벨에 배치하고 Play로 확인합니다. 장애물 우회가 필요하면 경로 이동 설정도 합니다.

일반 Actor에 메시만 붙인 것과는 다릅니다. 태그 이름만 Enemy로 붙여도 공통 전투 인터페이스·컴포넌트·사망 처리가 생기지는 않습니다.

프로젝트 노드Get … Component · 적 자신의 관리자를 얻기

ARBaseCharacter의 조회 노드입니다. Target=적 Self. 반환 참조를 타입에 맞는 변수로 캐시하면 긴 선 대신 Get 변수를 사용할 수 있습니다. 캐시는 BeginPlay에서 준비하고, 다른 적/플레이어의 컴포넌트와 섞지 마세요.

Get Stats Component
기본/최종 스탯 조회·보정.
Get Health Component
현재 체력·실드·Is Dead 등 생존 정보.
Get Action Component
Try Start Action / End Action / Action Delay에 연결할 관리자.
Get Movement Control Component
일반 이동·액션 이동·정지·잠금.
Get Stagger Component
경직·슈퍼아머·그로기 게이지와 이벤트.

Blueprint의 Self는 적 Actor입니다. Component 노드의 Target은 Actor가 아니라 위 조회 결과입니다. Actor를 받는 공통 라이브러리 버전과 혼동하지 마세요.

에디터 설정Class Defaults / Base Stats / Use Groggy Gauge

Class Defaults는 새로 생성되는 이 클래스 인스턴스의 기본값입니다. 레벨에 배치된 인스턴스의 개별 덮어쓰기는 별도이므로, 클래스 변경 후 기존 배치 객체도 확인하세요.

Stats Component → Base Stats
AttackPower, MoveSpeed, MaxHealth, MaxGroggy 등 기본 스탯. MoveSpeed는 공통 CharacterMovement의 MaxWalkSpeed에 연결됩니다.
Stagger Component → Use Groggy Gauge
그로기를 사용하는 적이면 켭니다. MaxGroggy와 회복 스탯도 함께 설정합니다.
AI Controller Class / Auto Possess AI
기본 ARAIController와 Placed in World or Spawned 경로를 유지하거나, 동일 공통 규칙을 지원하는 컨트롤러를 선택합니다.
Tick / Collision / Physics
Event Tick을 쓸 경우 시작 Tick이 활성인지 확인합니다. 외형 Mesh의 Simulate Physics는 의도 없이 켜지 않습니다. 이동 충돌은 Capsule 및 CharacterMovement 기준으로 확인합니다.
02대상 선택 · 거리 · 생존 검사
언리얼 기본Get Player Pawn / Is Valid

간단한 로컬 테스트에서 Player Index 0의 Pawn을 가져와 TargetActor 변수에 저장합니다. 멀티플레이 타깃 선택·인지 범위·시야 검사까지 해 주는 노드는 아닙니다.

Player Index
로컬 플레이어 인덱스. 0이 항상 모든 게임 상황에서 유일한 공격 대상이라는 뜻은 아닙니다.
Return Value
Pawn 참조. 플레이어 생성 전/교체/사망·파괴 시 비어 있거나 오래된 참조일 수 있습니다.
Is Valid
참조가 현재 사용 가능한 UObject인지 확인합니다. 살아 있는 적대 대상인지까지 판정하지 않습니다.

대상 소멸 시 재탐색하고, 공격 대기 완료 시에도 다시 검사하세요. Actor 참조의 Is Valid와 Action Handle의 Is Action Active는 서로 다른 검사입니다.

프로젝트 노드Can Damage Target

현재 시스템에서 두 Actor 사이에 피해 요청이 가능한 대상 관계인지 확인합니다. 거리·벽·회피 확률·무적·실제 피해량을 모두 보장하는 명중 판정은 아닙니다.

Attacker
공격하는 적 Self.
Target
공격 후보 Actor.
Return Value
전투 대상 관계 검사 통과 여부 Bool.
Failure Reason
무효 대상·같은 팀·사망 등의 요청 실패 이유.

대상 선정/피해 직전 필터로 사용하고, 실제 피해 결과는 Apply Combat Damage의 Return Value로 확인합니다. 일반 Actor Tag가 아니라 공통 전투 팀/대상 인터페이스 정책이 적용됩니다.

언리얼 기본 · 계산Get Actor Location · 거리/방향 계산

Get Actor Location(Target=각 Actor)은 월드 위치를 반환합니다. 추적 방향은 대상 위치 − 적 위치, 평면 거리 판정은 두 위치 차이의 Z를 0으로 만든 뒤 Vector Length 또는 XY 길이를 사용합니다.

방향 Vector
이동할 방향. 목적지 월드 좌표 자체를 Direction에 넣지 않습니다.
거리 Float
언리얼 기본 거리 단위는 cm. 3m 반경은 300cm이며 지름은 600cm입니다.
평면/입체 정책
XY 비교는 Z를 무시합니다. 층 구분·높이 제한이 필요하면 별도 Z 범위나 3D 거리 조건을 추가합니다.
판정 기준
Actor 원점 거리와 콜리전 표면 거리는 다릅니다. AI Acceptance Radius도 단순 중심 거리와 같다고 가정하지 않습니다.

순수 조회 노드는 연결된 시점의 값을 읽습니다. 선딜 시작 위치를 고정하려면 변수에 저장하고, 현재 위치 기준 공격이면 완료 시 재조회하세요.

노드Apply Crowd Control · 그로기 소진 반응

소진 이벤트 자체는 기절을 만들지 않습니다. 간편 CC 노드로 자기 기절을 적용하고 성공 핸들을 저장합니다.

Event On Groggy Gauge Depleted → Apply Crowd Control
Target=Self / CC Type=Stun / Duration=원하는 초
Success → Return Value를 GroggyStunHandle에 저장

정확한 고정 3초를 의도하면 Affected By Tenacity를 해제합니다. CC 면역 등에 의해 실패할 수 있으므로 실패 시 게이지 복구/행동 정책도 정하세요.

CC 전체 핀과 상태 갱신은 간편 CC 참고서, 실제 종료 뒤 게이지 복구는 On Status Removed를 보세요. 게이지를 즉시 최대값으로 복구할지, 기절 종료 때 복구할지는 콘텐츠 정책입니다.

프로젝트 노드On Groggy Gauge Depleted / On Groggy Changed

Stagger Component의 다중 구독 이벤트입니다. 적 BP는 직접 Event On Groggy Gauge Depleted를 놓아 구현합니다. 외부 구독과 게이지 변화량은 기존 Bind 방식도 지원합니다. 게이지가 없어졌다고 모든 적이 자동으로 3초 기절하는 기본 구현은 아닙니다.

Use Groggy Gauge
Stagger Component 설정을 켜고 MaxGroggy를 양수로 지정합니다.
On Groggy Gauge Depleted
직접 이벤트는 출력 핀 없이 Self의 소진을 통보. 디스패처는 Target Actor 출력. 소진 반응으로 자기 기절 상태 적용/연출을 호출.
On Groggy Changed
Target / Current / Maximum / Delta. 게이지 HUD나 단계 반응에 사용.
Reset Groggy Gauge
Target=Stagger Component, New Current Value=-1이면 최대치 복구. 사용자 값으로 초기화도 가능.

일반 HP 피해만으로 그로기를 줄이지 않습니다. 공격 측에서 양수 그로기 피해를 전투 결과 경로에 연결해야 합니다. 소진 이후 복구 시점은 콘텐츠가 정합니다.

프로젝트 노드On Status Removed · 정확한 기절 종료에 복구

직접 Event On Status Removed 또는 기존 Bind 알림으로 실제로 해당 기절이 사라졌을 때 그로기 게이지를 복구합니다. 따로 만든 3초 타이머보다 조기 해제·갱신·강인함 변동 정책과 연결하기 좋습니다.

이벤트 출력
직접 이벤트는 Status(FARStatusEffectView), 디스패처는 Target / Status. Status에는 Handle, Status Tag, Definition, Source, Remaining Time이 있습니다.
비교
Status.Handle.Id와 저장 GroggyStunHandle.Id 비교 → 일치할 때만 처리. 아무 상태 제거에 무조건 게이지를 초기화하지 않습니다.
복구
Health.Is Dead=false 등 생존 검사 → Reset Groggy Gauge(-1) → 필요 시 AI 판단/경로 재요청.
이동 해제
상태 제거의 공통 처리에 맡기고 Can Basic Move를 다시 확인합니다. 다른 잠금까지 강제로 지우지 않습니다.

On Status Added/Updated/Removed는 상태 전체의 변화입니다. 같은 상태 갱신·사망 시 일괄 상태 해제도 고려하세요. Apply Status Effect 실패 때 유효한 저장 핸들이 없으면 별도 복구 분기를 설계해야 합니다.

04사망 · Actor 삭제 · 자체 자원 정리
프로젝트 노드Event On Character Death / 기존 Bind 알림

ARBaseCharacter의 사망 알림입니다. 적 BP는 직접 Event On Character Death를 놓고 연결합니다. 기존 Bind는 외부 구독에도 유지됩니다. 동일 처리를 양쪽에 중복 연결하지 않습니다.

Character / Self
직접 이벤트는 죽은 적 Self에서 실행. 디스패처는 Character 참조 출력.
Killing Damage
죽음을 만든 Damage Result. 연출·기록 등에 활용.
공통 사망 처리
먼저 모든 액션 취소(Death), 움직임 정지/사망 잠금, 상태 정리가 실행되고 On Character Death가 통보됩니다.
콘텐츠 처리
드롭/점수/사망 연출/삭제는 적 콘텐츠에서 결정합니다. 이 알림 자체가 자동 Destroy Actor는 아닙니다.

즉시 삭제면 이벤트 → Destroy Actor(Self). 사망 애니메이션을 보여주려면 살아 있는 Actor 수명과 공격 불가 상태를 유지한 채 연출 완료 후 삭제합니다.

언리얼 기본Destroy Actor / Set Life Span / Event EndPlay

엔진 제공 Actor 수명 노드입니다. 체력 사망과 월드에서 제거되는 시점은 구분합니다.

Destroy Actor.Target
삭제할 적/투사체 Actor. Self 삭제면 월드에서 제거됩니다.
Set Life Span
Actor의 삭제까지 남은 수명(초). 공격 선딜이나 액션 종료 노드가 아닙니다.
Event EndPlay
Actor가 파괴되거나 월드 종료 등으로 떠날 때의 정리. 사망 없이 제거될 수도 있으므로 자체 타이머/외부 구독 정리를 여기도 고려합니다.

삭제된 적의 늦은 콜백은 실행하지 않도록 참조·생존·활성 행동을 검사합니다. 액션 귀속 Actor는 자동 회수되지만 독립 투사체/외부 객체는 별도 수명 정책이 필요합니다.

시간 그룹 · 기능과 설정

World와 Player라는 시간 그룹이 있습니다. 선택형 기본값은 World이며 게임 Pause 시 두 그룹 모두 멈춥니다. 시간 기준은 아이템/액션의 자동 정리 수명과 별개입니다.

Try Start Action의 Request → Time Group이 Action Delay의 기준이며, Set Action Timer by Event에는 별도 Time Group 핀이 있습니다. 일반 엔진 타이머·AI 이동은 World 시간입니다. 그룹 선택은 CC·이동 가능 검사나 취소 규칙을 바꾸지 않습니다.
