액션 핸들·생명주기·정리 책임

아이템과 적이 공유하는 종료 계약입니다. 취소 이벤트의 용도 바로 아래에서 자체 타이머 정리까지 확인할 수 있습니다.

노드의 용도 → 연결 대상 → 입력·출력 → 정리 책임 순서로 확인합니다. 구조체는 설명 아래에서 펼쳐 보거나 Blueprint의 Split Struct Pin / Make 노드로 연결할 수 있습니다.

식별값

취소 이벤트 · 용도 아래에 정리 연결
아이템 직접 이벤트On Item Skill Cancelled

아이템 런타임에서 실제 실행했던 자기 스킬이 취소됐을 때 받습니다. 직접 이벤트이며 별도 Bind가 필요 없습니다.

취소 후 직접 정리할 것: 경직·기절 등으로 실제 액션이 취소되면 시스템이 액션 생명주기와 액션 귀속 자원을 처리합니다. 하지만 Set Timer by Event로 만든 별도 타이머·독립 Actor·공격 Bool·연출까지 자동 회수하지는 않습니다. On Item Skill Cancelled에서 해당 실행의 핸들을 확인한 뒤, 저장한 Timer Handle을 Clear and Invalidate Timer by Handle에 연결하고 자체 상태를 정리하세요. 모든 경직이 무조건 취소를 일으키지는 않습니다. Action Delay 내부 대기는 자동 정리되며, 정상 완료의 자체 정리는 별도 완료 경로에서 처리합니다.

Skill Id
취소된 아이템 내부 스킬. Switch on Name으로 정리 분기.
Action Handle
취소된 특정 실행. 저장 핸들과 비교해 오래된 콜백이 새 실행을 지우지 않게 합니다.
Reason
Stagger / Stun / ItemRemoved / Death / Manual 등 실제 취소 사유.

정상 End Action·사전 검사 실패·실행 전 거래 롤백에는 이 스킬 취소 알림이 오지 않습니다. 이미 취소된 액션을 다시 End Action하지 않습니다.

캐릭터 직접 이벤트On Action Cancelled

ARBaseCharacter 자식(적/플레이어)에서 자기 행동 취소를 직접 받습니다. 일반 Actor는 보유한 Action Component의 디스패처를 구독해야 합니다.

취소 후 직접 정리할 것: 경직·기절 등으로 실제 액션이 취소되면 시스템이 액션 생명주기와 액션 귀속 자원을 처리합니다. 하지만 Set Timer by Event로 만든 별도 타이머·독립 Actor·공격 Bool·연출까지 자동 회수하지는 않습니다. On Action Cancelled에서 해당 실행의 핸들을 확인한 뒤, 저장한 Timer Handle을 Clear and Invalidate Timer by Handle에 연결하고 자체 상태를 정리하세요. 모든 경직이 무조건 취소를 일으키지는 않습니다. Action Delay 내부 대기는 자동 정리되며, 정상 완료의 자체 정리는 별도 완료 경로에서 처리합니다.

Action Handle
관리자가 취소한 실행. 자기 공격 핸들과 비교합니다.
Reason
취소 사유. 특정 사유만 정리할지 정책을 정하되 모든 실제 취소 경로에 필요한 정리를 빠뜨리지 않습니다.

한 처리에 직접 이벤트와 Bind를 중복 연결하지 않습니다. Action Delay.Cancelled에도 같은 정리를 연결했다면 중복 호출돼도 안전하게 구성합니다.

별도 Timer를 쓸 때 연결 순서
언리얼 기본Clear and Invalidate Timer by Handle

예약된 Timer를 제거하고 보관한 핸들을 무효화합니다. Pause처럼 재개를 위해 보존하는 동작이 아닙니다.

Handle
Set Timer by Event의 Return Value를 저장한 Timer Handle 변수. Action Handle을 넣는 곳이 아닙니다.
시작: Set Timer by Event → Return Value를 Timer Handle 변수에 저장
취소 이벤트: 실행 핸들 비교 → Clear and Invalidate Timer by Handle → 자체 상태 초기화
콜백: 대상 Is Valid + Is Action Active 검사 → 후속 효과

Pause / Unpause는 기존 타이머를 보존·재개할 때 사용합니다. 취소된 스킬의 늦은 공격을 막으려면 Clear합니다. Clear한 Timer는 Unpause로 되살릴 수 없습니다. 판단 루프용 Timer와 공격용 Timer를 구분하세요.

아이템은 On Item Unregistered, Actor는 Event EndPlay에서도 필요한 자체 정리를 처리합니다. 정상 완료에서는 Timer의 반복 여부에 따라 직접 Clear하고 End Action을 호출합니다.

액션 대기는 Action Delay 우선
노드Action Delay

선딜·후딜이 액션 수명에 묶여야 한다면 일반 Delay/Timer보다 간편합니다.

Action Component / Action Handle
이번 실행의 같은 관리자와 활성 핸들.
Duration
초 단위 대기 시간.
Completed
시간을 채운 후 효과/판정/다음 단계. 여기서 정상 End Action까지 이어갑니다.
Cancelled
대기 중 End/Cancel 또는 무효 요청. 공격하지 않고 자체 정리만 수행합니다.

상단 즉시 실행 출력은 대기를 마친 출력이 아닙니다. Action Delay의 Cancelled는 정상 End에서도 올 수 있으므로 취소 사유가 필요하면 실제 취소 이벤트를 사용하세요.

Cancel Rules · 종료와 강제 취소 구분
Cancel On Stagger / Cancel On Stun
기본 true. 해당 사유의 취소 요청을 받았을 때 현재 액션을 취소하도록 합니다. 꺼져 있다면 경직/기절이 생겨도 해당 이유로 이 액션이 자동 취소되지는 않을 수 있습니다.
Cancel On Roll / Cancel On Basic Movement Input
기본 false. 액션별 중단 정책을 설정합니다.
Cancel Action
특정 핸들을 직접 취소. 자동 사유 규칙과 별개의 명시적 요청입니다.
End Action
정상 종료 알림. 취소 이벤트를 대신 발생시키는 노드가 아닙니다.
시간만 끝내고 종료하지 않은 경우
일반 타이머 완료나 Action Delay.Completed만으로 액션이 끝나지 않습니다. End Action을 연결해야 합니다.
