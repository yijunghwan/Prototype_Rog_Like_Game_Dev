Action RogueLike · Blueprint 제작자용

아이템 런타임 기본 참고서

액티브·패시브 유물의 ARLoadoutItemInstance 자식 BP에서 쓰는 이벤트, 함수 노드, 구조체 핀을 실제 C++ 동작 기준으로 설명합니다. 무기도 같은 부모를 쓰지만 입력 슬롯·진화 규칙은 별개입니다.

아이템 데이터 에셋 제작 가이드 · 객체별 스탯 가이드 · 스킬 런타임·액션 핸들 가이드 · 이 문서는 런타임 그래프 편입니다.

시작등록·해제스탯 버프Spec의 모든 핀중첩·조회액티브 스킬슈퍼아머·CC 면역아이템 UI 상태픽업·상호작용점검

큰 항목과 각 노드를 눌러 펼칠 수 있습니다.

00 먼저 알아둘 것
  • 유물 데이터 에셋은 ARItemDefinition, 실제 조건부 동작은 ARLoadoutItemInstance 자식 BP에 둡니다. 에셋의 Runtime Behavior Class에 그 BP 클래스를 지정해야 합니다.
  • 이 런타임 BP는 Actor가 아닌 UObject입니다. 장착 이벤트는 Event BeginPlay가 아닌 On Item Registered입니다.
  • Apply Item ... 노드의 Target = Self는 이 유물을 가진 플레이어에게 적용한다는 뜻입니다. 플레이어 입력 핀은 없습니다. 다른 플레이어·적에게 효과를 주려면 별도 일반 전투/스탯 노드를 사용합니다.
  • 데이터 에셋의 Default Stat Modifiers는 등록 시 자동 적용됩니다. 같은 기본 효과를 런타임 BP에서 다시 주면 중복됩니다.
여기서 말하는 버프 아이콘·중첩은 FARStatModifierSpec의 HUD 필드로 현재 기본 HUD에 표시됩니다. UI State Display Definitions는 유물 고유 게이지·숫자용 데이터 통로이며 현재 기본 HUD가 이를 자동으로 그리지는 않습니다.
01 장착·해제 이벤트와 소유자 조회
이벤트 On Item Registered

획득·장착이 성공해 런타임 인스턴스가 등록될 때 호출됩니다. 입력값은 없습니다. 데이터 에셋의 기본 스탯 수정치가 먼저 적용되고 나서 이 이벤트가 옵니다. 타이머 시작, 이벤트 구독, 초기 변수 설정에 사용합니다. 같은 유물을 두 개 얻으면 각각 별도 런타임 인스턴스에서 호출됩니다.

이벤트 On Item Unregistered

Reason 입력은 제거 이유(Replaced, Discarded, Evolved, OwnerDestroyed, Manual)입니다. 반복 타이머 해제, 직접 묶은 이벤트 해제, 직접 만든 별도 액터 정리 등에 사용합니다. 이 이벤트 뒤에 아이템이 소유한 수정치·슈퍼아머·CC 면역·아이템 UI 상태가 자동 정리됩니다.

타이머는 자동 정리 대상이 아닙니다. BP에서 보관한 Timer Handle은 이 이벤트에서 Clear and Invalidate Timer by Handle로 멈추세요.
조회 Get Item Owner / Get Item Definition / Get Instance Id / Is Registered
노드반환값사용처
Get Item OwnerARPlayerCharacter 참조조준 방향·플레이어 컴포넌트 등 다른 기능이 필요할 때. Apply Item Stat Modifier에는 필요하지 않습니다.
Get Item Definition현재 ARItemDefinition이름·아이콘·아이템 ID 같은 고정 정보를 읽을 때.

Is Registered참/거짓지연 콜백이 도착했을 때 아직 장착 중인지 확인할 때.
02 스탯 효과를 주고 제거하는 노드
일반 노드 · 기본값 증감 Apply Stat Modifier / Permanent Flat

아이템을 버려도 남겨야 하는 기본 스탯 변화나 돈 지급은 일반 Apply Stat Modifier를 사용합니다. Target=Get Item Owner(픽업에서는 Interactor), Spec Stat Type=원하는 스탯, Spec Operation=Permanent Flat, Spec Value=증감량입니다. 양수는 더하고 음수는 뺍니다.

버프 기록·타이머·반환 핸들이 없습니다. 성공해도 Return Value가 비어 있으므로 Success를 검사하세요. Duration/Source/HUD/Tenacity/Stack Group은 무시하고 Stack Only/Guarantee 옵션은 해제해야 합니다. 기본값이 바뀐 뒤 기존 퍼센트·배율과 안전 범위를 다시 적용합니다.

Money는 플레이어 전용 float 스탯, 기본0. 기본 잔액 부족 차감은 무변경 실패입니다. 임시 Money 보정은 영구 잔액으로 소비할 수 없습니다. 자동 결제·돈 UI·세이브·새 플레이어 객체로 이전은 구현하지 않습니다.

Apply Item Stat Modifier / Apply Action Stat Modifier / DA의 Default Stat Modifiers에서는 Permanent Flat을 거절합니다. 아이템 BP에서도 일반 노드를 사용하면 가능합니다. Flat + Duration=-1은 기존 무기한 버프이며 아이템 수명에 묶을 수 있습니다. 반복 습득·이벤트 재진입의 중복 지급 방지는 콘텐츠 책임입니다.

전체 핀·돈 차감·수명 규칙

호출 Apply Item Stat Modifier

이 유물을 가진 플레이어에게 스탯 수정치를 한 건 추가합니다. 그래프에서 Self 핀을 끌어 검색하면 찾기 쉽습니다. 아래 Spec 펼치기를 누르면 실제 핀 조작 순서와 모든 필드를 볼 수 있습니다.

입력/출력의미
Target 입력현재 아이템 런타임 객체. 보통 Self. 플레이어 캐릭터를 연결하는 자리가 아닙니다.
Spec 입력FARStatModifierSpec. 대상 스탯, 연산 방식, 값, 지속시간, 출처, HUD 표시, 보장 효과를 한데 묶은 설정입니다. 바로 아래 Spec 칸을 눌러 펼쳐 보세요.
Success 출력실제 추가에 성공했는지. 중첩 변수 증가나 후속 처리는 참일 때만 실행합니다.
Return Value 출력FARStatModifierHandle. 그 적용 1건을 조기 제거하거나 남은 시간을 조회할 때 저장합니다.
Spec 입력 누르면 펼쳐지는 핀 조작법 · 모든 세부 필드

일반·아이템·액션 노드의 전체 필드와 수명 비교

먼저 블루프린트에서 펼치는 방법

  1. Apply Item Stat Modifier 노드를 그래프에 놓습니다. 노드 왼쪽의 파란 Spec 핀을 우클릭 → Split Struct Pin(구조체 핀 분할)합니다.
  2. Spec Stat Type, Spec Operation 같은 개별 입력이 나타납니다. Spec Source만 뭉쳐 보이면 그 핀도 다시 우클릭해 분할합니다. 지금처럼 Spec Source Category, Spec Source Id, Spec Source Display Name이 보이면 끝까지 펼친 상태입니다.
  3. 드롭다운은 항목을 선택, 숫자·이름 칸은 직접 입력, 체크박스는 켜기/끄기, 핸들·아이콘 핀은 필요할 때 변수 또는 에셋 연결로 설정합니다. 아무 선도 연결하지 않은 핀은 화면에 적은 기본 입력값을 사용합니다.
  4. 설정만 해서는 효과가 생기지 않습니다. 왼쪽 흰색 실행 핀에 이벤트를 연결하고, 오른쪽 Success로 성공을 확인하세요. 핀을 다시 합치려면 우클릭 → Recombine Struct Pin을 사용합니다. 분할 대신 Make AR Stat Modifier Spec 구조체 노드를 연결해도 됩니다.
데이터 에셋의 Default Stat Modifiers는 장착 시 자동 적용됩니다. 런타임 Spec에는 조건부·시간제·반복 효과처럼 추가로 필요한 효과만 설정하세요.

① 어떤 스탯을 얼마나 바꾸는가

핀역할·왜 필요한가화면에서 어떻게 설정하나
Spec Stat Type수정할 스탯의 종류. 한 적용 건은 하나의 스탯을 대상으로 합니다. 다른 스탯도 바꾸려면 노드를 한 번 더 실행합니다.드롭다운에서 목적에 맞게 선택. 예: 최대 체력 효과라면 Max Health.
Spec Operation값을 고정치·합연산 %·곱배율 중 무엇으로 계산할지 결정합니다. Independent Damage Reduction은 피해 감소율 스탯만 사용할 수 있습니다.드롭다운에서 선택. 수치 그대로 더하려면 Flat.
Spec Value실제 입력 수치. Flat 1은 +1, Additive Percent 20은 +20%, Multiplicative 1.2는 ×1.2입니다. 독립 피해 감소의 50은 남은 피해를 절반으로 줄입니다.숫자 칸에 원하는 값을 입력. 예: 고정치 +5라면 5.0.
Spec Duration적용 수명. 양수는 그 초만큼, 음수는 직접 제거하거나 유물을 해제할 때까지. 0은 유효하지 않아 실패합니다.숫자 칸에 영구 효과는 -1.0, 5초 버프는 5.0.

일반 스탯 계산은 (기본값 + 모든 Flat 합) × (1 + 모든 AdditivePercent 합 ÷ 100) × 모든 Multiplicative 값의 곱입니다. 독립 피해 감소는 이 식과 별개로 피해의 남은 비율에 곱합니다.

② 어느 효과가 준 것인지 구분하기 — Source

핀역할·왜 필요한가화면에서 어떻게 설정하나
Spec Source Category출처 종류. 공통 Spec 구조체라 보이지만 Apply Item Stat Modifier에서는 C++가 아이템 종류에 따라 Weapon 또는 Relic으로 다시 지정합니다.유물 화면에는 Relic으로 둡니다. 다른 항목을 골라도 이 노드의 실제 분류를 바꾸는 용도로 쓰지 않습니다.
Spec Source Id효과의 묶음 이름. 같은 출처 분류와 같은 ID의 적용은 조회·버프 HUD에서 함께 집계됩니다. 아이템의 정수 Item Id와 다릅니다.이름 칸에 고유한 효과 이름 입력. 여러 효과를 따로 표시하려면 서로 다른 ID를 사용.
Spec Source Display Name사람에게 보여줄 출처명. ID와 달리 UI 문구입니다. 비워두면 아이템 데이터 에셋의 표시 이름으로 대체됩니다.선택 입력. 별도 출처명이 필요 없으면 비워도 됩니다.
Source Id를 비우면 코드가 이 런타임 인스턴스의 고유 ID를 사용합니다. 서로 다른 효과를 HUD에서 분리하려면 명시적인 별도 이름을 사용하세요. 같은 유물을 여러 개 보유하면 고정 이름끼리 합쳐 보일 수 있으므로, 독립 표시가 필요할 때는 인스턴스별 이름 생성이 필요합니다.

③ 중첩을 새로 쌓을지, 같은 중첩에 묶을지

핀역할·왜 필요한가화면에서 어떻게 설정하나
Spec Stack Only체크하면 스탯 변화 없이 중첩 기록만 추가합니다. 다른 노드에서 중첩 수를 읽어 조건을 처리할 때 사용합니다. 이 경우 무적·회피 보장을 동시에 줄 수 없습니다.체크박스. 스탯을 실제로 바꿀 때는 끄고, 숫자 중첩만 기록할 때 켭니다.
Spec Stack Group Handle이전 적용의 Return Value 핸들을 연결하면 여러 스탯 수정치를 같은 한 중첩으로 셉니다. 연결하지 않으면 이번 호출은 새 중첩입니다. 연결한 핸들은 같은 출처 분류·ID여야 하고 지속시간도 원래 그룹을 따릅니다.독립된 새 중첩이면 비워두고, 한 중첩에 여러 스탯을 묶을 때만 이전 핸들을 연결합니다.

Source Id가 같다는 사실만으로 하나의 스택이 되는 것은 아닙니다. Source Id는 화면·조회에서 묶는 이름, Stack Group Handle은 실제 중첩 단위를 정합니다.

④ 지속시간과 버프 아이콘

핀역할·왜 필요한가화면에서 어떻게 설정하나
Spec Affected by Tenacity시간제 효과라면 대상의 강인함이 지속시간을 줄이게 할지 선택합니다. 강인함이 100이면 적용되지 않을 수 있습니다. 영구 효과에는 의미가 없습니다.체크박스. 강인함이 지속시간에 영향을 줘야 할 때만 켭니다.
Spec HUDDisplay스탯 효과의 HUD 아이콘 표시 유형. Hidden은 안 보임, Buff는 버프, Debuff는 디버프입니다. 아이템 전용 UI State와 별개의 표시 경로입니다.드롭다운. 화면에 표시할지와 효과의 성격에 따라 선택합니다.
Spec HUDName아이콘 이름·툴팁. 비워두면 Source Display Name, 그것도 비우면 아이템 이름을 씁니다.텍스트 칸에 선택 입력. 필요한 표시 이름이 없으면 비웁니다.
Spec HUDIcon버프 아이콘 이미지. 데이터 에셋의 Display → Icon이 자동 복사되지 않기 때문에 별도 필드가 있습니다.에셋 선택기에서 Texture2D를 지정. 비우면 아이콘 틀에 이미지가 없습니다.

⑤ 100%를 보장하는 특수 옵션

핀역할·왜 필요한가화면에서 어떻게 설정하나
Spec Guarantee Invulnerability일반 감소율 계산과 별개로 무적 보장을 등록합니다. Stat Type = Overall Damage Reduction일 때만 허용됩니다. 공허 같은 시스템 피해 규칙은 별도입니다.체크박스. 무적 보장을 원할 때만 해당 Stat Type과 함께 켭니다.
Spec Guarantee Evasion일반 회피율 수치와 별개로 회피 보장을 등록합니다. Stat Type = Evasion일 때만 허용됩니다. 필중 기술까지 회피한다는 뜻은 아닙니다.체크박스. 회피 보장을 원할 때만 해당 Stat Type과 함께 켭니다.
설정 뒤에는 실행 핀을 연결하고 Success를 확인하세요. 같은 ID로 여러 번 적용하고 Stack Group Handle을 비우면 HUD에서는 한 효과의 여러 중첩으로 집계됩니다.

아이템 해제 시 성공한 수정치는 핸들별로 자동 회수됩니다. 이 노드로 준 효과를 Remove All Own Item Modifiers로 직접 지우지 않는 한 유물 수명에 묶입니다.

호출 Remove Own Item Modifier

Target = Self, Handle에는 이전 Apply Item Stat Modifier의 Return Value를 넣습니다. 반환 bool은 제거 성공 여부입니다. 이 아이템 인스턴스가 부여한 핸들만 제거할 수 있습니다. 예: 5초짜리 효과를 조건 만족 시 조기에 해제.

호출 Remove Stat Modifiers by Source — Category·Source Id로 버프 제거

핸들 대신 출처 분류와 ID가 일치하는 스탯 수정치 전부를 대상 캐릭터에서 제거합니다. 해당 수정치가 HUD에 버프로 표시 중이었다면 버프 표시도 함께 갱신됩니다. Remove Own Item Modifier와 달리 아이템 인스턴스의 Self를 대상으로 하는 노드가 아닙니다.

입력/출력연결 방법과 의미
Target 입력수정치가 적용된 캐릭터 Actor. 유물 런타임 BP에서는 Get Item Owner → Return Value를 연결합니다. Self를 연결하지 않습니다.
Category 입력추가 당시의 실제 Source Category와 같아야 합니다. 유물은 Relic, 무기는 Weapon입니다. Apply Item Stat Modifier는 이 분류를 아이템 종류에 맞게 지정합니다.
Source Id 입력추가 노드의 Spec Source Id와 같은 이름을 입력합니다. 아이템 데이터 에셋의 정수 Item Id가 아닙니다. 적용할 때 ID를 비웠다면 런타임 인스턴스의 고유 ID로 대체되므로 임의의 이름으로 제거할 수 없습니다.
Return Value 출력실제로 제거된 수정치 건수(int32). 0이면 대상, 분류, ID 또는 현재 적용 여부를 확인합니다.
Get Item Owner → Target · 추가할 때의 Category → Category · 추가할 때의 Spec Source Id → Source Id
이 노드는 그 유물만 골라 제거하지 않습니다. 같은 캐릭터에게 붙은 동일 Category·Source Id의 효과는 다른 유물이나 데이터 에셋의 기본 효과에서 왔더라도 모두 제거됩니다. 반복해서 적용·삭제하는 아이템에서 이 노드를 사용하면 런타임 객체가 보관한 소유 핸들 기록은 별도로 정리되지 않습니다. 인스턴스별 안전한 제거가 필요하면 Apply Item Stat Modifier의 Return Value를 보관하고 Remove Own Item Modifier를 사용하세요.
호출 Remove All Own Item Modifiers

Target = Self. 반환값은 실제 제거한 수정치 건수(int32)입니다. 데이터 에셋의 기본 수정치까지 포함해 이 아이템 소유의 모든 수정치를 지웁니다. 일부 스택만 지울 때는 사용하지 마세요. 재등록 없이 기본 효과가 자동 복구되지 않습니다.

03 중첩 수·최종 스탯을 조회할 때

이 절의 조회 노드는 Apply Item ...과 달리 Stats Component의 함수입니다. 런타임 BP에서 Get Item Owner → Get Stats Component를 거쳐 호출합니다. 단, 이 컴포넌트는 플레이어 전체 효과를 보므로 같은 출처 ID를 다른 아이템도 사용한다면 합쳐집니다.

조회 Get Modifiers By Source

입력: Category(유물은 Relic), 조회할 Source Id. 반환 구조체: Exists(존재), Stack Count(서로 다른 스택 그룹 수), Has Permanent(영구 건 존재), Longest Remaining Time(가장 긴 남은 시간, 영구가 있으면 -1). Stack Group Handle로 여러 수정치를 한 그룹에 묶었다면 수정치가 여러 건이어도 1중첩으로 셉니다.

같은 출처 ID를 여러 아이템이 공유할 수 있으므로, 한 유물 인스턴스만의 제한 횟수는 해당 BP의 정수 변수로 별도 관리하세요.

조회 Get Final Stat / Get Modifier Remaining Time / Get Visible Stat Effects
노드입력과 반환용도
Get Final StatStat Type → 현재 최종 float현재 최대 스태미나 등 계산이 끝난 값을 조건에 활용.
Get Modifier Remaining Time적용 핸들 → 성공 여부, 영구 여부, 남은 초특정 적용 건이 아직 남아 있는지 확인.
Get Visible Stat Effects입력 없음 → HUD에 표시되는 효과 목록UI에서 출처별 이름·아이콘·중첩 수·남은 시간을 읽을 때. 기본 HUD는 이 통로를 사용합니다.
Clear Modifiers와 위에서 설명한 Remove Stat Modifiers by Source는 플레이어 전체 효과를 대상으로 합니다. 특정 유물이 자기 효과만 정리할 때는 Remove Own Item Modifier 또는 아이템 해제 시 자동 회수를 우선하세요.
04 액티브 유물의 발동 스킬

스킬 등록 정보·비용·쿨다운·입력 방식은 데이터 에셋의 Skill Definitions에 둡니다. 런타임 BP는 조건과 실제 스킬 효과를 담당합니다. 패시브 유물이 입력 스킬을 갖지 않으면 이 절은 건너뛰세요.

조건 Can Execute Item Skill

입력 Skill Id는 데이터 에셋에서 등록한 이름. 출력 Return Value가 참이면 실행 가능, 거짓이면 해당 스킬을 실행하지 않습니다. Failure Tag는 거절 이유를 전달하는 출력값입니다. 이 함수는 부모 클래스에 기본 구현이 있으므로 조건이 필요할 때만 자식 BP에서 재정의합니다.

이벤트 Execute Item Skill

입력: Skill Id, Action Handle. 등록된 입력을 누르고 조건·자원·쿨다운·행동 시작이 통과하면 호출됩니다. BP는 이곳에서 공격 판정·연출·효과 노드를 실행합니다. 데이터 에셋의 자원 비용과 기본 쿨다운은 이 이벤트 전에 시스템이 처리하므로 BP에서 중복 소비시키지 마세요. 시전이 끝나면 소유자의 Action Component에서 받은 핸들로 End Action을 호출하고, 취소 시 정리가 필요한 타이머·연출은 행동 종료/취소 이벤트에 연결합니다.

이벤트 On Item Skill Cancelled

입력받는 정보: Skill Id, Action Handle, Reason. 이벤트 그래프에 직접 추가하며 Bind가 필요 없습니다. Loadout에서 실행된 이 아이템 인스턴스의 스킬이 취소되면 액션 자동 정리 후 호출됩니다. Switch on Name으로 스킬을 구분하여 자체 타이머·상태·연출을 정리합니다.

정상 End Action·사전 거절에는 호출되지 않습니다. 이미 취소된 핸들에 End Action을 다시 호출하지 않습니다. 아이템 해제 때의 실행 중 스킬 취소는 On Item Unregistered 전에 알립니다. Action Delay.Cancelled와 정리가 중복되지 않도록 책임을 정하세요. 스킬 취소 이벤트 상세

입력 경로 Direct Tag와 Active Relic Slot

Direct Tag는 IA→입력 태그와 동일 태그의 스킬을 연결하는 기존 방식입니다. Active Relic Slot은 플레이어의 Active Relic Slot Input Bindings에서 지정한 장착 칸 번호 + 해당 유물 내 스킬 번호로 실행합니다. 1번·2번 유물이 모두 로컬 Slot Skill Index = 1이어도 슬롯별 키로 구분됩니다. 물리 키는 IMC가 정하며 런타임 BP 안에서 고정하지 않습니다.

05 특수 보장 효과: 슈퍼아머·CC 면역
호출 Apply Item Super Armor / Remove Own Item Super Armor

Apply Item Super Armor 입력 Spec에는 Duration(음수면 직접 제거 전까지 유지)과 Source(분류·ID·이름)가 있습니다. 출력은 Success와 FARSuperArmorHandle입니다. 슈퍼아머는 경직을 막지만 그로기 피해나 다른 상태이상까지 모두 막지는 않습니다. 조기 종료 시 Remove Own Item Super Armor(Target=Self, Handle)의 반환 bool로 결과를 확인합니다. 아이템 해제 때 자동 회수됩니다.

호출 Apply Item CC Immunity / Remove Own Item CC Immunity

Apply Item CC Immunity 입력 Spec에도 Duration과 Source가 있습니다. 출력은 Success와 FARCCImmunityHandle입니다. 새 CC 상태이상 적용을 막으며 이미 걸린 것을 자동 해제하지는 않습니다. 조기 종료는 Remove Own Item CC Immunity(Target=Self, Handle)를 호출합니다. 아이템 해제 때 자동 회수됩니다.

시전 중에만 필요한 효과라면 Apply Action Super Armor / Apply Action CC Immunity를 사용해 행동 핸들의 수명에 묶는 편이 안전합니다. 이 경우 노드의 Target은 Item Self가 아니라 소유 플레이어의 Action Component입니다.
06 아이템 고유 UI 상태 노드 — 현재 표시 범위 주의

이 통로는 Spec HUDDisplay의 버프 아이콘과 다릅니다. 데이터 에셋의 UI State Display Definitions에 State Id, 표시 이름·아이콘·형식(Gauge/Number/SmallStack)을 미리 등록해야 합니다.

호출 Set Item UI State

Target=Self, State Id(데이터 에셋에 등록된 Gameplay Tag), Current Value, Maximum Value를 받습니다. 반환 bool은 등록된 ID로 갱신했는지입니다. 미등록 ID는 거절하고 로그 경고를 남깁니다. SmallStack에서 최대값이 6을 넘으면 숫자 방식으로 바뀝니다. 유물 자체의 수치를 갱신할 뿐 스탯을 변경하지 않습니다.

호출·조회 Remove Item UI State / Get Item UI States / On Item UI State Changed

Remove Item UI State(State Id)는 해당 상태를 지우고 성공 여부를 돌려줍니다. Get Item UI States는 현재 상태 배열을 돌려줍니다. On Item UI State Changed 이벤트에는 아이템 인스턴스 ID, 상태값, 제거 여부가 옵니다. 아이템 해제 때 등록된 상태는 자동 제거됩니다.

현재 기본 HUD는 아이템 UI State를 화면에 그리지 않습니다. 기본 HUD가 그리는 것은 스탯 버프·디버프 아이콘입니다. 아이템 UI State 값은 장비/인벤토리 조회와 변경 이벤트로 전달되지만, 무기·액티브 슬롯·패시브 전용 위젯은 추후 제작해야 합니다.
07 막힐 때 확인할 것
현상우선 확인
On Item Registered가 안 옴데이터 에셋의 Runtime Behavior Class가 이 BP인지, 실제 획득·장착이 성공했는지.
Apply Item Stat Modifier의 Success=false장착 상태·소유 플레이어·Stats Component 유효성, Duration=0 여부, 잘못된 보장 효과/독립 피해 감소 조합, 잘못된 Stack Group Handle.
HUD에 버프 아이콘이 안 보임HUDDisplay=Buff인지, HUDIcon을 지정했는지, 실제 적용 성공 여부. 데이터 에셋의 기본 아이콘은 자동 재사용되지 않습니다.
예상보다 중첩 수가 크게 나옴서로 다른 효과가 같은 Source Id를 공유하는지, Stack Group Handle이 의도대로 연결됐는지 확인하세요.
Remove Stat Modifiers by Source로 지워지지 않음Target에 수정치를 받은 캐릭터가 연결됐는지, Category와 Source Id가 적용 당시의 실제 값과 둘 다 일치하는지 확인하세요. Return Value=0이면 일치하는 활성 수정치가 없다는 뜻입니다.
버린 뒤에도 타이머가 실행됨On Item Unregistered에서 해당 Timer Handle을 해제했는지.
같은 패시브 두 개의 스택이 합쳐 보임두 인스턴스가 동일한 Source Id를 쓰는지. 인스턴스별 UI 구분이 필요하면 고유 Source Id를 설계하세요.
