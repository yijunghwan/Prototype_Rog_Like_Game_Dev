아이템 스킬 런타임 참고서

ARLoadoutItemInstance 자식 블루프린트에서 아이템의 스킬 조건·실행·대기·효과·종료를 구현할 때 옆에 두고 찾는 문서입니다. 노드의 호출 시점과 연결 대상, 액션 핸들의 수명 기준을 정리합니다.

아이템 에셋 제작 가이드 · 아이템 런타임 노드 가이드 · 객체별 스탯 가이드 · 데미지 노드·공식 참고서 · 적 제작 참고서

범위: 플레이어가 소유한 무기·유물의 아이템 스킬. 소비형 아이템의 별도 사용 경로와 적 AI의 직접 액션 시작·관리는 다루지 않습니다.

항목과 노드를 눌러 자세히 볼 수 있습니다.

00 적용 범위와 실행 계약

아이템 런타임은 월드에 배치하는 Actor가 아닌 UObject 인스턴스입니다. DA의 Runtime Behavior Class에 BP 클래스를 지정하고, Skill Definitions의 스킬을 해당 런타임에서 구현합니다.

플레이어 입력Input Action·실제 키·Input Tag 요청, 장착 슬롯 요청아이템 런타임에서 키를 하드코딩하지 않음

아이템 런타임 BP아이템 고유 사용 조건, 실제 효과, 자체 상태·연출, 정상 종료·취소 정리이 참고서의 대상

사전 검사는 비용·쿨다운·액션 시작 전이고, Execute Item Skill은 그 처리 이후의 실행 통보입니다. 둘 다 BP로 작성하지만 호출 시점과 책임이 다릅니다.

우선도와 거래 규칙

같은 우선순위 묶음·누적 비용·중단 규칙 상세

Input Priority는 작은 숫자부터 검사합니다. 같은 우선도의 후보는 한 그룹이며, 하나라도 조건이나 누적 비용 검사에 실패하면 그 그룹과 더 큰 숫자의 그룹은 진행하지 않습니다. 앞서 통과한 더 작은 숫자 그룹은 실행될 수 있습니다. 최종 통과한 후보의 MP·스태미나 비용을 합산해 지불합니다.

현재 Loadout은 활성 스킬 그룹이 남아 있으면 새 스킬 요청을 차단합니다. 정상 완료 경로의 End Action 누락은 후속 입력 차단으로 이어질 수 있습니다. Execute Item Skill 이후의 콘텐츠 실패는 이미 지불한 DA 비용·쿨다운을 자동 환불하지 않습니다.

01 실행 전 조건 검사 · 함수 오버라이드
오버라이드 Can Execute Item Skill

역할: 아이템 고유 조건을 비용 지불·액션 시작 전에 검사합니다. C++에 호출 위치가 준비되어 있으므로 아이템 제작자가 C++을 수정할 필요는 없습니다.

입력/출력연결 기준
Skill Id 입력검사 대상 스킬. 여러 스킬이 있으면 스킬별 조건을 구분
Return Value 출력True: 아이템 고유 조건 통과. False: 이번 후보 거절. True여도 공통 액션·비용 검사에서 거절될 수 있음
Failure Tag 출력실패 이유용 Gameplay Tag. 선택 사항이며 현재 기본 Loadout은 이를 자동 HUD 메시지로 표시하지 않음

작성 위치

  1. 아이템 런타임 BP의 내 블루프린트 → 함수 → 오버라이드 → Can Execute Item Skill을 선택합니다. 이미 재정의되어 있으면 그 함수를 엽니다.
  2. 보라색 함수 시작점의 Skill Id로 조건을 구분하고, 조회·비교·AND/OR 등의 노드로 판정합니다.
  3. 흰 실행 경로를 Return Node로 연결하고, 조건 결과도 Return Value의 값 입력에 연결합니다. 여러 반환 경로를 사용할 수 있습니다.

일반 함수에 같은 이름을 붙이는 것과 부모 함수를 오버라이드하는 것은 다릅니다. 보라색 시작 노드는 호출받았을 때 실행할 내부 구현, 초록색 호출 노드는 그 함수의 결과를 읽는 곳입니다. 이벤트 그래프에서 직접 호출하지 않아도 시스템이 사전에 호출합니다.

기본 부모 구현은 등록 상태를 반환합니다. 이 기본 검사를 유지하려면 Parent: Can Execute Item Skill.Return Value AND 아이템 고유 조건을 최종 반환값에 사용합니다. 부모의 Failure Tag만 연결하고 불리언을 사용하지 않으면 부모의 허용 판정을 결합한 것이 아닙니다.

조건은 읽기 전용으로 구성합니다. 이 함수에서 자원 소비·효과 적용·액션 시작·지연 대기를 하지 않습니다. 아직 액션이 없으므로 End Action도 필요하지 않습니다. 모든 스킬이 이 함수로 들어오므로 한 스킬의 조건을 전체 반환값으로 쓰면 다른 스킬도 거절될 수 있습니다. 검사가 없는 스킬을 허용할지 거절할지는 기획에 맞게 결정합니다.

조건을 이벤트 그래프에서 다시 확인하는 것은 실행 중 상태 변화에 대한 방어입니다. 하지만 그때 거절해도 사전 검사 시점으로 되돌아가지 않습니다. 같은 함수 내부에서 자기 자신의 호출 노드를 사용하면 재귀 호출이 되므로 주의하세요. Parent 호출은 부모 구현을 호출합니다.

02 실행 이벤트 · 핸들 · 연결 대상
이벤트 Execute Item Skill

역할: 시스템이 승인하고 시작한 스킬의 실제 동작을 구현하는 입구입니다. DA 비용·쿨다운을 같은 이유로 다시 처리하거나 Try Start Action으로 동일 행동을 다시 시작하지 않습니다.

출력사용처
흰 실행 출력Skill Id 분기 후 실제 동작 실행
Skill IdSwitch on Name의 Selection 또는 스킬별 조건 분기. DA의 Skill Id와 일치
Action Handle이번 행동을 관리·대기·종료하는 데 사용. 지연 동작은 실행별로 보관

즉시 완료되는 경로는 받은 핸들을 End Action에 전달합니다. 대기하는 경로는 완료 콜백까지 같은 핸들을 유지합니다. 콘텐츠 실패 경로에서도 시작된 행동이 남지 않도록 종료 또는 취소를 처리합니다. 처리하지 않는 Skill Id의 실행 경로도 남겨 두지 않습니다.

기본 연결 Switch on Name / Set·Get Action Handle

Switch on Name은 전달된 이름으로 실행 분기를 선택하는 엔진 기본 노드입니다. 자체 비용·쿨다운·액션 관리 기능은 없습니다.

연결기준
Execute Item Skill 실행 → Switch 실행언제 분기할지

스킬 분기 실행 → 해당 핸들 변수 Set 실행그 스킬의 핸들을 저장하는 시점
이벤트 Action Handle → Set의 값 입력저장할 실제 핸들. 흰 실행선만 연결해서는 저장되지 않음
저장한 핸들 Get → Action Delay·Apply Action·End Action의 Handle처음 시작된 행동을 계속 사용

핸들 변수 타입은 ARAction Handle입니다. 동일 인스턴스의 여러 스킬이 한 입력 그룹에서 실행될 수 있으므로 한 변수에 무조건 덮어쓰지 않습니다. 스킬별 변수 또는 실행별 문맥으로 보관합니다. 재진입을 허용하는 별도 콘텐츠라면 스킬별 변수 하나로도 충분하지 않을 수 있습니다.

빈 핸들, 다른 실행으로 덮어쓴 핸들, 다른 소유자의 관리자에 전달한 핸들은 동일 액션을 가리키지 않습니다. Action Delay가 즉시 Cancelled로 빠지거나 효과·종료 요청이 실패할 수 있습니다.

03 정상 종료 · 직접 취소 · 활성 상태 조회
종료 End Action

역할: 해당 행동을 정상 완료로 종료하고 액션 소유 자원을 회수합니다.

핀연결/결과
Target핸들을 발급한 Action Component
Handle이번 실행에서 받은 Action Handle
Return Value성공 여부. 무효·이미 종료·다른 관리자의 핸들은 False

액션을 활성 목록에서 제거하고 소유 자원을 정리한 뒤 On Action Ended를 알립니다. 실제 동작의 정상 완료 또는 콘텐츠가 완료로 처리하는 실패 출구에 사용합니다. 액션 종료는 DA 비용·쿨다운의 환불을 뜻하지 않습니다.

취소 Cancel Action

입력: Target=Action Component, Handle=이번 실행 핸들, Reason=취소 이유. 출력: 성공 여부.

특정 액션을 직접 취소하고 자원을 회수한 뒤 On Action Cancelled를 알립니다. 이 노드는 Cancel Rules를 검사하지 않습니다. 이유를 지정해도 직접 취소는 직접 취소이며, 규칙에 따라 선택적으로 취소하려면 Cancel Actions by Reason을 사용합니다.

성공적으로 취소한 핸들에 End Action을 다시 호출하지 않습니다. 이미 취소된 뒤 도착하는 콜백에서는 자신의 상태·연출만 정리하세요.

조회 Is Action Active / Get Active Action Count

Is Action Active: Target=Action Component, Handle=확인할 핸들 → 해당 관리자의 활성 액션인지 Bool 반환. 핸들 구조체가 형식상 유효한 것과 실제 액션이 아직 진행 중인 것은 다릅니다.

Get Active Action Count: 해당 관리자의 활성 액션 수를 반환합니다. 특정 아이템만의 수가 아니며, 종료 누락 등 진단에 사용합니다. 늦게 도착한 외부 타이머·연출 콜백은 Is Action Active로 유효 실행을 확인할 수 있습니다.

“구르기를 하면 스킬 취소”와 “스킬 중 구르기 금지”는 다른 정책입니다. 취소 규칙을 켜는 것은 해당 사유의 취소 요청이 도착했을 때 반응한다는 뜻이지, 요청이나 상태이상을 자체 생성한다는 뜻이 아닙니다.

설정 Set Action Cancel Rules

Target=Action Component, Handle=활성 핸들, Rules=ARActionCancelRules → 성공 Bool. 현재 행동의 경직·기절·구르기·기본 이동 입력 취소 설정을 교체합니다. 구조체 전체를 전달하므로 다른 필드도 원하는 값인지 확인하세요. 이미 종료된 행동을 복구하거나 과거 취소를 되돌리지는 않습니다.

설정 Set Action Roll Blocked / Set Action Basic Movement Blocked

Target=Action Component, Handle=활성 핸들, Blocked=차단 여부 → 성공 Bool. 각각 구르기 시작 차단과 관리형 기본 이동 잠금을 변경합니다. 기본 이동 차단은 All Movement 잠금과 다르며 모든 외부 이동을 중단시키는 기능은 아닙니다.

일괄 취소 Cancel Actions by Reason / Cancel Actions by Item Instance

Cancel Actions by Reason: Reason에 대해 각 액션의 취소 규칙을 검사하여 취소하고 취소 수를 반환합니다. 현재 Root 사유는 구르기 액션을 대상으로 하며, 그 밖의 관리 사유는 소유 행동 정리에 사용됩니다.

Cancel Actions by Item Instance: Get Instance Id로 얻은 Item Instance Id가 Owning Item Instance Id와 일치하는 행동을 취소합니다. Reason 기본값은 ItemRemoved, 반환값은 취소 수입니다. Source Id나 DA의 Item Id를 넣는 자리가 아닙니다. 정상 Loadout 제거는 이미 해당 인스턴스의 액션을 취소합니다.

광범위 취소 Cancel All Actions / Cancel Roll Actions

Target=Action Component, Reason을 받아 각각 관리자 안의 모든 행동 / Is Roll Action인 행동만 취소하고 개수를 반환합니다. Cancel All Actions는 이 아이템 외의 행동에도 영향을 주므로 개별 아이템의 정리에 무조건 사용하지 않습니다.

현재 일반 경직은 최종 경직 피해가 경직 저항력을 초과하고 슈퍼아머·면역 등에 막히지 않아야 발생합니다. 강인함은 허용된 상태이상의 시간 조절 수치이며 확정 CC 면역과 다릅니다. 아이템 제거·사망의 정리 취소는 경직/기절 체크와 별개로 수행됩니다.

05 액션에 연결된 대기 · 종료 알림
비동기 대기 Action Delay

역할: 활성 액션의 수명에 묶인 대기입니다. 시간이 끝나면 Completed, 해당 액션이 정상 종료·취소되거나 시작 조건이 무효이면 Cancelled를 실행합니다.

핀연결 기준 / 의미
Action Component 입력핸들을 발급한 소유자의 관리자
Action Handle 입력이번 실행의 핸들. 빈 핸들·다른 실행의 값 사용 금지
Duration 입력초 단위 대기 시간. 현재 구현은 0 이하를 즉시 완료로 처리
Completed 실행 출력대기가 정상 완료된 후 실행할 실제 효과. 필요한 처리를 마친 뒤 End Action
Cancelled 실행 출력취소·외부 종료·무효 조건의 정리 경로. 완료 효과는 실행하지 않음
상단 Then 실행 출력노드 시작 후 이어지는 실행선. 대기 완료 핀이 아님

Action Delay는 대기만 관리하며 Completed에서 액션을 자동 종료하지 않습니다. 정상 완료 후 End Action은 콘텐츠가 호출합니다. 반대로 시스템이 이미 취소한 액션의 Cancelled에서는 End Action을 중복 호출하지 않습니다.

시작 시 관리자가 없거나 해당 핸들이 활성 상태가 아니면 즉시 Cancelled입니다. 월드 참조가 무효여도 취소 경로로 갑니다. 취소 출력의 원인을 구분해야 한다면 관리자·핸들·Is Action Active를 확인하고 디버그 로그를 남깁니다.

일반 Delay·Set Timer는 Action Handle을 모릅니다. 액션이 중단되어도 자동으로 완료 동작이 차단되지 않으므로, 별도 종료 구독·타이머 해제·활성 확인이 필요합니다. Action Delay가 자신의 대기를 정리해도 다른 타이머·연출은 자동으로 정리하지 않습니다.

입력 유지·해제에 반응하는 콘텐츠는 입력 해제 전달, 경과 시간, 상태 전환을 별도로 설계합니다. Execute Item Skill의 현재 입력은 Skill Id와 Action Handle이며, 키 해제 이벤트가 자동 추가되는 것은 아닙니다.

아이템 이벤트 On Item Skill Cancelled

아이템 런타임 BP의 이벤트 그래프에서 Event On Item Skill Cancelled를 추가합니다. 별도 Bind 없이 시스템이 취소된 스킬을 실행한 아이템 인스턴스에만 전달합니다.

취소 후 직접 정리할 것: 경직·기절 등으로 실제 액션이 취소되면 시스템이 액션 생명주기와 액션 귀속 자원을 처리합니다. 하지만 Set Timer by Event로 만든 별도 타이머·독립 Actor·공격 Bool·연출까지 자동 회수하지는 않습니다. On Item Skill Cancelled에서 해당 실행의 핸들을 확인한 뒤, 저장한 Timer Handle을 Clear and Invalidate Timer by Handle에 연결하고 자체 상태를 정리하세요. 모든 경직이 무조건 취소를 일으키지는 않습니다. Action Delay 내부 대기는 자동 정리되며, 정상 완료의 자체 정리는 별도 완료 경로에서 처리합니다.

출력 핀의미
Skill Id · NameExecute Item Skill에 전달됐던 해당 아이템 내부 스킬 이름. Switch on Name으로 스킬별 정리 분기
Action Handle취소된 정확한 실행의 핸들. 같은 이름의 재실행과 다른 지연 콜백을 구분할 때 사용
ReasonStagger·Stun·ItemRemoved·Death·Manual 등 실제 액션 취소 사유
Event On Item Skill Cancelled → Switch on Name(Skill Id) → 해당 스킬의 Timer Handle Clear → 자체 상태·연출 정리

알림은 해당 액션의 자동 정리 이후에 호출됩니다. 이미 종료된 액션에 End Action/Cancel Action을 다시 호출하지 않습니다. 일반 타이머·독립 Actor·연출을 대신 전부 정리해 주는 이벤트는 아닙니다.

실제로 Execute Item Skill을 시작한 실행만 알립니다. 사전 조건/비용/쿨다운 거절, 실행 전 거래 롤백, 정상 End Action에는 오지 않습니다. 다른 아이템의 같은 Skill Id도 이 아이템으로 전달되지 않습니다. Loadout을 통하지 않고 직접 시작한 일반 액션에는 이 스킬 이벤트가 없으므로 기존 Action Component 알림을 사용합니다.

아이템 제거 경로는 실행 중인 자기 스킬 취소 알림 → On Item Unregistered 순서입니다. 비용·쿨다운 자동 환불은 없으며, 정상 완료의 자체 정리는 콘텐츠의 완료 경로에서 처리합니다. Action Delay.Cancelled와 이 이벤트에 같은 정리를 연결했다면 중복 실행에도 안전하게 구성하거나 책임을 한 곳으로 모읍니다.

추가 참고직접 시작한 액션·정상 종료 알림이 필요한 경우

아이템 스킬 취소는 위 On Item Skill Cancelled가 가장 간편합니다. 직접 액션/정상 종료의 외부 알림은 별도 책임으로 확인합니다.

06 효과의 수명 · 적용 · 스택 소비·제거

효과의 출처 이름과 자동 정리 소유권은 별개입니다. Source Id가 같다고 액션이나 아이템에 자동 귀속되지 않습니다. 어떤 적용 노드가 효과 핸들을 정리 목록에 등록했는지가 중요합니다.

정리 소유권연결 대상수명선택 기준
액션 소유Apply Action 계열 / Action Component + Action Handle자체 시간 만료 또는 액션 종료·취소 중 먼저 온 시점현재 행동이 끝나면 함께 없어져야 하는 효과
아이템 소유Apply Item 계열 / 런타임 Self자체 시간 만료 또는 아이템 해제액션 종료 뒤에도 유지하되 아이템 해제 시 회수할 효과
대상 소유 일반 효과일반 스탯·자원·상태 노드 / 대상 Actor 또는 해당 컴포넌트각 효과의 시간·명시적 제거·대상 수명액션·아이템 수명과 독립적으로 유지할 효과

Duration이 음수인 시간 제한 없는 효과도 정리 소유권의 종료를 무시하지 않습니다. 디스크 저장을 뜻하지도 않습니다. Duration이 0일 때의 처리는 노드별 정의를 확인하세요.

액션 효과 Apply Action Stat Modifier

Target=Action Component, Handle=활성 핸들, Spec=ARStatModifierSpec. Success와 ARStatModifierHandle을 반환합니다. 성공한 적용 건을 액션 정리 목록에 넣습니다.

Spec의 Stat Type·Operation·Value·Duration·Source·HUD 항목은 런타임 가이드의 Spec 필드를 참고하세요. Action Handle은 행동 식별값, 반환 Modifier Handle은 효과 적용 1건의 식별값으로 서로 대체할 수 없습니다.

액션 효과 Apply Action Super Armor / Apply Action CC Immunity

Target=Action Component, Handle=활성 핸들, Spec=각 효과 구조체. Success와 각 타입의 효과 핸들을 반환합니다. 성공한 효과는 해당 액션의 종료·취소 때 회수됩니다.

슈퍼아머와 CC 면역은 서로 다른 시스템의 효과입니다. 한쪽을 적용했다고 다른 쪽까지 보장되지 않습니다. 행동 종료 뒤 유지할 효과를 액션 소유 노드로 적용하면 설정한 지속시간 전에 회수될 수 있습니다.

아이템 효과 Apply Item Stat Modifier / Apply Item Super Armor / Apply Item CC Immunity

Target=런타임 Self, Spec=각 효과 설정. 플레이어 소유자와 적용 대상은 아이템 런타임이 처리하며 성공한 효과는 아이템 해제 정리 목록에 들어갑니다. 이 목록은 액션 종료 정리 목록과 다릅니다.

Apply Item Stat Modifier는 지정한 Source Id가 있으면 보존하고, 없으면 인스턴스 ID 기반 출처를 사용합니다. Category는 아이템 유형에 따라 Weapon/Relic으로 설정됩니다. Item Super Armor·CC Immunity도 아이템 인스턴스 기반 출처를 사용하므로, 수동 회수는 각 Remove Own Item 노드와 반환 핸들을 사용하면 정확합니다. 세부 필드는 아이템 런타임 가이드에서 확인하세요.

일반 효과 Apply Stat Modifier / Apply Shield

Actor 대상 일반 노드는 Target에 효과를 보유할 실제 Actor를 연결합니다. 소유 플레이어에게 적용할 때는 Get Item Owner 결과입니다. 같은 이름의 컴포넌트 버전은 해당 컴포넌트 참조를 요구하므로 Target 타입을 확인하세요.

아이템 런타임에서 호출했다는 이유만으로 액션·아이템 정리 목록에 등록되지 않습니다. 해제 후 보존 또는 제거 여부를 설계하고, 필요한 효과 핸들·출처를 보관합니다. 일반 적용 노드의 상세 필드는 런타임·스탯 가이드로 분리합니다.

효과 제거 Remove Stat Modifier / Remove Stat Modifiers by Source / Remove Own Item Modifier

Remove Stat Modifier: 대상 Actor + 적용 시 발급된 Modifier Handle로 정확한 효과를 제거합니다. 스탯 컴포넌트 버전은 컴포넌트를 Target으로 받습니다.

Remove Stat Modifiers by Source: 대상 Actor + Category + Source Id가 일치하는 효과를 제거합니다. Category=All은 분류 전체, Source Id=None은 ID 전체를 뜻하는 와일드카드입니다. 공유 출처 키는 다른 아이템의 효과도 포함할 수 있습니다.

Remove Own Item Modifier: 런타임 Self + Modifier Handle. 이 아이템의 소유 목록에 속한 효과만 조기 제거합니다. 다른 액션/아이템의 핸들을 넣는 용도가 아닙니다.

07 조준 · 위치 · 생성 · 판정 · 이동 노드

이 항목은 아이템 스킬에서 필요한 값과 Actor 연결 기준입니다. 액션 핸들은 행동의 수명, Actor 참조는 대상, Vector는 위치·방향을 나타냅니다. 서로 역할이 다릅니다.

조준 · 프로젝트 Get Aim Direction

Target=Get Item Owner 결과. ARBaseCharacter가 보관하는 조준 방향 Vector를 반환하며, 현재 구현은 Z=0인 XY 정규화 방향입니다. 월드 좌표나 Actor Forward Vector와 다릅니다.

조회 자체는 조준을 갱신하지 않습니다. 소유자의 조준 갱신 경로가 저장한 현재 값을 읽습니다. 생성 순간의 값을 Actor에 전달하면 이후 조준 변경과 분리되고, 지속 추적이 필요하면 콘텐츠가 별도로 갱신해야 합니다. 수직 조준은 현재 이 값만으로 제공되지 않습니다.

위치 · 엔진 기본 Get Actor Location

Target=위치를 읽을 Actor. 소유 플레이어 위치는 Get Item Owner를 연결합니다. 반환값은 루트 컴포넌트의 X·Y·Z 월드 위치이며, 방향·상대 위치가 아닙니다. 내부 함수명은 K2_GetActorLocation입니다.

런타임 Self는 UObject이므로 Actor Target을 대신할 수 없습니다. 루트와 실제 효과 발생 지점은 다를 수 있으므로, 정확한 지점이 필요하면 소유자의 소켓 또는 해당 컴포넌트의 월드 위치를 읽습니다.

계산 · 엔진 기본 Multiply (Vector × Float) / Add (Vector + Vector) / Make Transform

방향 × 거리는 이동량 Vector, 위치 + 이동량은 새로운 월드 위치입니다. Make Transform은 Location·Rotation·Scale을 생성 위치 정보로 묶습니다.

생성 위치 = 기준 월드 위치 + 정규화된 방향 × 위치 오프셋 거리
Make Transform.Location = 생성 위치
Make Transform.Rotation = 콘텐츠에 필요한 회전
Make Transform.Scale = 콘텐츠에 필요한 스케일

언리얼 기본 월드 거리 단위는 cm입니다. 위치 오프셋·최대 이동 거리·이동 속도는 서로 다른 값입니다. 정규화된 방향을 Location에 바로 넣으면 기준 Actor의 위치를 반영하지 못합니다. 흰 실행 핀이 없는 조회·계산 노드는 실제 사용 시 평가되므로 과거 값을 유지하려면 그 시점에 변수에 저장합니다.

생성 · 엔진 기본 Spawn Actor from Class / Is Valid / Destroy Actor

Class=생성할 Actor BP, Spawn Transform=위치·회전·스케일. Return Value는 생성된 Actor 참조입니다. 충돌 처리 설정 등의 이유로 생성이 실패할 수 있으므로 Is Valid로 성공을 확인하고 실패 경로도 종료·취소 책임을 처리합니다.

Owner는 엔진 소유 관계를 설정합니다. 이것만으로 피해 출처·이동 방향·사거리·액션 수명이 자동 연결되지 않습니다. 생성 시 노출(Expose on Spawn) 변수가 있으면 그 Actor가 요구하는 값을 연결합니다. 그런 핀은 해당 BP의 변수이지 모든 Spawn 노드의 공통 핀이 아닙니다.

독립 Actor는 자체 충돌·거리·수명 종료 시 Destroy Actor 등을 처리해야 합니다. Destroy Actor는 아이템 런타임 UObject나 Action Handle의 종료를 대신하지 않습니다. 액션 종료 이후에도 유지할 Actor는 액션 자동 삭제 목록에 등록하지 않습니다.

스탯 · 프로젝트 Get Final Stat

ARStatsBlueprintLibrary 버전은 Target=스탯 보유 Actor, Stat Type=조회할 종류 → 최종 값 Float. Stats Component 버전은 해당 컴포넌트를 Target으로 받습니다.

Range 등 콘텐츠 해석이 필요한 스탯은 값 조회만으로 Actor의 거리·속도가 자동 설정되지 않습니다. 단위·환산 계수·0 처리·실행 시점의 값 고정 또는 재조회 정책을 콘텐츠에서 정합니다. 실제 계산·사용처는 객체별 스탯 가이드를 참고하세요.

액션 귀속 Register Action Hitbox / Initialize Hitbox

Register Action Hitbox: Target=Action Component, Handle=활성 핸들, Hitbox Actor=등록할 Actor → 성공 Bool. 등록된 Actor는 액션 종료·취소 때 Destroy됩니다.

Initialize Hitbox: ARActionHitboxActor 자식의 초기화 노드. Action Handle + Combat Source + Hit Policy + Lifetime을 받으며, Combat Source의 Action Component를 확인해 등록을 내부 수행합니다. 이 초기화를 썼다면 보통 다시 Register할 필요가 없습니다. 활성 행동·유효 출처가 필요하고, 재초기화는 거절됩니다. Lifetime이 양수이면 자체 수명도 지정합니다.

아이템 스킬의 Combat Source는 소유 플레이어이며, 노드 Target은 생성한 히트박스 Actor입니다. 기본 히트박스의 콜리전 구성과 활성화·대상 탐지·실제 피해는 자식 콘텐츠가 구현해야 합니다.

대상 정책 Try Accept Target / On Hitbox Target Accepted / Reset Accepted Targets

Target=초기화된 히트박스, Candidate=접촉한 대상 Actor. Try Accept Target은 대상 정책에 따라 수락 여부를 반환하고, 수락 시 On Hitbox Target Accepted로 알립니다. Once Per Target은 해당 히트박스에서 대상당 한 번, Every Accepted Overlap은 중복 기록으로 재수락을 막지 않습니다.

Reset Accepted Targets는 기록을 비워 같은 대상의 재수락을 가능하게 합니다. 이것은 자동 틱 간격이 아닙니다. 수락 자체가 팀 검사·피해·경직을 대신하지 않으므로 실제 전투 요청은 콘텐츠에서 연결합니다.

액션 이동 Request Action Move / Request Action Velocity

Target=소유자의 Movement Control Component, Action Handle=현재 활성 핸들. Request Action Move는 방향과 Scale, Request Action Velocity는 방향과 Speed를 받습니다.

같은 소유자의 활성 핸들과 이동 허용 상태가 필요합니다. 기본 이동 잠금과 All Movement 잠금은 다릅니다. 액션이 종료됐다는 이유만으로 콘텐츠의 외부 이동·애니메이션·연출·이미 부여한 모든 속도가 자동 초기화된다고 가정하지 않습니다.

08 등록·해제 이벤트와 정리 책임
아이템 이벤트 On Item Registered / On Item Unregistered

On Item Registered: DA 기본 스탯 보정 적용 후 호출됩니다. 소유자·컴포넌트 캐시, 자체 상태 초기화, 필요한 이벤트 구독을 처리합니다. 같은 기본 효과를 다시 적용하면 중복됩니다.

On Item Unregistered: 해제 사유를 받습니다. 정상 Loadout 경로는 이 이벤트 전에 해당 인스턴스 액션을 취소하고, 이벤트 후 아이템 소유 효과·UI 상태를 정리합니다. 런타임은 자체 타이머·구독·외부 작업·참조를 정리합니다.

아이템 등록은 Actor BeginPlay가 아닙니다. 여러 보유본은 각기 다른 인스턴스이므로 공유 Source Id·외부 이벤트 구독의 범위를 확인하세요.

타이머 · 엔진 기본 Clear and Invalidate Timer by Handle / Pause·Unpause Timer by Handle

Clear and Invalidate는 저장한 Timer Handle의 타이머를 종료하고 핸들을 무효화합니다. 아이템 해제나 더 이상 필요 없는 타이머의 최종 정리에 사용합니다.

Pause는 타이머를 보존하며 일시 정지하고, Unpause는 존재하는 정지 타이머를 재개합니다. 이미 Clear된 타이머를 복구하지 않습니다. Timer Handle은 Action Handle이나 Stat Modifier Handle과 다른 타입입니다.

자체 타이머를 썼다면 종료·취소·아이템 해제 시점의 책임을 정합니다. 런타임 해제는 임의의 BP 타이머·외부 Actor를 모두 자동 삭제하는 기능이 아닙니다.

10 구현·검증 체크리스트
  • DA의 Runtime Behavior Class와 Skill Id가 실제 런타임 BP와 일치한다.
  • 입력 키·장착 슬롯 결정과 아이템 내부 스킬 구현을 분리했다.
  • 아이템 고유 사전 조건은 Can Execute Item Skill 오버라이드에서 읽기 전용으로 반환한다.
  • 조건을 적용하지 않는 스킬의 반환 정책도 정했다. 특정 조건을 불필요하게 모든 스킬에 강제하지 않는다.
  • DA 비용·쿨다운·액션 시작 처리를 실행 이벤트에서 중복하지 않는다.
  • Action Handle의 값 선을 실제 저장 변수에 연결하고, 동시 실행이 다른 핸들을 덮어쓰지 않는다.
  • Action Component와 Action Handle이 같은 소유자의 한 실행을 가리킨다.
  • 모든 정상 완료·콘텐츠 실패 출구에 종료·취소 책임이 있다.
  • 이미 종료된 행동의 알림에서 중복 종료하지 않는다.
  • 효과 지속시간, 액션 소유권, 아이템 소유권, 대상 소유권을 구분했다.
  • Actor 생성 실패·조건 변화·자원 부족·대기 취소·아이템 해제·사망·소유자 교체를 검증했다.
  • 외형·연출·조작감은 실제 플레이에서 확인한다. 노드 성공값만으로 모든 콘텐츠 동작을 보장하지 않는다.
