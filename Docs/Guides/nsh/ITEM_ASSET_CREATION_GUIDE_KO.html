아이템 에셋 제작 가이드

무기, 액티브 유물, 패시브 유물, 소모품을 만드는 공통 데이터 에셋과 각 항목의 의미를 현재 프로젝트 코드 기준으로 설명합니다. 정보를 담는 데이터 에셋과 실제 동작을 만드는 런타임 블루프린트를 구분해서 읽으세요.

시간 그룹 · 기능과 설정Runtime에서 시간 작업을 만들 때 제작 순서유형별 사용표IdentityDisplayStatsSkillsRuntimeUI보장 효과Evolution검색·획득검증

궁금한 항목을 누르면 설명이 펼쳐집니다. 아래 버튼으로 한꺼번에 열거나 닫을 수도 있습니다.

00 어디서 무엇을 만들까?

데이터 에셋

네 종류 모두 Data Asset → ARItemDefinition을 만듭니다. 이름, 유형, ID, 아이콘, 장착 시 기본 스탯, 스킬 등록 정보 등을 보관합니다.

런타임 블루프린트

무기·유물은 ARLoadoutItemInstance를 부모로, 소모품은 ARConsumableInstance를 부모로 만듭니다. 타이머, 조건부 효과, 공격, 실제 사용 효과를 구현합니다.

픽업·획득 경로

맵에 떨어뜨릴 때는 ARItemPickup 계열 객체에 정의 에셋을 지정합니다. 상점·보상 등은 Try Acquire Item으로 같은 정의를 획득시킬 수 있습니다.

  1. 1Content/Game/Objects/Items/Weapons, Relics/Active, Relics/Passive, Consumables 중 해당 폴더 아래에 아이템 전용 폴더를 만듭니다. Data에는 정의 에셋, Runtime에는 동작 BP를 둡니다.
  2. 2콘텐츠 브라우저에서 우클릭 → 기타(Miscellaneous) → 데이터 에셋(Data Asset) → 부모 클래스로 ARItemDefinition 선택. 표시 메뉴 이름은 언리얼 버전에 따라 약간 다를 수 있습니다.
  3. 3아래 Identity와 Display를 채웁니다. 필요하면 Stats·Skills·UI·Evolution을 설정합니다.
  4. 4유형에 맞는 런타임 BP를 만들거나 데이터만 있는 장비·유물은 기본 ARLoadoutItemInstance 클래스를 선택하고, Runtime Behavior Class에 연결합니다.
  5. 5에셋을 저장하고 획득 테스트를 합니다. 저장되지 않은 새 에셋은 카탈로그 검색에서 누락될 수 있습니다.
에셋 파일 이름은 DA_..., 런타임 BP는 BP_...처럼 구분하면 편합니다. 내부 Primary Asset ID는 ARItem:에셋파일명이므로 폴더가 달라도 데이터 에셋 파일 이름은 전체 프로젝트에서 중복되지 않게 짓는 편이 안전합니다. 게임 규칙의 검색 키는 별도로 (Item Type Tag, Item Id)입니다.

02 Identity — 무엇인지 식별하기
필드무엇을 적나?실제 역할 / 주의점
Item Type Tag프로젝트에 등록된 네 Gameplay Tag 중 하나를 선택합니다: Item.Type.Weapon, Item.Type.ActiveRelic, Item.Type.PassiveRelic, Item.Type.Consumable.획득할 때 어느 시스템으로 보낼지 정하는 종류입니다. 개별 아이템을 나타내는 값이 아닙니다. 종류가 다르면 허용되는 런타임 부모 클래스도 달라집니다.
Item Id사람이 입력하는 양의 정수. 0은 미지정이므로 사용하지 않습니다.(Item Type Tag, Item Id) 조합이 고유 검색 키입니다. 같은 유형에서 ID가 겹치면 카탈로그 조회가 실패합니다. 다른 유형끼리는 같은 정수를 쓸 수 있습니다.
Additional Tags선택적 문자열 배열. 예: Fire, Sword, Starter.계열 검색·보유 수 집계에 씁니다. 여러 아이템이 같은 문자열을 가져도 됩니다. 비교 시 대소문자와 앞뒤 공백은 무시합니다. Gameplay Tag가 아니므로 프로젝트 설정에 등록할 필요가 없습니다.
예: 패시브 유물의 Item Type Tag = Item.Type.PassiveRelic, Item Id = 101, Additional Tags = [Stamina, Growth]. Find Item By Key(PassiveRelic, 101)는 하나를 찾고, Find Items By Additional Tag("Growth")는 여러 개를 찾을 수 있습니다.

여기는 표시 데이터입니다. 실제 화면에 어디에 그릴지는 해당 UI 위젯이 결정합니다. 현재 픽업 객체의 기본 상호작용 문구는 별도 속성인 Interaction Prompt이고, Display Name을 입력했다고 자동으로 바뀌지는 않습니다.
04 Stats — 장착 즉시 자동 적용할 스탯

Default Stat Modifiers는 배열입니다. 무기·액티브·패시브 유물을 획득하면 각 항목이 자동 적용되고, 해당 아이템이 제거되면 자동 회수됩니다. 소모품은 이 배열을 자동 적용하지 않으므로 비워 두세요. 시간 경과·피격 조건·사용 시 효과는 런타임 BP에서 구현합니다.

배열 원소 하나(FARStatModifierSpec)의 모든 필드

필드뜻설정 방법 / 주의점
Stat Type변경할 스탯 종류예: Max Stamina, Max Health, Attack Power. 실제 최종값은 플레이어의 기본 스탯과 다른 효과까지 합쳐 계산됩니다.
Operation값을 계산하는 방식Flat: 고정값 더하기. AdditivePercent: 합연산 % 더하기. Multiplicative: 마지막에 곱할 배율. IndependentDamageReduction: 일부 피해 감소율 스탯에서만 쓰는 독립 피해 감소. Permanent Flat은 일반 Apply Stat Modifier 전용이며 이 DA 기본 효과/아이템·액션 귀속에서는 사용 불가입니다.
Value변경량Flat 10은 +10, AdditivePercent 20은 +20%, Multiplicative 1.2는 ×1.2입니다. 독립 피해 감소는 50을 적으면 50% 감소이며 0.5가 아닙니다.
Duration초 단위 지속시간런타임 적용에서는 -1이 무기한, 양수는 해당 초 동안입니다. 0은 거부됩니다. Default Stat Modifiers는 등록 시 무조건 -1로 바꿔 적용되므로 이곳에 시간을 적어도 장착 중 영구입니다.
Source → Category출처 분류런타임 아이템 적용 시 무기는 Weapon, 유물은 Relic으로 자동 지정됩니다. 여기서 Other로 보여도 아이템 등록 시 실제 분류는 바뀝니다.
Source → Source Id효과 묶음·검색에 쓸 이름서로 다른 효과에는 서로 다른 이름을 지정합니다. 직접 입력한 값은 아이템 적용 시 보존됩니다. 같은 ID는 조회·HUD 묶음 기준이 됩니다.
Source → Display Name출처를 사람이 읽을 이름비우면 아이템의 Display Name으로 보완됩니다. 개별 효과 이름이 필요하면 따로 적습니다. HUD의 HUD Name이 설정됐다면 HUD에서는 그것을 우선 사용합니다.
Stack Only스탯 변경 없이 중첩 한 개만 기록숫자 표시·중첩 카운터 전용일 때 켭니다. 켜면 Stat Type / Operation / Value가 실제 스탯을 변경하지 않습니다. 무적·회피 보장과 함께 쓸 수 없습니다.
Stack Group Handle여러 수정치를 중첩 한 개로 묶는 핸들런타임 BP에서 첫 Apply Item Stat Modifier의 반환 핸들을 다음 효과에 넣을 때 사용합니다. 독립 중첩을 늘릴 때는 비웁니다. 기본 수정치에서는 직접 입력값이 무시되고 같은 Source Id끼리 등록 시 자동으로 한 묶음이 됩니다.
Affected By Tenacity강인함으로 지속시간을 줄일지양수의 유한 Duration에만 적용됩니다. 데이터 에셋의 기본 수정치는 장착 중 무기한이므로 효과가 없습니다.
HUD Display효과 아이콘 표시 분류Hidden은 숨김, Buff는 버프, Debuff는 디버프입니다. 이 값은 스탯 증감 부호를 자동 판별한 결과가 아니라 제작자가 정합니다.
HUD NameHUD 효과 이름Buff/Debuff일 때 표시할 텍스트. 비우면 Source Display Name을 사용합니다.
HUD IconHUD 효과 아이콘Buff/Debuff일 때 사용할 Texture2D 참조. 아이템 자체의 Display → Icon과 별도입니다.
Guarantee Invulnerability보장형 무적 부여Stat Type = OverallDamageReduction일 때만 허용됩니다. 일반 100% 피해 감소와 구별해야 할 무적 효과에 사용합니다.
Guarantee Evasion보장형 회피 부여Stat Type = Evasion일 때만 허용됩니다.
일반 스탯 최종값 = (기본값 + Flat 합계) × (1 + AdditivePercent 합계 ÷ 100) × Multiplicative 값들의 곱

IndependentDamageReduction은 OverallDamageReduction, PhysicalDamageReduction, FireDamageReduction, MagicDamageReduction에만 사용 가능합니다. Value = 50인 독립 감소 두 개라면 남는 피해는 0.5 × 0.5 = 0.25, 즉 합계 75% 감소입니다.

스탯이 여러 개여도 ‘중첩 1개’로 세고 싶다면 기본 배열에서는 같은 Source Id를, 런타임에서는 Stack Group Handle을 사용합니다. 별개의 효과를 HUD에서 따로 표시하려면 서로 다른 Source Id를 사용하세요.
05 Skills — 입력 스킬을 등록하기

Skill Definitions는 배열이며, 무기와 액티브 유물에서 주로 사용합니다. 패시브 유물도 입력으로 발동하는 스킬이 실제로 있을 때만 사용할 수 있습니다. 소모품 사용 효과는 여기에 넣지 않습니다. 이 배열은 등록·비용·쿨다운·UI 정보이며 공격 판정이나 연출을 자동 생성하지 않습니다.

필드뜻설정 방법 / 주의점
Skill Id아이템 내부 스킬 이름같은 아이템 안에서는 고유해야 하고 빈 값이면 등록이 거부됩니다. 런타임 Execute Item Skill(SkillId, ActionHandle)에서 어떤 동작인지 분기합니다.
Input Mode입력을 찾는 방식Direct Tag는 기존 방식으로 무기·유물 모두 사용할 수 있습니다. Active Relic Slot은 액티브 유물 전용으로, 장착 슬롯 위치와 내부 스킬 번호로 입력을 찾습니다. 기존 에셋은 기본값인 Direct Tag를 유지합니다.
Input TagDirect Tag의 논리 입력Direct Tag에서만 보입니다. 등록된 Gameplay Tag를 고릅니다. 예: Input.Skill.Primary, Input.Skill.1, Input.Skill.2. 물리 키는 플레이어의 Input Action·IMC에서 연결합니다. Direct Tag일 때 비어 있으면 정의가 거부됩니다.
Slot Skill Index액티브 유물 내부의 스킬 번호Active Relic Slot에서만 보입니다. 1부터 시작합니다. 서로 다른 액티브 유물이 모두 1번 스킬을 갖더라도, 장착된 1번/2번 슬롯 입력이 각 유물을 따로 찾습니다. 무기·패시브에는 이 입력 방식을 사용할 수 없습니다.
Input Priority같은 입력 후보의 우선순위낮은 숫자부터 확인합니다. 같은 우선순위의 스킬은 그룹 단위로 비용·쿨다운·행동 가능 여부를 확인하여 의도적인 동시 발동을 지원합니다. Direct Tag에서는 같은 태그끼리, 슬롯 방식에서는 같은 유물·같은 내부 스킬 번호끼리 적용됩니다.
Resource Cost → Mana / Stamina한 번 발동할 때의 마나·스태미나 소모0 이상. 비용은 발동 과정에서 검사·차감됩니다. 복잡한 추가 조건은 런타임 Can Execute Item Skill에서 검사할 수 있습니다.
Base Cooldown기본 쿨다운 초0 이상. 캐릭터 쿨다운 감소율을 반영합니다.
Minimum Cooldown쿨다운 최저 초0 이상. 최종 쿨다운은 Max(Minimum Cooldown, Base Cooldown × (1 - 쿨다운감소율/100))입니다.
Action Request → Cancel Rules경직·기절·구르기·기본 이동 입력에 의해 취소될지Cancel On Stagger, Cancel On Stun, Cancel On Roll, Cancel On Basic Movement Input을 각각 결정합니다. 기본값은 앞 두 개만 참입니다.
Action Request → Block Roll While Active행동 중 구르기 금지차징이나 무거운 공격처럼 구르기로 중단되면 안 되는 동작에서 사용합니다.
Action Request → Block Basic Movement While Active행동 중 WASD 기본 이동 금지스킬 자체의 이동까지 모두 막는 뜻은 아닙니다. 기본 이동 입력만 제한합니다.
Action Request → Is Roll Action구르기 행동 여부일반 무기·유물 스킬이면 기본값 false를 유지합니다. 실제 구르기로 취급할 의도가 있을 때만 변경합니다.
Action Request → Skill Group Handle / Owning Item Instance Id실행 중 그룹·소유 아이템 연결값아이템 스킬 실행 과정에서 시스템이 채웁니다. 데이터 에셋에서는 기본값으로 둡니다.

액티브 유물 슬롯 키 연결 예시

두 액티브 유물의 스킬 정의에서 Input Mode = Active Relic Slot, Slot Skill Index = 1로 설정합니다. 테스트 플레이어 BP의 Active Relic Slot Input Bindings에 IA_Active1 → Active Relic Slot 1 / Skill Index 1, IA_Active2 → Active Relic Slot 2 / Skill Index 1을 넣고 IMC에서 두 IA를 각각 원하는 키에 연결합니다. 유물 에셋에는 Q/E 같은 물리 키를 넣지 않습니다. 두 번째 스킬이 있다면 해당 슬롯의 Skill Index 2용 IA·키를 추가합니다.

슬롯 방식은 장착 배열의 현재 위치를 따릅니다. 1번 유물을 버려 2번 유물이 앞으로 당겨지면 남은 유물은 1번 슬롯 키로 작동합니다. 무기와 의도적 동시 발동용 스킬은 기존 Direct Tag를 사용하세요. 같은 물리 키를 Direct Tag IA와 슬롯 IA 양쪽에 등록하면 충돌할 수 있으므로 IMC의 키 중복은 피해야 합니다.
06 Runtime — 실제 동작 클래스 연결하기

Runtime Behavior Class에는 데이터 에셋이 아니라 BP 클래스를 선택합니다. 플레이어 BP 안에 그래프가 복사되는 구조가 아닙니다. 획득하면 아이템별 런타임 인스턴스가 새로 만들어지고, 해제·교체·사용 시 해당 인스턴스가 정리됩니다.

유물 BP에서 사용할 이벤트와 노드의 모든 주요 핀은 유물 런타임 블루프린트 노드 가이드를 참고하세요.

유형허용되는 부모주요 이벤트·역할
무기 / 액티브 유물 / 패시브 유물ARLoadoutItemInstance 또는 그 자식 BPOn Item Registered: 장착 시 시작. On Item Unregistered: 타이머·이벤트 바인딩 정리. Execute Item Skill: 스킬 실행. Apply Item Stat Modifier: 시간·조건부 스탯 효과 적용.
소모품ARConsumableInstance 또는 그 자식 BPCan Use Consumable: 사용 가능 여부. Execute Consumable Use: 사용 즉시 효과 구현. 사용 뒤 슬롯에서 제거되며 현재 기본 쿨다운은 없습니다.

데이터만 제공하는 무기·유물은 기본 ARLoadoutItemInstance를 지정해도 되지만, 소모품의 실제 효과는 자식 BP에서 구현해야 합니다. 유형과 다른 부모를 선택하거나 클래스를 비우면 획득이 거부됩니다.

아이템 런타임의 Apply Item Stat Modifier로 준 수정치는 아이템 해제 시 핸들별로 자동 제거됩니다. 다만 BP에서 시작한 반복 타이머·직접 바인딩한 이벤트는 On Item Unregistered에서 직접 정리하세요. 소모품 BP에서는 아이템 장착용 기본 수정치가 자동 적용되지 않으므로 사용 효과를 별도로 호출해야 합니다.
07 UI — 아이템 고유 게이지와 버프 표시

08 런타임 보장 효과 — 슈퍼아머·CC 면역

이 두 효과는 데이터 에셋의 숫자 스탯이 아닙니다. 필요할 때 무기·유물 런타임 BP에서 Apply Item Super Armor 또는 Apply Item CC Immunity를 호출합니다. 각 입력 구조체에는 Duration과 Source가 있으며 -1은 별도 제거 전까지 유지됩니다. 아이템이 해제되면 해당 아이템이 부여한 보장 효과는 자동 회수됩니다.

  • 슈퍼아머: 경직을 막습니다. 그로기 피해나 상태이상을 함께 막지는 않습니다. 필요하면 반환 핸들로 Remove Own Item Super Armor를 호출해 일찍 끝낼 수 있습니다.
  • CC 면역: 새 기절·속박 등 CC로 지정된 상태이상 적용을 막습니다. 이미 걸린 상태를 해제하지는 않습니다. 필요하면 Remove Own Item CC Immunity를 호출합니다.
  • 스킬 행동에만 적용: 장착 아이템의 수명 전체가 아니라 시전 중에만 필요하면 Apply Action Super Armor / Apply Action CC Immunity를 사용합니다. 해당 행동의 종료·취소와 수명을 맞추는 방식입니다.
Guarantee Invulnerability / Guarantee Evasion은 Stats의 별도 보장 옵션이며 슈퍼아머·CC 면역과 다른 기능입니다. 해당 기능을 쓰는 아이템에서만 설정하세요.

11 저장 전·테스트 전 확인
  • Item Type Tag를 네 유형 중 하나로 선택했는가? 새 아이템마다 새 Gameplay Tag를 만들 필요는 없습니다.
  • Item Id > 0이며 같은 유형의 다른 에셋과 겹치지 않는가? 데이터 에셋 파일 이름도 중복되지 않는가?
  • Runtime Behavior Class가 비어 있지 않고 아이템 유형에 맞는 부모 클래스인가?
  • 무기·유물의 기본 스탯은 Default Stat Modifiers, 조건부 효과는 런타임 BP로 나눴는가? 소모품은 기본 수정치 배열에 의존하지 않는가?
  • 스킬을 등록했다면 Skill Id가 유효한가? Direct Tag는 유효한 Input Tag, 액티브 슬롯 방식은 1 이상의 Slot Skill Index가 있는가? Action Request는 취소·이동 제한 규칙이며 별도의 행동 태그는 필요하지 않습니다. 실제 효과를 Execute Item Skill에 구현했는가?
  • HUD에 표시할 스탯 효과라면 Source Id와 HUD 분류·이름·아이콘을 설정했는가? 독립적인 효과에 같은 Source Id를 무심코 재사용하지 않았는가?
  • BP 반복 타이머와 이벤트 바인딩은 해제 이벤트에서 정리하는가? 특히 버린 뒤 다시 줍는 테스트를 했는가?
  • 새 에셋을 저장한 뒤 Validate Item Catalog로 전체 유형·ID·런타임 클래스 오류를 확인했는가?
제작용 DA 설정 경고 확인

콘텐츠 브라우저에서 아이템 DA를 우클릭하여 에셋 작업(Asset Actions) → 에셋 검증(Validate Assets)을 실행하면 메시지 로그에 [AR 아이템] 경고와 해당 객체 링크를 표시합니다. 저장 시 검증은 에디터의 데이터 검증 설정에 따릅니다.

지원하지 않는 유형·0 이하 ID·런타임 클래스 누락/추상 클래스/유형에 맞지 않는 부모, 중복 또는 빈 Skill Id, 잘못된 입력·음수/비유한 비용·쿨타임, 아이템 기본 효과의 Permanent Flat을 안내합니다. 소모품 경로에서 무시되는 스킬·기본 효과 배열도 안내합니다.

이 검사는 경고만 남기며 값을 자동 수정하거나 저장·실행 규칙을 새로 차단하지 않습니다. 검증 결과가 Valid여도 경고 내용을 확인하세요. 다른 에셋과의 ID 중복은 기존 Validate Item Catalog를 사용합니다. 같은 Input Tag·우선순위 공유와 액티브 슬롯 스킬의 빈 Input Tag는 정상 설정일 수 있으므로 그 이유만으로 경고하지 않습니다.

현재 코드의 데이터 구조를 설명하는 문서입니다. UI 스킨·픽업 스프라이트·공격 판정은 별도 블루프린트/위젯 제작 영역입니다.

Runtime에서 시간 작업을 만들 때

DA의 쿨타임·기본 효과 Duration과 BP 예약은 서로 다릅니다. 보유 주기 효과는 런타임의 On Item Registered → Set Item Timer by Event, 스킬 선딜·반복 효과는 Execute Item Skill → Set Action Timer by Event로 연결하세요. DA에 시간을 적는 것만으로 BP 콜백이 생성되지는 않습니다.

시간 그룹 · 기능과 설정

World와 Player라는 시간 그룹이 있습니다. 선택형 기본값은 World이며 게임 Pause 시 두 그룹 모두 멈춥니다. 시간 기준은 아이템/액션의 자동 정리 수명과 별개입니다.
